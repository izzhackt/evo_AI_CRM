## 2. Карта разделов и возможностей (веб и iPhone — одни возможности, разная компоновка)

Навигация: веб — левый рейл + топбар (дизайн-контракт, «Карта экранов»); iPhone — таб-бар по `accessTier` (ios/EVOAdmissions/Views/TabShell.swift): approved «Главная · Университеты · Профессии · Английский · Профиль», assisted «Главная · Моё поступление · Университеты · Английский · Профиль».

| Договор и оплата (`/portal/payments`) | транши, суммы, статусы из существующей модели CRM; не эквайринг | клиент |

## 6. Передача исполнения Astra GPT-6

Инициировано владельцем 2026-09-20: «после этого давай сделаем продолжения через Astra gpt 6».

### Момент передачи

Schema/release-координация переходит от Fable к Astra после мержа этого пакета; до мержа она остаётся за Fable (как записано в KB-секции `docs/EVO_LAUNCH_PLAN.md`).

### Наследуемые рабочие соглашения

- Трёхзначная нумерация миграций, следующая свободная — 205, contiguity-gate релиза.
- Релизный контракт: readback ledger через Management API → пинг соседним сессиям → `gh variable set EVO_PRODUCTION_RELEASE_ARMED --body true` → dispatch evo-platform-ci.yml с proof_revision=точный main SHA → авто evo-fast-release → верификация на hermes-vps (docker inspect ревизии evo-crm-app-1, /opt/evo-crm/release-evidence/current-v3-accepted.json, /api/health) → disarm → receipt в начало релизного блока docs/EVO_LAUNCH_PLAN.md → независимое review receipt до мержа.
- PLAN_CHANGES строго append-only, запись решений ПЕРВЫМ коммитом до кода.
- Независимое адверсариальное review каждого продуктового PR на точном head до мержа + delta-конфирмы после ребейзов с `git patch-id --stable` доказательствами.
- Байт-замороженные smoke-якоря: data-testid student-portal-shell, nav «Разделы кабинета», заголовки «Моё поступление»/«Документы»/«Чеклист», empty-state «Список документов пока пуст», #staff-email/#staff-password — менять нельзя без правки production-smoke.
- Канонические node-флаги `--conditions=react-server --experimental-strip-types` для node-тестов и server-only скриптов.
- iOS: `xcodegen generate` после чекаута, схема «EVO admissions» (с пробелом), симулятор iPhone 17 Pro.
- Пины `tests/ci-node-test-suite.test.mjs` обновляются в ТОМ ЖЕ коммите, что и состав сьютов.
- Suite-прогоны и push — раздельные команды с индивидуальной проверкой exit-кодов.

- Ping-before-arm с Claude-сессиями через их канал.
- QA-аккаунт студента — владельческий файл `.env.student-portal-qa.json` (не в гите, пароль не печатать).
