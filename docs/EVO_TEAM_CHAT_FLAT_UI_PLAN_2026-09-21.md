## A15d: ограниченный контракт до кода

### Хранение и чтение

1. Сохранить `team_chat_preferences.read_sequence` без сброса/перезаписи. Это
   историческая граница: всё, что уже было прочитано старым способом, остаётся таким.
2. Добавить приватное множество seen для `(organization, channel, membership,
   message_id)` с уникальностью всей комбинации и составными внешними ключами
   на исходное сообщение того же канала/организации и членство организации.
   Не менять message rows и не создавать копии. Таблица закрыта прямому клиентскому
   чтению/записи, RLS включён; доступ только через проверенные RPC.
3. Непрочитанное — существующее неудалённое сообщение другого автора выше
   исторической границы, ID которого отсутствует в seen текущего сотрудника.
   `firstUnreadId` — минимальный sequence среди этого же множества. Число и ID
   вычисляются по одинаковому условию; root/reply учитываются одинаково.
4. Обновить только расчёт unread в `team_chat_channels`, сохранив форму v1 DTO,
   инертные прежние preference-поля и актуальные custom-staff права. Определение
   брать с учётом replacement из156, не копировать старую coarse-role проверку141.
   Preview/time в этот блок не входят.
5. Не продвигать общий cursor до максимального seen. Не вводить автоматическую
   очистку/свёртку seen в A15d: корректность пропусков важнее ранней оптимизации.
   Индекс под anti-join ограничен organization/channel/membership/message.

### Новое действие

Предлагаемый RPC: `platform.team_chat_mark_seen(organization UUID, channel TEXT,
message_ids UUID[])`, actor берётся только из обычной Auth authority. Имена
параметров/результата фиксируются вместе с миграцией после review.

- Один запрос содержит от1 до50 различных валидных ID одного разрешённого канала.
  NULL, неизвестный канал, пустой/слишком большой batch, NULL/повторяющийся ID,
  чужой канал/организация или отсутствующее сообщение отклоняются целиком.
- Все IDs валидируются до вставки. Чужая membership не передаётся клиентом.
  Проверка доступа отклоняет и FALSE, и NULL (`IS NOT TRUE`). Student/anon и
  недоступный канал запрещены; grants как у223: только authenticated execute,
  без service-role продукта и без открытого PUBLIC.
- Операция — идемпотентное объединение множества. Повтор того же batch, повтор
  части или два пересекающихся batch не создают второй seen row и не затрагивают
  пропущенные IDs. Здесь не нужен request receipt на каждый скролл: неизвестный
  ответ повторяет то же неизменяемое множество. Ответ подтверждает принятые IDs;
  клиент не считает запрос успешным до валидного server acknowledgement.
- Собственные/уже исторически прочитанные/удалённые IDs, прошедшие проверку
  принадлежности, допустимы как no-op; старые данные не меняются. Удаление между
  показом и запросом не превращает весь batch в ложную ошибку.
- RPC не посылает упоминания, не создаёт audit message events и не публикует
  текст/ID в Realtime. Чтение самого канала/поиска остаётся STABLE без seen writes.
  Версионность сообщений, read_sequence, receipts старых команд неизменны.
- Новые типы/decoder, server repository и server action проверяют границы
  batch/ack и отказывают staff preview. Действие пока не подключается к UI.
  `team_chat_command(operation=read)` остаётся прежней явной командой старого UI;
  новый интерфейс не будет использовать её для авто-просмотра.

Обычный SQL owner способен обходить RLS; поэтому наличие политики само по себе
не доказательство изоляции SECURITY DEFINER. Нужны явная actor/channel проверка,
пустой search_path и проверенные grants.
[PostgreSQL Row Security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html).

### Проверка A15d

Небольшие decoder/validator checks, scoped lint/typecheck и migration boundary
для выделенной миграции. Реальные локальные проверки выполняются только после
отдельного reviewed packet и эксклюзивного ROOT GO:

- До/после apply: все исходные rows, история, прежние read_sequence и receipts
  сохранены; допустимы только заявленные schema/function/index изменения.
- Положительно разрешить существующего наблюдателя, отличного от автора
  сохранённой истории, через обычный login и actor/access snapshot. Sales-автор
  всех текущих QA сообщений не доказывает уменьшение чужого unread.
  `salesOther` с известным invalid_credentials повторно не использовать.
  Без подходящего разрешённого наблюдателя отметить этот тест непроверенным;
  не создавать новую личность, роль или историю без отдельной authority.
- На реальных существующих IDs выбрать два непоследовательных сообщения выше
  legacy floor; после mark_seen уменьшить unread только на них, первый пропуск
  оставить `firstUnreadId`. Проверить subset/duplicate retry и конкурентное
  пересечение с точным ожидаемым seen-множеством.
- Проверить legacy floor на текущих данных без его искусственного сброса. Если
  подходящей положительной истории нет, отдельный заранее разрешённый read
  command обязателен для такой QA, иначе coverage остаётся ограниченным.
- Негативные Student/anon/неразрешённый канал/invalid batch дают ноль изменений;
  mixed batch не пишет частично. Чужой tenant проверять только при наличии
  действительной отдельно разрешённой организации, не объявлять passed по NULL.
- Повторные read/search/context не создают seen. Старый reader/command replay
  остаются совместимыми. Проверить планы relevant SQL на реальной локальной
  истории; не запускать весь продуктовый E2E или unrelated тяжёлые suites.

## Обязательства будущего включения UI

**Цитаты.** Не превращать старый parent в произвольный вложенный parent.
Прямой quote target хранится отдельно, old root-parent остаётся для v1 reader.
Старые ответы получают цитату из существующего parent без переписывания rows.
Новый read/DTO contract обязан отличать прямую цитату от root и не ломать
декодер223, который пока связывает quotes с parent. Точный additive v2 contract
проверяется в A15e. Изменение/удаление оригинала обновляет видимую цитату,
включая original вне загруженной страницы; удалённый текст не восстанавливается.

**Черновики.** Сканировать только собственный префикс
`evo-team-draft-v1:<org>:<membership>:<channel>:` текущей вкладки. Общий,
thread и edit drafts остаются разными, пока пользователь явно не выберет нужный.
Доступный список восстановления показывать только при наличии таких черновиков.
Не перезаписывать занятый редактор и не удалять исходник при одном чтении.
Frozen retryInput/requestId не переписывать под новую цитату; старую неизвестную
попытку отправлять/сверять прежним контрактом. Ошибка Storage означает явное
предупреждение о несохранённом черновике, а не обещание сохранности.

**Лента и контекст.** Один нормализованный store по ID/version, sequence хранится
как bigint-compatible строка. latest/before/after/context различают границы
загруженных диапазонов; отдельно пришедший fragment не делает пробел полной
историей. Старый URL открывает вокруг target; безопасное отсутствие/отказ не
показывает чужой root. Search state хранит query, results/pages и anchor+offset;
context state хранит return target. «Назад к результатам» восстанавливает всё это.
Правки/удаления обновляют store, но не считаются новыми сообщениями.

**Авто-просмотр.** Наблюдать только bodies обычной ленты, не результаты поиска,
не quote preview и не скрытый мобильный слой. Учитывать активный видимый документ,
текущий канал и перекрывающие рабочую область слои. Прыжок сам ничего не отмечает;
после него отдельные реально показанные сообщения могут попасть в batch.
До A15f зафиксировать bounded dwell/visibility criterion, в том числе для сообщения
выше viewport, и проверить scroll/смену вкладки/диалог без ложных seen.
IntersectionObserver даёт пересечение, а не доказательство прочтения;
Page Visibility нужен отдельно. Это инженерный способ выполнить требование,
не основание увеличивать read_sequence.
[Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API),
[Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API).

**Положение.** Сохранять visible message ID+offset при prepend, редактировании,
resize редактора и возврате из поиска. Если сотрудник читает историю, приход
сообщения не скроллит её. Переход вниз показывается при настоящем unread/new
tail либо при контекстном фрагменте вдали от конца; не при любом invalidate.
Grouping не пересекает автора/день/разрыв загруженных диапазонов.

**Ошибки и доступность.** История, отправка, удаление и seen имеют разные причины
и восстановление. Неуспех refresh после confirmed send не превращает отправку
в неуспешную. Hover actions доступны при keyboard focus, touch menu явно видимо,
focus возвращается к вызвавшему действию. Один редактор поддерживает Enter,
Shift+Enter, IME, autosize и существующие mentions/лимиты. При forbidden очищаются
history/search/quotes/participants и queued seen текущего канала; другой аккаунт
не видит старое приватное состояние. Никакого автоповтора в отозванные права.

### Данные, черновики и переходы

V2 хранит прямой quote ID отдельно от root-parent. Приходящие V1 changes не
содержат direct ID: у известной строки сохранить её ID цитаты, неизвестную
дочитать V2. Не угадывать прямую цитату по parent. Обновление оригинала должно
обновлять его видимые цитаты и выбранную цитату редактора, даже если оригинал
вне текущей страницы; применять только более свежую версию, deleted preview пуст.
Данные текущего оригинала из разрешённого changes ответа можно использовать
для такой проекции; неизвестную структуру ответа нельзя достраивать как V2.

Один store ID/version; int64 cursor/sequence остаются строками. Отдельно хранить
набор ID и границы активного непрерывного диапазона. Context-фрагмент не закрывает
незагруженный промежуток. Before/after продолжают именно текущую границу; переход
к latest не склеивает пропуск. Search хранит запрос/страницы/якорь/фокус; переход
к результату сохраняет их для возврата. Изменение/удаление не считается новым tail.

Сохранять первый видимый ID+смещение при prepend/обновлении/resize редактора.
Новый хвост при чтении истории не сдвигает экран; появляется переход вниз.
Удержание якоря делать коротким измерением после commit до paint, без большого
блокирующего цикла. Этот выбор следует из [React useLayoutEffect](https://react.dev/reference/react/useLayoutEffect);
это наше применение API, не обещание готовой устойчивости без браузерной проверки.

Сканировать только собственный org/member/channel prefix sessionStorage.
Восстановленные V1 drafts, включая ещё не отправленные, сохраняют V1 путь;
requestId/retryInput неизвестной попытки неизменны. Не отправлять при mount,
не удалять источник при чтении и не перезаписывать занятый ввод. Отдельный новый
V2 draft содержит direct quote ID. Edit draft без expectedVersion требует текущего
контекста и явного возобновления, без скрытой подстановки новой версии.
Autosize44–160px, mentions/лимиты, Enter/Shift+Enter/IME сохраняются.
Подтверждённая отправка и неудачный refresh имеют разные состояния.

### Точный критерий автоматического просмотра

В A15f применяем500мс непрерывного спокойного показа body сообщения и высоту
его пересечения с viewport истории не меньше min(50%высоты body,160px).
Документ должен быть visible и окно активно; нужный mobile слой открыт.
Исключить search results, цитаты, собственные/удалённые сообщения и перекрытые
меню/диалогом состояния. Scroll/resize/blur/hidden/смена слоя сбрасывают dwell;
после стабилизации видимые body могут начать отсчёт заново. Сам прыжок не seen.

IntersectionObserver ограничивает кандидатов видимостью в истории; геометрию
уточнять при изменениях viewport и перед завершением dwell. Нельзя полагаться
на callback произвольного pixel threshold: [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)
описывает пересечение и пороги, а не доказательство просмотра человеком.
[Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)
отдельно сообщает скрытие вкладки; focus/blur не заменяют её.

Собирать только квалифицированные IDs в bounded batches1–50; серверный ack
подтверждает результат, после него обновлять unread metadata. Ошибка seen
сохраняет bounded очередь и даёт явный повтор без массового read fallback.
При forbidden остановить refresh/reconnect/send/seen, очистить защищённые
history/search/quotes/participants и очередь; смена канала/actor не переносит
старые ответы асинхронных запросов в новый экран. Старый read_sequence не двигать.

### Проверка этого среза

До runtime: focused проверки чистого merge/range/draft/visibility-кода,
TypeScript/scoped lint и независимый review. Это не заменяет браузерный путь.
В выделенном ROOT окне — настоящие существующие QA actors/история и обычные
server actions: старый deep link/reply, before/after более50 строк, reply-to-reply,
изменённый/удалённый вне страницы original, frozen retry без дубля, V1 draft
recovery, поиск/context/возврат, ошибки Storage и send-success/refresh-error.
Проверить A→пропустить B→C: только реально показанное seen, B остаётся unread
после reload; search/quote/hidden/overlay ничего не гасят. Точные допускаемые
новые message/seen IDs и эффекты закрепить перед этим общим runtime окном;
чужую историю/роль/сессии не менять. Никакого нового общего QA-протокола.

Impeccable: craft-floor непосредственно перед первым UI edit. Один общий раунд
реального desktop/mobile, light/dark,320/390px, focus/keyboard/IME; исправления
пакетом и максимум один подтверждающий визуальный раунд. Не заявлять native,
screen-reader, provider, production или полноту пункта15 по этому срезу.
