## Следующий блок: A15b — автоматическая высота composer

Выбран как самостоятельный пункт уже принятого плана. Он полезен нынешнему
общему вводу, reply/edit composer и будущему единому composer. Для него не
нужны миграция, новые сообщения или изменение бизнес-команд. Общая лента при
этом не считается выполненной и не теряет приоритет следующего большого блока.

Владелец A, ровно два runtime-файла:

- `src/components/v3/team-chat/TeamChatComposer.tsx`: локальный пересчёт высоты
  textarea при изменении draft.body, первом восстановлении черновика/правки и
  изменении доступной ширины. Пустой текст уменьшает поле к прежнему минимуму;
  длинный текст достигает прежней верхней границы и прокручивается внутри.
- `src/components/v3/team-chat/team-chat.module.css`: только свойства высоты,
  overflow/resize у существующей textarea. Сохранить нынешние min44/max160,
  padding, line-height, шрифт, цвета и размеры кнопок; ручное растягивание
  уступает автоматической высоте. Проверить фактические5–6строк при текущем
  computed line-height, без нового оформления всего composer.

Механика: сбросить вычисленную inline-height перед измерением, учитывать padding
и box sizing, ограничить размер существующими CSS-границами. Измерение после
обновления DOM до отрисовки не должно давать видимого скачка. Реагировать на
изменение ширины контейнера, а не порождать цикл observer от собственной высоты;
при скрытом composer с нулевой шириной дождаться его появления. Убрать observer
и отложенную работу при unmount. Не ставить React state только ради пикселей.

Официальные основания:
[React useLayoutEffect](https://react.dev/reference/react/useLayoutEffect)
описывает измерение до repaint и требует симметричной очистки;
[MDN scrollHeight](https://developer.mozilla.org/en-US/docs/Web/API/Element/scrollHeight)
включает padding, но не border;
[MDN ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver)
описывает наблюдение размеров и риск циклов при собственной записи размеров.
Эти API нужны только для геометрии; текущий hydration gate остаётся.

### Что сохраняется

Весь draft и его scoped key; body/mentions/requestId/retryInput; серверный payload;
приоритет неизменяемого retryInput; readonly при pending/uncertain; предел8000;
Enter/Shift+Enter/IME229; focus после подтверждения и отмены; сохранение и ошибка
sessionStorage; состояния отправки/редактирования. Sizing не инициирует submit,
новый UUID, изменение mentions, удаление/переименование черновика или scroll-to-bottom
истории. Commands, shared composer/quote contract и read-state остаются прежними.
После существующего подтверждённого saved setDraft(empty) тот же sizing effect
уменьшает поле; сам успешный server command этим блоком не меняется.

### Impeccable и проверка

Operate/refinement: поле показывает набранный текст, не заставляя вручную
растягивать его; ограничение высоты оставляет место переписке. Сохранить EVO,
Golos, familiar controls и зоны нажатия. Не добавлять анимацию высоты, новые
карточки или подсказки об устройстве системы. Использовать текущие screenshots
A15a как источник incumbent UI и повторно открыть actual composer перед edit
в согласованное QA-окно; craft-floor прочитать непосредственно перед UI-правкой.

После разрешения implementation — scoped lint/types, необходимые существующие
chat checks, одна объединённая проверка desktop/mobile и максимум одна
корректирующая проверка. Размеры принимать по фактическим CSS-измерениям;
предыдущая попытка CDP1280/390/320 из-за browser zoom дала1707/520/427, поэтому
в новом проходе откалибровать viewport перед единственным набором screenshots.

Реальный UI: существующий обычный staff, контролируемый несохранённый текст
через обычное поле, без отправки сообщения. Проверить одну строку → переносы/
длинный текст → внутреннюю прокрутку → удаление текста → минимум; смену ширины,
возврат к каналу и восстановление именно своего QA-черновика. Не трогать чужой
или уже существующий черновик: сначала установить чистый owned-tab context,
после проверки убрать только введённый самим агентом QA-текст обычным UI.
Никаких message/task/Mark read writes или Auth resets. Это ввод в настоящий
composer для проверки геометрии, не выдуманная серверная история/acceptance.

Пустая QA-история позволяет проверить ввод, но не реальные edit/reply contexts
или подтверждённую отправку. Их source path остаётся тем же; положительный
результат без подходящих данных и отдельной authority не заявляется. Не
имитировать saved ради отчёта. Не добавлять snapshot/string tests, повторяющие
реализацию. Независимый exact-head review и protected short CI обязательны.

## Следующие зависимости, пока без номеров миграций

1. Общая лента/цитаты/единый composer — один отдельно спроектированный контракт
   чтения, command reply-to-reply, старых URL и восстановления draft. Сохранить
   исходные IDs/порядок/author/time/body/parent и safe deleted quote, дать
   context before/after и не утратить ответы при rollback. До кода согласовать
   минимальную схему и зарезервировать миграцию у ROOT; здесь ни номер, ни
   конкретное изменение parent-семантики не выбираются.
2. Поиск с возвратом/подсветкой и группировка — после определённого контекстного
   reader; сохранить query, результаты/позицию и явные границы автора/дня.
3. Sparse seen — отдельный контракт, сохраняющий старые прочтения и доступы;
   viewport visibility и активная вкладка не подменяются поиском/цитатой.
   До этого старый whole-channel read не становится автоматическим.
4. Previews каналов и точность ошибки — самостоятельные bounded blocks с
   теми же current-authority и truthful-empty правилами.

A15b не резервирует миграцию и не разрешает эти последующие изменения.
