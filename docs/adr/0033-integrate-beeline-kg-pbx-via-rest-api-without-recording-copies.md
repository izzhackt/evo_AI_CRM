# 0033 — Телефония: Beeline KG ВАТС через REST API, записи без копий

- Статус: принято 2026-10-16 (решения владельца 1–8 того же дня). Контракт —
  [план телефонии, фаза 1](../EVO_TELEPHONY_PLAN_2026-10-16.md).
- Владелец решения: владелец продукта EVO.
- Заменяет: DEC-019 «Deferred» в `docs/specs/EVO_PLATFORM_TZ.md` **только в
  части телефонии** (платёжный шлюз, email-провайдер и подача в вуз остаются
  отложенными) и отсрочку DA-04 в бэклоге для телефонии. Тексты спецификации и
  бэклога не переписываются (append-only): поправкой служат этот ADR и запись
  в `docs/PLAN_CHANGES.md` от 2026-10-16.
- Выполняет, не отменяет: INT-018 (провайдер не показывается как рабочий без
  contract и acceptance). Contract — план, acceptance — §15 плана на настоящих
  звонках.
- Сохраняет: одну Платформу и один Supabase (0020, 0024, 0027); решение
  владельца 2026-08-09 не копировать сырые записи без юридического решения
  (теперь закреплено как правило); приватность WAHA и lead-agent; скрытый 404
  старых маршрутов `/calls` и `/api/webhooks/telephony` (P6B). Не затрагивает
  ADR 0018 и 0019 об amoCRM: перенос продаж из amoCRM шире телефонии и
  оформляется отдельно, здесь только телефония.

## Контекст

EVO звонит клиентам через «Виртуальную АТС Beeline Бизнес» (Beeline
Kyrgyzstan), тенант `evoadmitions.ats.beeline.kg`: пять пользователей, один
номер компании, запись разговоров включена, хранение один год. Менеджеры
звонят из WebRTC-виджета amoCRM. С апреля 2025 в amoCRM записано 30 673
звонка (91 % исходящие), поле результата не заполнено ни разу, больше половины
входящих остаётся без ответа.

В CRM EVO телефонии нет: старый вебхук и страница звонков удалены 04.09.2026
(P6B) без преемника, спецификация откладывает телефонию (DEC-019). Владелец
16.10.2026 поставил цель перенести продажи из amoCRM в CRM EVO в два шага:
сначала параллельно, затем переключить маршрутизацию и всплывающую карточку.

Факты платформы ВАТС (проверено чтением 16.10):

- Тенант отдаёт публичный PDF «REST API Облачной АТС»: двусторонний HTTPS-обмен
  с общим ключом в теле запроса (`token` к ВАТС, `crm_token` к CRM), без
  подписи сообщений. ВАТС шлёт `event`, `history` (с ссылкой на запись) и
  синхронный `contact`; CRM может вызывать `makeCall`, `accounts`, `groups`,
  `history` (CSV) и другие команды. Лимиты, повторы, таймаут и кодировка
  тела не описаны.
- В кабинете блок «Ваша CRM» допускает несколько подключений по REST API, то
  есть EVO можно подключить параллельно amoCRM.
- Ссылка на запись — URL MP3 без подписи: любой владелец ссылки слушает запись.
  Записи удаляются у Beeline примерно через год; первые удаления с текущего
  тенанта ожидаются около 28.10.2026.
- WebRTC-телефон платформы работает внутри её виджетов; публичного WSS-адреса и
  SIP-учёток для сторонней CRM нет.

## Решение

1. **Интеграция через REST API ВАТС, параллельно amoCRM.** EVO подключается
   отдельным подключением «Ваша CRM» с собственным ключом и принимает `event` и
   `history`; маршрутизация звонков по CRM для этого подключения выключена до
   фазы 2. Действующее подключение amoCRM, маршрут входящих и виджет не
   меняются. Если подключение требует общего ключа с amoCRM или ломает виджет,
   запуск останавливается.
2. **Приём — публичный маршрут с тремя защитами.** `POST
   /api/v2/telephony/beeline/inbound` (новый путь; `/calls` и
   `/api/webhooks/telephony` остаются скрытым 404). Выключатель
   `EVO_PLATFORM_TELEPHONY_ENABLED`; жёсткий предел тела 32 КиБ; постоянное по
   времени сравнение `crm_token` до любого обращения к базе. Так как подписи у
   ВАТС нет, а токен лежит в теле, до проверки токена допускается только
   ограниченный плоский разбор тела: это осознанное исключение из правила
   «неподписанное тело не доходит до JSON.parse», принятое для этого
   провайдера. Токен не попадает в базу и журналы. Идемпотентность по ключу
   сообщения и по `callid`; итог `history` окончательный; повтор ВАТС не
   предполагается, страховка — периодическая сверка командой `history` (CSV).
3. **Отдельные таблицы доказательства и очереди.** Таблицы
   `platform_private.telephony_*` (RLS без политик, append-only для доказательства, исходящий
   «ящик» с арендой и попытками). Не расширяем `communication_provider`,
   `provider_webhook_events` и `durable_work_items`: их проверки и внешние
   ключи привязаны к WAHA, а общая таблица — горячий путь WhatsApp. Выбор может
   быть пересмотрен на ревью первого среза (замена слоя очереди, например на
   pgmq, не меняет контракт маршрута).
4. **Записи без копий.** EVO хранит метаданные звонка и непрозрачную ссылку на
   запись как секрет (одна колонка, не в доказательстве, не в журналах, не в
   браузере). Воспроизведение — серверный потоковый прокси с `Range`: право
   проверяет база (`telephony.recording.listen.own` для своих звонков,
   `.all` для остальных), разрешение выдаётся на 15 минут и фиксируется в
   журнале действий, ссылка погашается только серверной функцией, адрес
   проверяется по хосту тенанта и строгому пути (защита от подмены ссылки),
   редиректы не выполняются, тело не буферизуется и не кэшируется. После
   удаления у Beeline (ответ 404 или срок год) состояние становится
   `expired`, ссылка обнуляется, в карточке — «запись удалена по сроку
   хранения». Сохранение отдельного звонка и расшифровка ИИ — только по
   отдельному решению после юридической оценки.
5. **Звонок из CRM — `makeCall` на устройство сотрудника.** ВАТС звонит
   сотруднику на зарегистрированное устройство и затем соединяет с клиентом.
   Номер берётся на сервере из доступной сотруднику карточки; ручного набора
   нет; лимит в сутки; идемпотентность по `request_id`; повтор `makeCall` не
   выполняется автоматически. Встроенный в браузер телефон (WebRTC) не входит
   в фазу 1: он зависит от WSS и SIP-учёток, которые должен подтвердить
   Beeline/ITooLabs. Точка решения G-SP (вкладка amoCRM, «Коммуникатор»,
   мобильное приложение, встроенный WebRTC, amoCRM только как телефон)
   закрывается до выхода из фазы 1.
6. **Автоматика — по включателям.** Пропущенный входящий → задача
   «Перезвонить» (15 рабочих минут), неизвестный номер → лид `phone_call`,
   «Недозвон» и следующий шаг, автозакрытие при отвеченном звонке. Включатели
   в настройках организации, по умолчанию выключены, чтобы EVO не создавал
   работу, пока команда работает в amoCRM; включаются после недели сверки с
   отдельного «да» владельца. Лид `phone_call` в «Заявках» требует новой версии
   очереди `staff_requests_queue_v3` (v2 берёт только `website` и `whatsapp`).
7. **Права и аудит.** Шесть прав уровня организации
   (`telephony.call.dial`, `telephony.recording.listen.own|all`,
   `telephony.report.read.own|all`, `telephony.manage`) по шаблону 268;
   «свои»/«все» решает функция в базе по сопоставленному сотруднику, а не
   область права. Журнал: прослушивание, набор, результат, правки настроек.
   Номер телефона клиента сотрудникам показывается маской.
8. **Секреты.** Только в игнорируемом env и SOPS-архиве: `EVO_PLATFORM_TELEPHONY_CRM_TOKEN`,
   `…_PBX_TOKEN`, URL и хост тенанта. Токены не
   повторяют друг друга и ключ amoCRM. Подключение «Ваша CRM», правка edge,
   ledger, выпуск и включение приёма — отдельными разрешениями владельца.
9. **Фаза 2** (ответ на `contact` с ответственным, всплывающая карточка,
   переключение маршрута, отключение виджета amoCRM) — отдельным планом после
   выхода из фазы 1.

## Последствия

- Звонки, записи (ссылки), результаты и отчёт по ним появляются в EVO без
  копирования звука. Вместе с решением владельца это означает: записи, которых
  к моменту подключения уже нет у Beeline, и записи старше года потеряны для
  EVO; обратного хода нет.
- EVO получает публичный маршрут с токеном в теле. Его поверхность атаки
  ограничена выключателем, пределом тела, лимитом неудачных попыток, длинным
  случайным токеном, правкой edge (только `POST`, предел тела, при известных
  адресах — `remote_ip`) и тем, что до проверки токена нет обращений к базе.
- Нужна отдельная очередь и фоновый скрипт (`telephony-maintenance.mjs` по
  таймеру): повтор проекции, сверка, срок перезвона, отметка истёкших записей.
  Контейнер приложения остаётся `read_only`.
- EVO и amoCRM параллельно получают одни и те же события. До включения
  автоматики дублей задач и лидов нет; после — двойная работа менеджеров
  возможна, пока команда не перешла в EVO; это решение владельца о моменте
  включения.
- Метаданные звонка (номер, время, сотрудник, результат) — персональные
  данные клиента того же класса, что переписка. Юридическая оценка записи,
  транзита звука через сервер EVO и строки в политике сайта (Цифровой кодекс
  КР) остаётся за юристом КР; уведомление о записи включает владелец.
- Новые миграции (ориентир 287–293) нумеруются при слиянии по свежему
  `origin/main`: 283–286 заняты открытыми PR приложения студента.

## Не решается этим ADR

- Отключение amoCRM и перенос истории звонков и записей из amoCRM.
- Wazzup и WAHA: Wazzup остаётся как есть, WAHA возвращается отдельным планом.
- Расшифровка и пересказ звонков ИИ; номера под рекламные каналы.
- Тариф Beeline (API, шестой пользователь, хранение).
