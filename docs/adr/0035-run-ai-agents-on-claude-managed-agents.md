# 0035 — ИИ-агенты EVO на Claude Managed Agents

- Статус: принято 2026-10-22 (решение владельца в беседе того же дня: «давай делаем … управлять через раздел нашего CRM»). Контракт реализации —
  [docs/design/ai-agents/contract.md](../design/ai-agents/contract.md). Запись плана:
  `docs/PLAN_CHANGES.md` «2026-10-22 · ИИ-агенты на Claude Managed Agents: план».
- Владелец решения: владелец продукта EVO.
- Дополняет: [ADR 0021](0021-unified-net-new-pilot-and-human-reviewed-gemini.md) и
  [ADR 0032](0032-run-the-ai-agent-as-a-private-evo-service.md). Они говорили «один провайдер ИИ,
  Gemini». После этого ADR в CRM два независимых ИИ-продукта: **Gemini-помощник в чате**
  («ИИ-агент», P1–P4, остаётся как есть и один раз показывается карточкой в новом разделе) и
  **ИИ-агенты на Claude** (этот ADR). У них разные данные, разные пути вызова и разные выключатели; ни один
  не зависит от другого.
- Сохраняет: одну Платформу и один Supabase (0020, 0024, 0027, 0034); границы клиентской базы знаний
  и порядок авторитетов знаний (0029); канонический путь исходящих WhatsApp (044, 266, 276);
  Supabase Auth как единственный вход сотрудников; replace-not-layer.
- Не затрагивает: ночной автоответчик Gemini (ADR 0031) и его выключатели.

## Контекст

Владелец хочет «ИИ-отдел» внутри CRM: агента-аналитика (недельный отчёт руководству), агента продаж
(заявки сайта и WhatsApp), кураторов по направлениям (Китай, Малайзия; Европа, ОАЭ, Турция позже).
Агенты должны читать данные CRM (лиды, дела, документы, платежи, чаты, каталог, база знаний), ставить
задачи, писать заметки, готовить отчёты и писать клиентам и студентам — сами или через одобрение
сотрудника. Управление — в разделе CRM: включить, переключить «Авто», поправить инструкцию, запустить
вручную, посмотреть, что агент делал и сколько это стоило.

Проверенные 22.10.2026 факты о платформе Claude Managed Agents (документация platform.claude.com):
бета; размещённый «агентный цикл» с песочницей; агенты версионируются; свои MCP-серверы подключаются
по URL с токеном из vault (`static_bearer`), по умолчанию политика инструментов MCP — «спрашивать
человека», её можно переключить в `always_allow`; запуски по cron — «развёртывания»; бюджет на сессию
в центах; события сессий хранятся на стороне Anthropic до удаления; Managed Agents не входит в
zero data retention (ZDR); географии хранения — США.

## Решение

1. **Где живут агенты.** В Claude Managed Agents, под управлением CRM. CRM создаёт и обновляет агента,
   среду, vault и расписание через REST (`fetch`, без SDK и новых зависимостей), хранит ключ
   `EVO_ANTHROPIC_API_KEY` только в окружении приложения и показывает сотрудникам состояние. Первичное
   создание агента допустимо и в Claude Console (CRM может подхватить его по id); единая панель — CRM.
2. **Как агенты видят CRM.** Через собственный MCP-сервер CRM `POST /api/mcp/v1` (JSON-RPC, streamable
   HTTP с JSON-ответами, без состояния). Идентификация: токен на каждого агента (256 бит), в БД только
   SHA-256, в vault Claude — открытым текстом (write-only); принимается только с исходящих адресов
   Anthropic (`160.79.104.0/21`, переопределяется окружением); окно ротации токена 10 минут. Инструменты —
   24 штуки (19 чтений, 5 записей), каждый — функция БД `service_role` в схеме `platform` с проверкой
   аргументов, минимизацией данных и строкой в журнале действий агента; чтения персональных данных и все
   записи видны также в «Журнале действий» платформы.
3. **Доступ агента.** Все агенты видят все инструменты (решение владельца): ограничения — только
   промптом. Это принятый риск: инъекция через сообщение клиента или документ может заставить агента
   вызвать любой инструмент. Смягчают не промпт, а механика: предохранители отправки в БД
   (ответ только на последнее входящее; молчание, если за последние 30 минут писал сотрудник; не более
   6 сообщений в час на диалог и 60 в организации), черновики при выключенном «Авто», журнал каждого
   вызова, выключатель агента (выключенный агент отвечает инструментами ошибкой `agent_disabled`),
   потолок расхода на запуск и общий лимит в Claude Console. Студенческие «приватные» данные (оценки,
   обучение) и банковские реквизиты, паспортные номера, секреты базы знаний, ссылки на записи звонков
   и всё из amoCRM инструменты не отдают.
4. **Только данные EVO CRM.** amoCRM не читается и не пишется; уход из amoCRM — отдельное решение и
   отдельный план, агенты от него не зависят.
5. **«Авто» и черновики.** «Авто» включён — агент пишет сам; выключен — `send_message` создаёт черновик,
   который сотрудник правит и одобряет в CRM. Сотрудник может приказать отправить сразу без включения
   «Авто»: переключатель «Отправлять без черновика» на время разговора реализован кодом полномочия,
   который знает только БД и первое сообщение этого разговора (не доверием модели). Кабинет студента —
   запись в чат дела тем же кодом, что у сотрудника; WhatsApp — тот же канонический путь «авторизация →
   очередь → WAHA → итог», что у ручной отправки и автоответчика, с новым видом авторизации
   `ai_agent`.
6. **Документы студентов.** Агенты читают их (решение владельца): инструмент выдаёт одноразовую ссылку
   на 10 минут и 3 скачивания на хост CRM, файл скачивается в песочнице агента и читается там. Байты в
   ответы MCP не кладутся. Каждая выдача — событие журнала платформы.
7. **Деньги.** Лимиты расходов задаёт владелец в Claude Console. CRM только показывает расход по
   запускам (по прайс-листу Anthropic, `list_cost` сессии) и ставит страховочный потолок на запуск
   (по умолчанию 5 долларов, настраивается, 0 — без потолка).
8. **Кто что меняет.** Настройки агента (включить, «Авто», модель, инструкции, расписание, токен,
   синхронизация) — только системный администратор; просмотр, «Поручить» и решения по черновикам —
   сотрудники с правами `ai.agent.use`/`ai.agent.manage` (есть у всех, миграция 268). Эти права
   переиспользуются, новых прав нет.
9. **Хранение и передача данных.** Записи CRM, которые агент прочитал через MCP, и документы, которые
   он скачал, становятся частью **протокола сессии у Anthropic (США)** и остаются там, пока сессия не
   удалена (в CRM и Console). ZDR недоступен. CRM не копирует хронику в БД: она читается у Anthropic по
   запросу. В БД остаются только метаданные запуска (время, статус, токены, расход, краткий итог ≤ 4000
   знаков), строки действий (инструмент и сокращённые аргументы ≤ 300 знаков без текстов) и черновики.
   Сессии в Console удаляются по необходимости владельцем; автоматического удаления нет.
10. **Модель.** `claude-sonnet-5-5` по умолчанию; на агента выбираются `claude-opus-5-5`,
    `claude-sonnet-5-5`, `claude-haiku-5-5`.
11. **Событийные запуски.** Приём заявки сайта и входящее WhatsApp запускают включённого агента «Продажи»
    после собственной обработки (через `after()`, без ожидания и без влияния на приём), не чаще одного
    запуска вида события за 5 минут. Запуски по расписанию — «развёртывания» Anthropic; вебхуки
    Anthropic не используются, сверка ленивая.

## Последствия

- **Политика и согласие.** Черновик публичной политики конфиденциальности сейчас говорит, что EVO «не
  использует ИИ для написания и отправки клиентам ответов». С включённым «Авто» это неверно;
  правила Apple 5.1.2(i) требуют явного разрешения студента на передачу данных стороннему ИИ. До
  включения «Авто» для клиентов и студентов нужно обновить политику и текст согласия (решение владельца и
  юриста). Режим черновиков с одобрением сотрудником совместим с ADR 0032 («черновик, который
  просмотрел и отправил человек, — не клиентский ИИ»); данные при этом всё равно уходят в Anthropic.
- **Второй сторонний процессор данных.** К Google (Gemini) добавляется Anthropic. Список процессоров и
  DPA (в черновике политики) расширяется. Anthropic в своих Commercial Terms обязуется не обучать
  модели на данных клиента; соглашение об обработке данных (DPA) включено в условия по ссылке.
- **Публичный репозиторий.** Инструкции по умолчанию (`src/content/ai-agents/*.md`) лежат в Git:
  процедуры без персональных данных, цен, реквизитов и кодов агентов. Если владелец против публикации
  процедур, они переносятся в `instructions_override` (БД) без смены кода.
- **Бета-платформа.** Формы API взяты из документации и сверены тестами с подставным `fetch`; на живом
  ключе первая проверка — при включении. Переход платформы на новую версию заголовка беты потребует
  правки клиента.
- **WhatsApp.** Сессия `crm_primary` отключена с 12.10: путь отправки готов и покрыт проверками на
  подставном провайдере, но не прогонялся на живом WAHA. Пока WhatsApp отключён, `send_message` по
  WhatsApp отвечает понятной ошибкой/черновиком, а не пропадает.
- **Лента чата.** Сообщение агента в ленте WhatsApp-чата CRM отображается как написанное сотрудником-отправителем;
  метка «ИИ-агент» в ленте — отдельная правка (пробел G1 в контракте).
- **Эксплуатация.** Миграция 317 применяется workflow `EVO schema ledger` до выпуска приложения;
  `EVO_ANTHROPIC_API_KEY` добавляется владельцем в окружение production; строка `header_up` в edge — по
  желанию. Подробно — контракт §10 и `docs/runbooks/ai-agents-managed.md`.

## Рассмотренные и отклонённые варианты

- **Агент на нашем сервере (Agent SDK или цикл на Messages API).** Больше контроля над потоком данных
  и возможность ZDR для Messages API, но свой хостинг, расписание и наблюдаемость. Владелец выбрал
  управляемую платформу ради скорости; путь к Agent SDK остаётся открытым, потому что MCP-сервер, функции БД,
  интерфейс и инструкции от платформы исполнения не зависят.
- **Коннектор Claude Team с общей учётной записью.** Подходит для ручных вопросов владельца, но не для
  автоматических запусков, расписаний и очереди черновиков.
- **Подтверждение человеком каждого вызова (`always_ask`).** Выбран `always_allow`: решение «писать клиенту
  сразу или черновиком» принимает БД по переключателю «Авто», а не пауза сессии в ожидании клика.
- **Права на агента (разные наборы инструментов).** Отклонено владельцем: все инструменты всем,
  ограничения промптом.
- **Гибридный поиск по знаниям с эмбеддингами Gemini для агентов Claude.** Отклонено ради скорости:
  полнотекстовый поиск по уже проиндексированным фрагментам. Семантический поиск — позже.

## Не решается этим ADR

- Текст политики конфиденциальности и согласия студента; метка «ИИ» для клиентов.
- Включение «Авто» для клиентов и студентов, подключение WhatsApp, вывод кураторов Европа/ОАЭ/Турция.
- Расширение агентов инструментами подачи в вузы и платежей (сейчас агенты только читают платежи).
- Автоматическое удаление сессий у Anthropic по сроку; перенос агентов на собственный сервер.
