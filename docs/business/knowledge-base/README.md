## Что было очищено

Ниже зафиксирована историческая подготовка исходных материалов. Она не заменяет
нынешний approval gate: коммерческие значения могут быть полезным контекстом,
но весь документ допускается к AI только после проверки правил и явного
статуса Approved.

- удалены отметки черновика и `⚠️`;
- удалены открытые вопросы, незакрытые расшифровки и неопознанные названия;
- удалён повторный FAQ, который дублировал почти весь основной текст;
- исправлены нумерация, терминология и структура;
- цена услуг EVO отделена от обучения, проживания, визы и других платежей;
- добавлены правила ответа, минимальная квалификация лида, защита чувствительных
  документов и понятные причины передачи менеджеру;
- исходные коммерческие утверждения, цены, траектории, этапы и обещания не
  заменялись внешним фактчекингом.

Оригиналы в Downloads не изменялись:

| Исходный файл | SHA-256 |
| --- | --- |
| `Китай — база знаний для бота (1).md` | `aefe50aac82ccbd26bc3a01ac01d6a4da3180cbb66e6a6e24ce835f4d360f7bb` |

Checksum — это цифровой отпечаток файла. Совпадающий SHA-256 доказывает, что
в исходнике не изменился ни один байт.

## Как загрузить approved knowledge в EVO Inbox

Сейчас EVO Inbox не имеет кнопки загрузки `.md`-файла. Форма принимает два
поля: название и текст. Поэтому файл используется как подготовленный источник
для копирования.

Следующие действия выполняются только для страны/версии со статусом
**Approved**. Текущую Malaysia-версию не загружайте.

1. Откройте EVO Inbox и войдите под учётной записью с правом изменения настроек.
2. Откройте **Настройки → AI → База знаний**.
3. Нажмите **Добавить документ**.
4. Скопируйте название из таблицы выше в поле названия.
5. Откройте соответствующий Markdown-файл и скопируйте весь текст в поле
   содержания.
6. Нажмите **Сохранить документ** и дождитесь успешного завершения.
7. Убедитесь, что в списке появился ровно один документ для этой страны.
8. Не добавляйте другие страны или версии без отдельного review и статуса
   Approved.

При сохранении EVO Inbox автоматически:

- делит текст по абзацам на фрагменты не длиннее 1 200 символов;
- создаёт поисковое представление каждого фрагмента;
- создаёт embedding для семантического поиска, если provider настроен;
- записывает документ и его фрагменты в Supabase.

Отдельная кнопка «переиндексировать» после успешного сохранения не нужна.

### Проверенный размер фрагментов

Проверка 2026-07-13 запустила реальную функцию `chunkText` из EVO Inbox с её
стандартной границей 1 200 символов:

| Документ | Фрагменты | Самый длинный фрагмент | Фрагментов сверх лимита |
| --- | ---: | ---: | ---: |
| Китай | 14 | 1 197 символов | 0 |
| Малайзия | 13 | 1 185 символов | 0 |

Это историческая проверка структуры текста, а не approval содержания.
Фактическое создание embeddings происходит при сохранении в настроенном EVO
Inbox. Заблокированный Malaysia-документ не должен доходить до этого шага.

## Business context для поля инструкций

Approved страновой документ отвечает на вопрос «что конкретно разрешено
сообщать по этой стране». Стабильные правила «кто такая EVO, как разговаривать,
что спросить и когда позвать менеджера» должны быть доступны при каждом ответе,
даже если поиск не нашёл фрагмент страны.

Готовый текст для поля **Инструкции** находится в разделе
[«Готовый business context для EVO Inbox»](../evo-business-context.md#готовый-business-context-для-evo-inbox).

Не копируйте весь большой бизнес-документ в поле инструкций. Используйте только
короткий блок из указанного раздела, а страновые факты храните здесь.
AI готовит только RU/EN-черновик по языку последнего сообщения. Если язык не
определён уверенно как RU/EN, сотрудник выбирает его вручную или забирает
диалог. AI не отправляет сообщение самостоятельно.

## Как обновлять знания

1. Владелец бизнес-факта подтверждает изменение цены, программы, срока,
   партнёра, документа или обещания.
2. Создаётся новая versioned редакция канонического текста; исторический
   источник не перезаписывается для сокрытия изменений.
3. Изменение проходит review и PR в GitHub и получает явный статус Approved.
4. Администратор открывает существующий документ страны в EVO Inbox, заменяет
   текст и сохраняет его.
5. Старый документ не добавляется второй раз: обновление существующей записи
   пересоздаёт её фрагменты.
6. После сохранения проверяется один реальный вопрос, затронутый изменением.

Пересмотр нужен сразу при изменении цены, набора, дедлайна, партнёра, визового
процесса или состава услуги, а также не реже одного раза в месяц во время
активного набора.

## Что нельзя добавлять

Не загружайте в базу знаний:

- реальные паспорта, анкеты, медицинские документы или банковские справки;
- имена, телефоны, адреса и переписки клиентов;
- банковские реквизиты EVO;
- пароли, API keys, токены, session data или содержимое `.env`;
- неподтверждённые заметки, голосовые расшифровки и открытые вопросы;
- обещания admission, scholarship, visa или другого внешнего решения;
- второй документ с теми же фактами.

## Решение по внешним гарантиям

Исходный материал по Малайзии содержит заявления о гарантированной визе и
поступлении. Решение едино для всех стран: EVO гарантирует только выполнение
собственных согласованных услуг и обязательств и не гарантирует admission,
scholarship, visa или решение внешнего органа.

Версия Malaysia-файла от 2026-07-13 имела статус **not approved / blocked**. Её
формулировки о гарантиях удалены в v2 от 2026-10-18 (раздел «Журнал версий»).
Пока владелец не поставил явный статус Approved, файл нельзя загружать,
индексировать, цитировать в AI-черновике или переносить в другой канал. Конфликт
и решение описаны в
[бизнес-контексте](../evo-business-context.md#гарантии-по-малайзии).

Чтобы вернуть материал по Малайзии в knowledge base, нужны review/PR этой
версии и явный статус Approved. До этого никакого исключения для страны нет.
