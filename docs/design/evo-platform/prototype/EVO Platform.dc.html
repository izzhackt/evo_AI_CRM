01

Источники истины и границы

Дизайн опирается на подтверждённый бизнес-контекст EVO. Текущее разделение CRM и Inbox не считается обязательным будущим UX — они объединены в один продукт с единой моделью данных и навигацией.

Владельцы данных

amoCRM — контакт, лид, ответственный, этап продаж, история продаж.
EVO CRM — профиль студента и операции поступления (заявки, документы, виза, платежи, задачи).
Supabase (Inbox) — диалоги, сообщения, настройки и база знаний.
WAHA — транспорт WhatsApp; внешние органы — решения по заявке, гранту и визе.

Единый UX не означает одну физическую базу. Связанные данные показывают источник, статус синхронизации и конфликты.

Непреложные границы v1

amoCRM остаётся источником истины по продажам.
AI-ответы клиентам — только черновики, отправляет человек.
EVO Lead Agent — backend-only, без отдельного UI.
Этап продаж и операционный этап студента визуально различимы.
Массовые рассылки и авто-ответы — вне v1.
CONFIRMED — подтверждённый repo-факт HYPOTHESIS — безопасное допущение v1 OPEN DECISION — требует решения владельца

Роли и доступ

Навигация, экраны и действия меняются по роли. Права показываются не только скрытием пунктов меню, но и состояниями «только чтение», «нет доступа» и «требуется подтверждение». Полная матрица — в разделе «Администрирование → Роли».

Руководство
Обзор компании, KPI, воронка, риски, нагрузка, аудит.
Администратор
Пользователи, роли, интеграции, готовность, аудит.
Продажи
Лиды, воронка amoCRM, квалификация, консультации, договор.
Куратор
Student 360, стратегия, документы, заявки, дедлайны, связь.

04

Сквозные сценарии

Восемь кликабельных end-to-end потоков. Начните с точки входа — навигация, состояния и действия работают внутри прототипа.

1
Обращение → квалификация → встреча → договор → Student 360
Дашборд → «Новое обращение» → шаги мастера
 2
WhatsApp → AI-черновик → правка → ручная отправка → статус доставки
Диалоги → кнопка AI → «Вставить» → отправить
 3
Документ → проверка → возврат → переделка → принят
Очередь документов → карточка → решение; со стороны студента — в портале
 4
Стратегия → заявка → подача → решение → зачисление
Заявки → карточка → обновление статуса
 5
Виза: чек-лист → запись → подача → решение
Визовые кейсы → карточка студента → вкладка «Виза»
 6
Просрочка платежа → блок → действие → разблокировка
Финансы → «Подтвердить оплату» снимает визовый блок
 7
Приглашение → назначение роли → ограниченный доступ
Админ → пригласить; проверьте ограничения сменой роли
 8
Студент: следующий шаг → загрузка документа → статус
Портал → «Следующее действие» → загрузить новую версию

06

Гипотезы и открытые решения

HYPOTHESIS
Единый вход для сотрудников. Staff Workspace и Inbox используют одну навигацию и учётную запись. В коде это раздельные приложения — объединение принято как безопасное направление v1.
HYPOTHESIS
Разблокировка визы по оплате. Подтверждение платежа снимает финансовую блокировку визового этапа. Правило требует утверждения владельцем финансов.
OPEN DECISION
Гарантии по Малайзии. Источник содержит формулировку «гарантированная виза / 100% поступление», конфликтующую с общим правилом «результат принадлежит внешнему органу». В прототипе используется осторожная формулировка; требуется решение руководства.
OPEN DECISION
Доступ родителя/спонсора. Показаны как связанные лица без отдельного входа. Отдельный логин для них — открытое решение.
OPEN DECISION
KPI и метрики. Показатели в отчётах демонстрационные. Владельца, формулу, цель и период для каждого KPI ещё нужно утвердить.

Заметки для разработки

Что это

Высокоточный кликабельный фронтенд-прототип в единой дизайн-системе. Данные — обезличенные демонстрационные. Интеракции показывают намерение UX.

Что НЕ реализовано

Реальные интеграции amoCRM, WAHA, Supabase, AI и телефонии не подключены и не проверены. Никакая интеграция не является «работающей» в этом прототипе. Backend строится отдельно по этому handoff.
