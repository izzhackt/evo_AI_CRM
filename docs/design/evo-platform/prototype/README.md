# Handoff: EVO Platform — единый фронтенд и кликабельный прототип

## Overview

Единая продуктовая система EVO Admissions (образовательный консалтинг, Бишкек),
объединяющая работу сотрудников и кабинет студента поверх полного жизненного цикла
клиента: первое обращение → квалификация → консультация → договор → операционное
дело студента → стратегия → документы → заявки в вузы → offer → виза → оплата →
зачисление. Продукт состоит из двух поверхностей в одной дизайн-системе:

- **Staff Workspace** — desktop-first рабочее пространство сотрудников (мастер-вьюпорт 1440×1024).
- **Student Portal** — mobile-first кабинет студента (мастер-вьюпорт 390×844).

Текущие раздельные EVO CRM и EVO Inbox сведены в один UX с общей навигацией,
объектной моделью и языком взаимодействия.

## About the Design Files

Файлы в этом бандле — **дизайн-референсы, созданные в HTML** (формат Design Components:
единый `Name.dc.html`, использующий рантайм `support.js` и inline-стили). Это
высокоточные прототипы, показывающие внешний вид и поведение, **а не production-код
для прямого копирования**.

Задача разработчика — **воссоздать эти экраны в целевой кодовой базе** её
средствами и паттернами. Существующий репозиторий EVO — **Next.js + React + TypeScript**
(основная CRM на SQLite, EVO Inbox на Supabase). Рекомендуется реализовывать UI на
React с существующей компонентной библиотекой проекта (shadcn/ui присутствует в
`components.json`), перенося точные значения токенов из этого хендофа.

## Fidelity

**High-fidelity (hifi).** Финальные цвета, типографика, отступы, статусы и
интеракции. UI следует воссоздавать пиксель-в-пиксель средствами кодовой базы.
Точные значения — в разделе Design Tokens и в самих `.dc.html` (inline-стили).

## Non-negotiable product rules (перенести в реализацию)

- **amoCRM — источник истины** для контакта, лида, ответственного и этапа продаж.
  Платформа отображает и использует эти данные, но не создаёт независимую воронку.
- **AI — только черновики.** AI генерирует черновик ответа клиенту; сотрудник
  проверяет, редактирует/пересоздаёт и **отправляет вручную**. Никакой авто-отправки.
- **EVO Lead Agent — backend-only**, без отдельного UI.
- Этап продаж (amoCRM) и операционный этап студента — **визуально различимы** и
  не смешиваются в одну воронку.
- Массовые рассылки, broad automations и авто-ответы — **вне v1**.
- Связанные данные всегда показывают источник, `last synced`, `sync pending`,
  `sync failed`, `integration unavailable`, `data conflict`, `possible duplicate`.
- Прототип **не** утверждает, что amoCRM / WAHA / Supabase / AI / телефония
  реально подключены — интеграции не сконфигурированы и не проверены.

## Screens / Views

### Staff Workspace (`EVO Staff Workspace.dc.html`)

Общая рамка: слева тёмный сайдбар (ink `#131519`, 250px) с логотипом, поиском (⌘K),
сгруппированной ролевой навигацией (Операции / Работа / Коммуникации / Аналитика /
Система), карточкой пользователя. Сверху топбар (60px): хлебные крошки, статусы
интеграций (amoCRM/WAHA/AI), колокол уведомлений с бейджем, переключатель роли.
Контент центрируется в колонке max-width 1360px.

1. **Аутентификация** — сплит-экран: тёмная брендовая панель + форма входа; блок
   состояний доступа (приглашение по ссылке, истёкшая ссылка, истёкшая сессия).
2. **Командный центр (дашборд)** — ролевой: kicker + заголовок + подзаголовок,
   4 KPI-плитки, «Требует внимания сейчас» (приоритетная очередь), воронка/этапы,
   активность каналов, ближайшие дедлайны. Контент меняется по роли.
3. **Поступление · воронка** — сегмент Канбан/Список. Канбан: 6 колонок по этапам
   amoCRM (В обработке МП / Лид квалифицирован / Назначена встреча / Встреча
   проведена / Договор подписан / Лиды без запроса), карточки лида (аватар, сумма,
   страна, чипы amoCRM/задача/непрочитанные). Список: таблица.
4. **Lead 360** — шапка (статус, amoCRM-синхро, действия: Написать/Позвонить/
   Задача/Создать Student 360), квалификация, активность/история, правая колонка
   (amoCRM sync, участники решения, ответственный). Баннер конфликта данных.
5. **Student 360 (список)** — таблица: студент, этап (чип), направление, куратор,
   прогресс, риск.
6. **Student 360 (карточка)** — шапка, баннер риска/блокировки, степпер
   операционных этапов, вкладки: Обзор / Стратегия / Заявки / Документы / Виза /
   Финансы / Задачи / История. Обзор: следующее действие, статы, история, команда,
   участники решения, договор.
7. **Заявки в вузы** — фильтр-чипы по статусу; таблица (университет, студент,
   программа, дедлайн, статус). Карточка → drawer обновления статуса.
8. **Документы** — очередь с фильтр-чипами; строки (документ, студент, комментарий,
   статус) → drawer проверки (превью, AI-подсказка, Принять / На доработку / Отклонить).
9. **Виза** — очередь визовых кейсов (студент, страна, статус, запись, риск).
10. **Финансы** — 3 KPI (оплачено/ожидается/просрочено), баннер финблокировки с
    разблокировкой, таблица платежей с «Отметить оплату».
11. **Задачи и календарь** — сегмент Доска/Список/Календарь. Доска: 4 колонки
    (К выполнению / В работе / На проверке / Готово). Календарь: месяц + агенда.
12. **Звонки и встречи** — баннер «телефония не настроена» + журнал звонков.
13. **Диалоги (Inbox)** — 3 колонки: список диалогов | тред + композер + AI-черновик |
    контекст-панель (связанный лид/студент, действия, внутренняя заметка). Статусы
    доставки, состояние WAHA.
14. **Уведомления** — группировка по срочности (Срочное / Сегодня / Ранее).
15. **Отчёты** — KPI, столбчатый график, донат источников, таблица менеджеров,
    период-селектор.
16. **Администрирование** — вкладки: Пользователи / Роли и права (матрица 7 ролей) /
    Интеграции (готовность amoCRM/WAHA/AI/телефония) / Аудит.
17. **Нет доступа** — состояние для запрещённого роли раздела.

### Student Portal (`EVO Student Portal.dc.html`)

Телефонная рамка 390×844 (bezel `#0B0C0E`), статус-бар, топбар с колоколом,
нижняя таб-навигация (Главная / Документы / Заявки / Сообщения / Профиль).
Переключатель «Телефон / Десктоп» демонстрирует десктоп-адаптацию (760px, тот же
контент). Экраны: Главная (кольцо прогресса, следующее действие, путь поступления,
плитки Виза/Оплаты/Команда, обновление), Документы (чек-лист + bottom-sheet
переделки с загрузкой), Заявки, Виза, Оплаты, Сообщения (тред), Моя команда,
Профиль, Вход.

## Interactions & Behavior

- **Навигация**: ролевой сайдбар; клик по разделу без прав → экран «Нет доступа»;
  разделы с доступом «только чтение» показывают read-only баннер.
- **Переключение роли** (топбар): меняет лендинг, видимость и права навигации,
  контент дашборда. 7 ролей: leadership, admin, sales, curator, visa, finance, inbox.
- **Command palette** (⌘K): быстрый переход к разделам/записям.
- **Сегменты** (Канбан/Список, Доска/Список/Календарь): переключают представление.
- **Фильтр-чипы** (документы, заявки): реальная фильтрация списка.
- **Drawers** (справа, анимация slideup 0.2s): мастер обращения (4 шага), проверка
  документа, обновление статуса заявки.
- **Flow: AI-черновик** — кнопка AI генерирует черновик → «Вставить в ответ» →
  редактирование → отправка; сообщение появляется в треде со статусом «Отправлено»,
  через ~1.5с → «Прочитано» (демонстрация статусов доставки).
- **Flow: проверка документа** — Принять/На доработку/Отклонить меняет статус
  документа (в очереди и карточке студента), toast-подтверждение.
- **Flow: финблокировка** — «Подтвердить оплату» помечает платёж оплаченным и
  снимает блок визового этапа.
- **Портал: переделка документа** — «Следующее действие» → карточка документа →
  bottom-sheet → «Отправить на проверку» → статус документа «На проверке».
- **Deep-links**: `EVO Staff Workspace.dc.html?role=<role>&view=<view>` открывает
  нужную роль/экран (читается в `componentDidMount`).
- **Toasts**: подтверждения действий (2.4с).
- Все интеракции демонстрируют намерение; backend не вызывается.

## State Management

Логика каждого экрана — в классе `Component extends DCLogic` соответствующего
`.dc.html` (плоский классовый React-компонент без `render()`, метод `renderVals()`
возвращает данные шаблона). Ключевое состояние Staff Workspace:

- `role`, `view` — роутер и ролевой контекст.
- `activeLeadId`, `activeStudentId`, `activeConvId`, `studentTab`, `adminTab` — выбор.
- `salesView`, `tasksView` — представления.
- `docFilter`, `appFilter` — фильтры очередей.
- Оверрайд-мапы (демо-мутации): `docState`, `appState`, `payState`, `visaState`,
  `taskState`, `sentMsgs`, `aiDraft`, `composer` — позволяют интерактивным потокам
  реально менять статусы в рамках сессии.
- `PERMS` — матрица прав `role → key → full|read|none`; `PERMS`, `NAV`, `ROLES` —
  статическая конфигурация.

Portal: `mode` (phone/desktop), `view`, `docState`, `docSheetId`, `notifOpen`, `toast`.

В production это переносится на реальный роутинг (Next.js App Router), серверные
данные и состояние прав на бэкенде; оверрайд-мапы заменяются мутациями через API.

**Канонические статусы (RU-лейблы):**

- Операц. этап: Лид / Консультация / Договор / Документы / Подача заявок / Оффер /

- Заявки: Готовится / Подана / Оффер / Отказ / Зачислен.
- Документы: Требуется / Загружен / На проверке / Принят / Отклонён.
- Виза: Не начато / Сбор документов / Запись в посольство / Подано / Одобрена / Отказ.
- Платежи: Ожидает / Оплачен / Просрочен.
- Задачи: К выполнению / В работе / На проверке / Готово; приоритет Низкий/Обычный/

## Assets

- **Иконки**: единый линейный набор (стиль Lucide/Feather, stroke 1.75), собран в
  `evo-icons.svg` как SVG-спрайт `<symbol>` (ids `i-*`). В каждом `.dc.html` спрайт
  встроен inline (внешний `<use href>` в этой среде не резолвится). В production —
  использовать `lucide-react` (эквивалентные иконки) или встроенный спрайт.
- **Логотип**: воспроизведён типографически (Montserrat 800 «EVO» + красная точка +
  разрядка «ADMISSIONS»). Не искажать, не перекрашивать, без теней/градиентов.
  Оригинальный logobook — `docs/company/brand/evo-admissions-logobook.pdf` в репо.
- **Изображения**: реальных фото нет; превью документов — заштрихованный
  плейсхолдер с моноширинной подписью.

inline-`style` внутри шаблонов.
