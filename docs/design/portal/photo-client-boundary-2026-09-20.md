# Фото университетов: граница сервер/браузер

Блок B-5, остаток пункта 26. B-1 принят в main через PR #937
(`22404da81ab9398a28fdca99d879dc9f0b15a0d6`). Это отдельная оптимизация;
контент каталога, права, Storage и правила разрешения URL остаются прежними.

## Подтверждённая причина

На `20229d1915ffd99d18e2caccc1fe3e0cd6634330` выполнена настоящая сборка
Next 16.3.4 с текущей конфигурацией проекта. Audit manifest размером 105396
байт попадает в клиентский chunk `1g_natglpgvsa.js`: 174652 байта,
35315 байт gzip (Node zlib, уровень по умолчанию). В chunk присутствуют schema манифеста и SHA-256 первого
проверенного фото. Это размер содержащего chunk, а не обещание экономии.

Реальный маршрут `/v3/universities` открыт на localhost:3142 существующей
учётной записью Admin. DOM подтверждает загрузку этого chunk, 30 фотографий
на странице и 173570 байт встроенных скриптов. Первые три managed-фото
загружены из настоящего public Storage (naturalWidth 1280, 1280, 800),
подписи и ссылки на автора/лицензию видимы. Это staff-путь, не Student acceptance.

## Изменение

- `PhotoFigure` и `UniversityPhoto` становятся серверными оболочками:
  находят проверенную запись, разрешают URL и формируют атрибуцию.
- Общий маленький клиентский компонент отвечает только за загрузку img
  и состояние ошибки. Подпись приходит серверным children, без импорта
  библиотеки или полного audit manifest в клиентский граф.
- Resolver получает `server-only`, чтобы повторный клиентский импорт
  обнаруживался при сборке. Единственный полный manifest остаётся прежним.
- Сборка обнаружила ещё один прямой импорт: клиентский `FavoritesView`
  использовал `UniversityCard` из `Catalog`. Карточки теперь передаются
  из серверной favorites page; выбор для сравнения, таблица и действия
  избранного сохраняют прежние данные и обработчики.
- Размеры, CSS-классы, RU/KY-строки, lazy/async, no-referrer и ссылки
  атрибуции сохраняются. Изменение URL сбрасывает ошибку прошлого изображения.

Основание: [Server and Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components)
и поставляемая с Next 16.3.4 документация: импортируемые зависимости клиентского
компонента входят в клиентский граф; серверное содержимое можно передать через
children. Эта граница позволяет оставить интерактивность без полной библиотеки.

## Приёмка

После реализации: scoped lint и существующие фото-регрессии, production build,
поиск schema/audit hashes во всех клиентских chunks, сравнение фактически
загружаемых JS и встроенных данных того же маршрута. Открыть настоящий каталог,
сравнить фото/подписи/ссылки, пройти переход в карточку и мобильный размер.
Портальный UI проверять только доступным авторизованным путём; отсутствие
Student-сессии явно записать. Полный E2E, iOS, запись в БД/Storage и релиз
этим блоком не выполняются.

## Результат локальной реализации — 20 сентября 2026

Изменения поверх `22404da81ab9398a28fdca99d879dc9f0b15a0d6`:
scope записан до кода владельцем общего плана в `45d76d397` (PR #938).
Все перечисленные ниже проверки относятся к исходному diff этого PR;
последующий приём в main и серверный выпуск являются отдельными событиями.

| Измерение одной staff-страницы (30 карточек) | До | После |
|---|---:|---:|
| JS chunks, реально указанные в DOM маршрута | 864091 B | 688506 B |
| Сумма тех же chunks, Node zlib gzip default | 245659 B | 209862 B |
| Встроенные скрипты страницы, UTF-8 | 173570 B | 135084 B |

JS уменьшился на 175585 B (20,32%), gzip — на 35797 B (14,57%).
Это сравнение ресурсов страницы, не замер сетевой задержки или Core Web Vitals.
Новый общий image-frame chunk занимает 571 B (389 B gzip). Во всех 67
клиентских JS chunks отсутствуют schema и все 87 действительных audit hashes.
Проверенный полный манифест и библиотека в репозитории не изменены.

- `next build` (production Next 16.3.4) завершился успешно. Первый запуск
  честно выявил клиентскую import-цепочку FavoritesView → Catalog → PhotoFigure;
  после переноса server-card composition повторная сборка проходит.
- Scoped ESLint шести изменённых TS/TSX файлов, `git diff --check` и
  существующие фото-регрессии **10/10 PASS**. Эти тесты включают синтетические
  transport cases прежнего набора и не являются доказательством live apply.
- Impeccable `detect` по пяти изменённым UI-файлам завершился с кодом 0
  без вывода. Новые стили, шрифты или визуальная композиция не добавлялись.
- Реальная Admin-сессия, `/v3/universities`: HTML всех 30 `figure` до/после
  совпал полностью; три первые фотографии имеют прежние URL, подписи и
  naturalWidth. Переход в AGH успешен; при 390 px фото загружено,
  ширина документа 380 px, ширина img 346 px, переполнения страницы нет.
- Обычный вход существующего владельческого QA Student выполнен в отдельном
  браузере из ignored `.env.student-portal-qa.json`, без вывода или копирования
  credentials. `/portal/universities` показывает 30 реальных карточек;
  первые три managed-фото загружены, ссылки CC и атрибуция сохранены.
- `/portal/favorites` показывает три уже существующие записи. Их реальные
  official-source изображения загружены. Две checkbox отмечены клавишей
  Space; таблица сравнения раскрыла страны, программы, уровни и даты,
  фокус остался на checkbox. Это локальное состояние интерфейса, не запись
  избранного. При 390 px таблица прокручивается внутри области 346/560 px
  с `tabIndex=0`, страница не переполняется; переход в European University
  Cyprus сохраняет фото и атрибуцию. Временные viewport overrides сброшены.

Не проверялись: запись/удаление избранного, отправка документов, iOS,
полный E2E, принудительная сетевая ошибка изображения и production deployment.
Auth использован только для обычного входа; provisioning/reset/смена ролей,
business writes и изменения Storage не выполнялись.
