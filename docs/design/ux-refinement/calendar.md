## Точный текущий серверный состав

- Датированные задачи: `readCalendarTasks` вызывает `listPlatformAdmissionsTaskQueue` с dueFrom/dueTo, без personal/assignee-параметра (`src/lib/v3/calendar-source.ts:103–136`). Репозиторий вызывает `staff_case_task_queue` (`src/lib/platform-admissions-workspace.ts:565–595`). SQL читает `case_tasks` перед keyset/date bounds и LIMIT: организация, active/closed case, handoff и разрешённая задача. Исторический `admin OR current_curator` из migration119:1158–1164 **заменён** migration156:2393–2406 на `staff_can_access(...,'task.manage','task',case_task.id)`. Поэтому нельзя описывать нынешний контракт только старым role guard. Условие `case_task.assignee_membership_id = actor.membership_id` не добавлено.
- Без срока: отдельный `staff_case_task_undated_page`, не клиентское извлечение из полной истории (`calendar-contract.ts:299–332`). SQL отбирает null dueOn/dueAt, доступные handed-off active/closed cases и keyset ДО LIMIT (migration124:110–124), а migration156:2397–2406 также заменяет роль на scoped task.manage. Персонального условия назначения нет. Датированный диапазон сейчас исчерпывается по страницам; недатированные читаются одной ограниченной страницей.
- Прямой target: `?case=…&task=…` читает одну точную задачу через `staff_case_task_target`, не угадывает её по первой странице (`page.tsx:68–80`, `calendar-source.ts:250–263`). SQL проверяет case/task IDs, организацию, case state/handoff и scoped task.manage (migration156:921–925), но не личное назначение. Затем target добавляется в выдачу без personal-проверки (`calendar-source.ts:295–297`). Личный фильтр только в общей очереди оставит этот обход смысла экрана.
- Сейчас это **календарь разрешённых case-задач**, а не задач, назначенных текущему человеку. Он не использует фильтр по создателю тоже. Admin с расширенными grants может получить задачи других исполнителей. Из снимка нельзя установить assignee или creator каждой карточки; этот вывод основан на серверном контракте, а не на именах карточек.
- Самостоятельные `staff_tasks` текущим calendar-source не читаются; `CalendarTask` требует studentCaseId (`calendar/types.ts:113–115`). Между тем глобальное действие создаёт staff-task (`AppShell.tsx:258–263`). В личной проекции по смыслу §10 должны быть оба существующих вида назначенных задач; это прямая зависимость, без создания новой сущности. Переиспользовать персональную staff-логику `p_view='mine'` можно, но у старого `staff_task_list` p_task_id снимает view-предикат (migration140:241–243): для direct target проверка assignee остаётся обязательной.
- Отдельно вызывается `admissions_deadline_page_v1` для диапазона и ближайшего срока (`calendar-contract.ts:399–412,463–473`), и эти данные смешиваются с задачами в сетке (`Calendar.tsx:327–342`). Это реальные admissions deadline projections, а не задачи сотрудника. Их следует исключить из личной календарной выдачи/загрузки, сохранив в деле и клиентском поступлении.

## Личное правило и полномочия

| Случай | В личном календаре |
|---|---|
| Назначено мне другим сотрудником | Да, если задача доступна по существующей authority |
| Создано мной и назначено мне | Да |
| Создано мной для другого человека | Нет |
| Доступно Admin, но назначено другому | Нет |
| Сам по себе университетский/документный/admissions-срок | Нет |
| Реальная задача, назначенная мне, со сроком поступления | Да, как задача |
| Прямая ссылка на не мою задачу | Не добавлять её в личный календарь; возможность открыть в Tasks/деле определяется прежними правами |

Фильтр `assignee = current actor` относится к **назначению экрана**, а не заменяет RLS/grants. Его надо наложить на сервере до лимита/пагинации/счётчика и в targeted read. Не менять общий task.manage, task.assign, student_visible, закрытые дела, правила завершения/отмены и общие detail readers ради календаря. Staff preview не доказывает право на запись и не заменяет проверку реальной Admin/Sales/Admissions сессией.

## Пять наиболее сильных разрывов с планом

1. **Состав не персональный, direct target шире требуемого.** Доказательства выше: отсутствует assignee-предикат в dated/undated/target; самостоятельные staff-задачи не включены. Это первый срез до уплотнения интерфейса. Не делать client filter уже загруженной страницы: он даёт пустые страницы, неверный счётчик и пропускает свои задачи за лимитом.
2. **Не-задачи загружаются и занимают календарь.** `calendar-source.ts:279–302` запускает deadlines/nearest; `Calendar.tsx:206–209` всегда показывает nearest-card при доступе, а `ApplicationDeadline.tsx:59–85` рисует большую карточку даже при null. Оба снимка показывают пустой блок ближайшего дедлайна. §10 требует убрать эти факты с личного экрана, не удалять сами сроки и документы.
3. **Первое дело действительно подставляется сейчас.** `TaskControls.tsx:220` начинает с `selectedCase?.id ?? cases[0]?.id`; `TaskCasePicker.tsx:16` — `selectedCase?.id ?? initialCases[0]?.id`; при поиске исчезнувший выбор заменяется на `next[0]` (`:34–37`). Общий calendar передаёт cases без selectedCase (`Calendar.tsx:193–202`). Это конкретный текущий дефект, не вывод из истории. Начальное значение должно быть пустым; поиск не делает выбор за сотрудника. В контексте конкретного дела допустим explicit selectedCase с видимой подписью (`TaskCasePicker.tsx:42`). На снимках форма закрыта: выбранное поле визуально не проверено.
4. **Два одинаковых действия означают разные пути; форма и детали сдвигают сетку.** Глобальный «Создать задачу» ведёт к staff-форме (`AppShell.tsx:258–263`); календарное одноимённое раскрытие открывает case-форму (`TaskControls.tsx:252–259`). Calendar — вертикальный flex, форма и inspector стоят до расписания (`Calendar.tsx:144,193–215,327`). При открытии они вытесняют сетку. Нужен один ясный запуск с выбором типа или разные подписи «Задача сотруднику» / «Задача по студенту», desktop side panel и mobile экран с focus/возвратом. Сохранить общую возможность создавать задачи.
5. **Недатированные задачи и малая типографика мешают видеть период.** «Без срока» всегда развёрнуто (`Calendar.tsx:287–324`); на mobile вся видимая область занята шапкой, панелями и этим списком — начало сетки только у нижней границы снимка. Название task chip `text-xs`, студент/срок `text-2xs` (`grids.tsx:119–132`) вместо ориентира 14 и 12–13 px. Нужен сворачиваемый «Без срока — N», компактная верхняя панель и читаемый текст. N должен быть серверным числом по личному scope; длину одной страницы нельзя выдавать за полный count. Сетку не сжимать уменьшением шрифта.

## Сохранить работающие свойства

- URL хранит view/date и точный task; старые deep links сохраняют значение там, где задача входит в личный scope. Отдельная target read позволяет открыть собственную задачу за пределами первой undated-страницы. После закрытия возвращать прежний период, страницу undated и место/focus; сейчас selectTask строит только view/date/case/task (`Calendar.tsx:99–106`), поэтому исходный undated cursor нужно явно переносить при новой panel-навигации.
- Организационный часовой пояс **Asia/Bishkek**, не часовой пояс браузера и не Dubai. Сохранить разделение dueOn (весь день), dueAt (точный момент) и null (без срока), сортировку/keyset по каноническому сроку и ID; границы месяца включают соседние дни сетки (`page.tsx:47–53`). `projectPlatformTaskDeadline` отклоняет две одновременно заданные даты (`platform-task-deadline.ts:48–56`). Не делать midnight из неизвестного срока и не назначать длительность задаче: сетка сознательно не выдумывает интервалы (`grids.tsx:24–35`).
- Все статусы, даты, assignee, version и история остаются на исходных task rows; не превращать личный фильтр в удаление/архивацию чужих задач. Существующие completed/cancelled не терять произвольным новым active-only условием.
- Server commands сохраняют expectedVersion, requestId, актуальные recipient eligibility, task.assign для назначения и отдельный доступ к делу. Перенос формы в панель не означает ослабление этих проверок. Распознавать unavailable/stale/forbidden; не отображать read failure как успешное «задач нет» (сейчас `calendar-contract.ts:91–98` намеренно не подавляет разрешённую ошибку).
- Выбор дела определяет реальных доступных исполнителей; ответы поиска/assignees устаревшего выбора игнорируются (`TaskCasePicker.tsx:21–38`, `TaskControls.tsx:224–233`). Текущий общий TaskComposerDialog начинает свой caseId пустым (`:104–105`), поэтому не приписывать ему тот же initial-state дефект без учёта вложенного picker. Изменения общего picker/composer согласовать с владельцем задач.

Не проверены визуально раскрытая форма, inspector, фокус/клавиатура, task completion, другие виды, dark theme, граница суток и полная горизонтальная прокрутка. По коду week/month имеют внутреннюю min-width и overflow-контейнер (`grids.tsx:297,368–384,425–430`); снимок сам по себе не доказывает сломанный reflow или потерю задач. Изображение списка не доказывает assignee/creator: для этого нужен разрешённый readback.

## Приёмка по реальному пути, без выдуманных задач

- На существующих разрешённых записях получить защищённый readback ID/assignee/creator/type/dueOn/dueAt/status/version и сверить UI → current Auth → RPC. В отчёт выводить агрегированный результат без имён/текста. Покрыть свою задачу, самому себе, созданную собой другому, чужую доступную Admin; также собственную staff-задачу. Если в реальных разрешённых данных какого-то случая нет, честно оставить этот case непроверенным, не создавать фиктивную задачу ради картинки.
- Пройти существующие dated/undated страницы и direct link на свою запись за первой страницей; собственные задачи не теряются после чужих, чужая Admin-задача не внедряется через target. Та же чужая задача остаётся доступной через Tasks/дело по прежним grants. Проверить отозванное/чужое org право без раскрытия task data. Для эффекта pre-limit нужна реальная страница подходящего размера; один малый screenshot этого не доказывает.
- На существующем деле с реальным university/document deadline подтвердить: deadline остаётся в деле/«Моём поступлении», личный календарь его не получает; реальная назначенная задача с таким сроком сохраняется. Не создавать task автоматически из deadline.
- В generic форме визуально проверить пустой студент и невозможность submit до осознанного выбора; поиск и смена запроса не выбирают первого. При открытии из конкретного дела — правильный видимый контекст и eligibility. Для этой проверки submit не нужен. Создание/смена исполнителя/завершение проверяются только на реальном намерении владельца и с отдельной властью на запись; если её нет, gate остаётся открытым.
- Существующие all-day/timed/undated задачи сверить по Asia/Bishkek, включая границу суток/месяца, без изменения исходного срока. Проверить done/cancelled и историю после применения personal filter. Неизвестный/неизменённый timestamp не нормализовать заново на сохранении.
- Один batched desktop + mobile, light/dark проход: период виден рано, panel не уводит расписание, клавиатура/focus/Escape/возврат работают, N правдив, название читается. Узкие тесты канонического deadline, pagination/scope/target и исправленного picker дополняют real-path evidence, не заменяют её. Не требуется полный тяжёлый unrelated suite.
