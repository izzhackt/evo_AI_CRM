## Цель и порядок

### Reuse-first delivery

Уточнение владельца от 2026-09-14: перенести готовое из EVO Docs, не создавать
те же пять функций заново. Источник — `evo-student-document-system@6e7cf741`.
Word/PDF-движки уже портированы; сохранить их, исходные шаблоны/настройки,
правила заполнения и состав ZIP. PDF UI должен сохранить создание, перемещение
и изменение размера областей; адаптировать эти жесты из `PdfFormEditor.tsx`
в существующий редактор Platform. Не создавать параллельный экран или сервис.

Оставшаяся разработка — адаптеры к общим делам/каталогу, правам сотрудников,
Postgres и private Storage; подключение сохранения/истории и существующей
сборки ZIP. Gemini использует уже перенесённый extractor и постоянные задания.
Приёмку проводить на существующих разрешённых исходниках, без вымышленных
значений и подмены результата. Сохранённые доказательства переиспользовать;
повторять только затронутые проверки. Новая инфраструктура/форматы и расширение
тестовой платформы не входят в перенос без конкретно доказанной необходимости.

Исходный ZIP допускает250MiB выбранных оригиналов/частей; сгенерированная анкета
добавляется сверху, скачивание ограничено260MiB. Новый черновой контракт65MiB не доказывает
сохранение этой возможности. Перед подключением пакетов сверить реальную
ёмкость Storage и устранить несоответствие либо явно вынести ограничение
владельцу; не уменьшать возможности молча. Не менять тариф или managed-настройки
без нужной авторизации. Перенос данных/реальная приёмка остаются обязательными
перед выключением старого приложения.

Один вход, сотрудник, студент, дело и набор прав. В документах дела:
**открыть оригинал → извлечь поля → проверить → сохранить подтверждённое →
сформировать анкету/форму/пакет**. Не iframe отдельного приложения, не второй
Supabase, не синхронизация двух баз. Обычные загрузка/ClamAV/review уже есть в EVO.

## Перенос и точное выключение

До миграции выбранных реальных записей нужен mapping source-student → canonical
case, не совпадение имени. Не читать/отправлять паспорта и другие персональные
документы для технической проверки без согласованного конкретного случая.
Пустой VPS не доказывает, что можно удалить непустые локальные данные.

После D5/D6 кандидаты на retirement, с обязательной повторной сверкой:

- Compose `evo-student-docs`, container `evo-student-docs-app`, его private network
  `evo_student_docs_private` после проверки отсутствия других потребителей.
- Image `evo-student-docs:eadbef1` и standalone runtime `/opt/evo-student-docs/source`;
  старые Compose/Caddy snippets под `/opt/evo-student-docs`, отдельно от активного edge.
- Standalone Basic Auth secret после остановки; Gemini secret только после
  подтверждённого переноса. Не отзывать потенциально общий provider key.

**Не удалять в составе выключения:** `/opt/evo-student-docs/data`, `backups`, local
`runtime`, `.env`, оригиналы/шаблоны/историю, GitHub history; shared `evo_public_web`,
`evo-edge-caddy`, CRM/Inbox/WAHA/ClamAV и их volumes. Исходный репозиторий можно
архивировать после cutover, не стирать. Для удаления непустых данных нужен отдельный
утверждённый перечень. Не добавлять новую обязательную систему backup вопреки
предыдущему решению владельца; сохранять исходные данные до сверки.

## Доказательства и недостающие входы

Каждый срез: реальная сборка/серверный путь, конкретное разрешение/запрет,
независимое ревью, обычный PR/release. UI/healthy/ключ в env не доказывают Gemini,
реальную анкету или перенос. Пока нет выбранного разрешённого файла/case — делать
независимый код и schema, явно оставляя файловую/AI/миграционную приёмку открытой.
Рассылки сотрудникам, документы провайдеру и очищение данных не запускаются скрыто.

Официальные основания: [Gemini Files](https://ai.google.dev/gemini-api/docs/files),
[модели](https://ai.google.dev/gemini-api/docs/models),
[Supabase Storage access](https://supabase.com/docs/guides/storage/security/access-control).
Проверены 2026-09-13. Автоистечение Google files через 48 часов не доказывает
немедленное удаление; нужны собственные проверяемые cleanup receipts.
