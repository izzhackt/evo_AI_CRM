# EVO Docs → одна EVO Platform

Дата: 2026-09-13. Владелец разрешил перенос функций и последующее удаление отдельного
приложения. Статус: инвентаризация завершена; интеграция начата, перенос/удаление не выполнены.
Контракт: `docs/EVO_LAUNCH_PLAN.md` → ADR0028 → этот план → `DESIGN.md`.
Параллельный run: [сотрудники и роли](employee-roles-accounts-run-plan.md).

## Цель и порядок

Один вход, сотрудник, студент, дело и набор прав. В документах дела:
**открыть оригинал → извлечь поля → проверить → сохранить подтверждённое →
сформировать анкету/форму/пакет**. Не iframe отдельного приложения, не второй
Supabase, не синхронизация двух баз. Обычные загрузка/ClamAV/review уже есть в EVO.

| Этап | Что переносим | Готово, когда |
|---|---|---|
| D0. Контракт | ADR0028 отменяет прежнее разделение; единые case/version IDs, права, форматы и инвентаризация данных. | Нет активного плана строить второй Auth/SQLite/Express-продукт. |
| D1. Просмотр оригинала | PDF/фото рядом с текущей проверкой документа, включая выбранную историческую версию. | Реальный разрешённый файл виден; чужой/небезопасный файл недоступен; без новой загрузки и AI. |
| D2. Поля и анкета | Предложения полей, источник/версия/страница, исправление и подтверждение человеком; оригинальный EVO Student Profile DOCX. | Подтверждённые данные реального дела дают корректный файл; пропуски не выдумываются, черновик не выдается за финальную анкету. |
| D3. Распознавание | Явная обработка через Gemini, постоянные задания/статусы/leases, версия модели, проверяемая очистка provider files. | Реальный разрешённый документ → ответ провайдера → проверка человеком; сбой/restart не теряет задание и не дублирует платный вызов. |
| D4. Университетские формы и пакеты | Версионные DOCX/PDF-шаблоны и mappings, состав пакета, вложения/переводы, ZIP и история экспортов. | Экспорт воспроизводим по подтверждённым версиям/хешам; используется существующий каталог, не второй список вузов. |
| D5. Перенос данных | Один согласованный импорт локальных данных с явным сопоставлением действующим делам и сверкой всех доменов. | Количество, идентичность, байты/хеши, источники, решения и экспорты сверены; повтор не дублирует данные. |
| D6. Проверка и выключение | Реальный сквозной случай внутри Platform, затем точечное удаление отдельного runtime/config и закрытие старого направления работы. | Пользователь работает только в Platform; старое приложение больше не обслуживает запросы; оригиналы/история не потеряны. |

## Реализация без лишних зависимостей

- **Сейчас D1:** приватный preview PDF/JPEG/PNG в текущем staff Documents workspace.
  Точный versionId, те же разрешения и scan gates, no-store, освобождение временного
  клиентского URL при закрытии. Не добавлять вторую загрузку/базу, AI или публичный URL.
  Формат вне текущего поддерживаемого списка честно не открывается.
- D2–D4 сначала фиксируют schema/DTO, затем параллельные worker/service и UI.
  Root выделяет migration numbers после сверки staff-ветки; не занимать один номер.
  Динамические права staff и новые документные возможности должны использовать
  одну проверку прав; временные разрешения по имени должности не вводить.
- UI следует `DESIGN.md`: оригинал и компактная панель проверки на desktop,
  один слой на mobile; статус задания и ясное следующее действие. Не выводить
  одновременно все поля, шаблоны, историю и технические confidence-таблицы.
- Модель Gemini задаётся серверной конфигурацией после актуальной проверки. Не
  переносить hardcoded model и молчаливые ошибки удаления. Provider upload/cleanup,
  timeout и неизвестный исход сохраняются; автоматический повтор не разрешён.
- DOCX/video исходного приложения шире нынешней границы Platform PDF/JPG/PNG.
  Расширение MIME/размеров/сканирования — отдельный проверяемый шаг, не обход защиты.
- Девять готовых PDF-форм не означают поддержку всех вузов. Геометрия/шрифты/хеши,
  актуальность бланка и неподтверждённая приемлемость USTC DOC→PDF остаются явными.
  Экспорт не отправляет заявку, не подписывает документ и не даёт согласие за клиента.

### Обязательная совместимость D2–D4

Сверено с задачей **Find EVO document platform** по текущему исходному коду:

- D2: подтверждённое человеком пустое значение остаётся пустым после повторного
  распознавания. Конфликт не снимается автоматически; сохранение устаревшей версии
  вторым куратором возвращает конфликт, не затирает первое решение.
- D4: новая версия оригинала аннулирует текущие подтверждения оригинала и связанных
  переводов/вложений, даже при одинаковых байтах. Проверки привязаны к versionId,
  SHA, parentVersionId и правилам пакета; прежние экспорты остаются неизменными.
- D4: mapping полей подтверждается отдельно. Экспорт фиксирует версии шаблона,
  полей и обработки; изменение данных во время генерации запрещает публикацию
  устаревшего результата/истории. Итоговая проверка Storage и запись готовности
  должны согласованно завершаться, с восстановлением после сбоя.
- D4: перед обработкой шаблонов запрещены активные/интерактивные, подписанные и
  зашифрованные PDF, macros/OLE/ActiveX в DOCX; действуют ограничения распаковки.
  Конвертированный файл получает новый хеш и повторное подтверждение mapping.
  MIME и антивирус сами по себе не заменяют эти проверки.

Это критерии следующих срезов, не заявление о готовности нынешнего D1.

## Перенос и точное выключение

До миграции выбранных реальных записей нужен mapping source-student → canonical
case, не совпадение имени. Не читать/отправлять паспорта и другие персональные
документы для технической проверки без согласованного конкретного случая.
Пустой VPS не доказывает, что можно удалить непустые локальные данные.

После D5/D6 кандидаты на retirement, с обязательной повторной сверкой:

- Compose `evo-student-docs`, container `evo-student-docs-app`, его private network
  `evo_student_docs_private` после проверки отсутствия других потребителей.
- Image `evo-student-docs:eadbef1` и standalone runtime `/opt/evo-student-docs/source`;
  старые Compose/Caddy snippets под `/opt/evo-student-docs`, отдельно от активного edge.
- Standalone Basic Auth secret после остановки; Gemini secret только после
  подтверждённого переноса. Не отзывать потенциально общий provider key.

**Не удалять в составе выключения:** `/opt/evo-student-docs/data`, `backups`, local
`runtime`, `.env`, оригиналы/шаблоны/историю, GitHub history; shared `evo_public_web`,
`evo-edge-caddy`, CRM/Inbox/WAHA/ClamAV и их volumes. Исходный репозиторий можно
архивировать после cutover, не стирать. Для удаления непустых данных нужен отдельный
утверждённый перечень. Не добавлять новую обязательную систему backup вопреки
предыдущему решению владельца; сохранять исходные данные до сверки.

## Доказательства и недостающие входы

Каждый срез: реальная сборка/серверный путь, конкретное разрешение/запрет,
независимое ревью, обычный PR/release. UI/healthy/ключ в env не доказывают Gemini,
реальную анкету или перенос. Пока нет выбранного разрешённого файла/case — делать
независимый код и schema, явно оставляя файловую/AI/миграционную приёмку открытой.
Рассылки сотрудникам, документы провайдеру и очищение данных не запускаются скрыто.

Официальные основания: [Gemini Files](https://ai.google.dev/gemini-api/docs/files),
[модели](https://ai.google.dev/gemini-api/docs/models),
[Supabase Storage access](https://supabase.com/docs/guides/storage/security/access-control).
Проверены 2026-09-13. Автоистечение Google files через 48 часов не доказывает
немедленное удаление; нужны собственные проверяемые cleanup receipts.
