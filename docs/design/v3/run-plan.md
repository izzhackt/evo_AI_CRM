### B · Прод живой — завершить выкат Codex

3. Ручной полный прогон «EVO platform CI» на замороженном main → взвести
   `EVO_PRODUCTION_RELEASE_ARMED=true` → выкат → смок → приёмка.
4. Проверить логин и здоровье снаружи; записать команду отката.

### C · Честные числа и криты реестра

1. Дашборд операций: счётчики считаются по первой странице в 50 строк и
   показываются как тоталы — считать настоящие тоталы в SQL; ссылки чисел —
   в отфильтрованные экраны (`searchParams`).
2. Календарь: убрать `throw` при >100 задач (единственное место, где экран
   падает, а не деградирует) — страницы/«ещё N».
3. Поиск: воронка и входящие (RPC с `p_query` уже есть), фильтры
   мои/просроченные/стадия.
4. Входящие: «ждёт ответа с …» и маркер «без ответа» в строке очереди.
5. Виза: убрать нумерацию 1–6, вынести из вкладки «История».
6. Журнал настроек: имя записи + ссылка на профиль, страницы дальше 60 строк.
7. Доска на объёме: прокрутка колонок, липкие заголовки, возраст лида в
   стадии, свёртка «Переданы».
8. Кросс-ссылки: карточка воронки → диалог, профиль → диалог; задачи дела на
   профиле; история переходов с причинами.
9. Русский и правила мира: английские подписи (Student 360, Director/Admin,
   evidence/Delivered, CARD_TITLE) → `wording.ts`; сырой ключ роли на
   access-denied; подкрашенные плашки «Требует внимания» → пилюли/рёбра;
   альфа-границы → сплошные токены.

### D · Пять потребностей заказчика (схема 117+)

1. **Заметки к человеку**: таблица `platform.case_notes` (лид и дело),

2. **Вложения WhatsApp**: показать медиа в переписке (read-модель уже отдаёт),

3. **Шаблоны ответов**: тип «шаблон» в базе знаний + пикер в поле ответа.
4. **Страна и ступень у заявки**: расширить RPC 112, поля в формах, перевод

5. **Сроки набора**: дедлайны заявок в календарь, «до дедлайна N дней» на
   главной приёмной.

### E · Портал студента

Серверная машинерия жива (`student_portal_*` RPC, миграции 042–110), снесён
только старый read-only фронт. Строим заново, дружелюбно, по-русски:

1. Auth/схема: провижининг студента (auth user + membership `student` +
   привязка к кейсу + активация), публикация студенческого role bundle
   (least privilege), студенческая загрузка документов в свой слот через
   существующий скан-конвейер, студенческий download-guard.
2. Пять экранов: «Моё поступление» (стадия, следующий шаг, куратор),
   «Документы» (чеклист + загрузка + причины возврата), «Заявки и виза»
   (статусы, дедлайны, трек вехи), «Платежи» (что и когда платить),
   «Уведомления» (+прочитано). Отдельная ветка авторизации: студент никогда
   не резолвится в staff-актора.
3. Контрактные тесты портала возвращаются (были удалены с фронтом).

Мои решения по умолчанию (проговариваю, можно поправить): вход — приглашение
на почту с установкой пароля; загрузка документов студентом в v1 — да, это
главный смысл портала; язык — русский.
