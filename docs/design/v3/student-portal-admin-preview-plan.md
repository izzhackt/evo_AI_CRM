# Предпросмотр Student Portal для Admin

Задача: [#721](https://github.com/izzhackt/evo_AI_CRM/issues/721).

Дата: 10 сентября 2026. Статус: реализован, проверка и выпуск ещё не завершены.
База: main `722d547c`; принятый production `a52cca37`. Последний проход
Admin/chat/universities завершён, его публикации и миграции не повторять.

## Зачем

Живой Chrome дважды подтвердил: Admin открывает `/portal` и возвращается в
`/v3/main`. Это существующее разделение staff/Student, а не сбой туннеля.
Владелец одобрил отдельную кнопку предпросмотра без смены аккаунта и без доступа
к личным ответам студентов. Обычный Student Portal и его проверка роли остаются.

## Ограниченный контракт

- Отдельный явно подписанный маршрут `/preview/student`, кнопка «Предпросмотр
  кабинета студента» в Admin-навигации, постоянный возврат «Вернуться в CRM».
- Настоящая текущая Admin authority проверяется сервером для каждой страницы,
  до чтения содержимого. Не новая роль, не impersonation, не service-role чтение.
- Повторно используем `PortalShell`, `PortalPage` и существующие представления.
  Вкладки ведут внутри preview; не переносим туда формы записи или Student RPC.
- Поступление, документы, заявки, оплата и уведомления показывают честные пустые
  состояния: никакие чужие либо вымышленные дела/документы/платежи не загружаются.
- Университеты используют существующий живой опубликованный каталог через
  разрешённый Admin read path; не editorial templates и не резервный набор.
- Тесты показывают реальные вопросы текущих закреплённых файлов English36/ORVIS92
  из `supabase/assessment-content`. Это явно подписанный просмотр версии содержания,
  не чтение Student-попыток. Сервер отдаёт только вопросы и открытые инструкции,
  без ключей правильных ответов, grading rules и персональных результатов.
- Выбор вариантов и переходы между вопросами работают только в памяти открытой
  страницы. Нет попытки, автосохранения, отправки, балла, истории либо записи
  результата; обновление очищает выбор и интерфейс сообщает это заранее.
- По возможности вынести существующую разметку вопроса в общий чистый компонент,
  не копировать весь Student runner и не менять реальное сохранение Student.
- Одна база/приложение; без SQL-миграций, аккаунтов, приглашений, новых секретов,
  ослабления Auth и доступа staff к Student-private данным. WAHA/amoCRM не трогаем.

## UX

Спокойный существующий светлый EVO, прежний логотип и красный акцент. Верхняя
небольшая плашка объясняет режим, далее обычная навигация и содержимое портала.
Не создавать декоративный hero, вторую дизайн-систему или фиктивную статистику.
Взаимодействия: заметный выбор ответа, следующий/предыдущий вопрос, возврат в CRM;
видимый фокус, кнопки 44 px и существующее reduced-motion поведение.

## Выполнение и проверка

1. Root — план, решение, интеграция, независимый exact-head review, выпуск.
2. Worker A — Admin-вход/guard/route allowlist, shared shell, страницы и живой каталог.
3. Worker B — вопросник preview, минимальная общая разметка вопроса, безопасное
   выделение открытого содержания из действующих файлов, без persistence.
4. Узкие реальные проверки: типы/lint/build, контракт маршрутов, сериализация
   содержания. Не считать статические проверки либо harness бизнес-приёмкой.
5. В существующий реальный browser gate добавить read-only Admin переходы по
   preview и отказ Sales/Admissions/Student на этом новом маршруте. Не создавать
   новые QA-аккаунты/дела для этого блока; использовать существующие gate identities.
6. Проверенный PR → exact-current-main full CI один раз → guarded production
   release → принятый серверный SHA, health, arm=false, тот же localhost-туннель.
7. Настоящий Admin в Chrome: вход по кнопке, все разделы, live catalogue, выбор
   ответа/назад-вперёд/refresh без сохранения; desktop и узкая ширина. Не заявлять
   настоящую Student-session/попытку/запись результата по preview-доказательству.

Если реальная authority, источник каталога или выпуск недоступны, назвать ошибку;
не подменять их случайными данными или выключенным Auth. При передаче записать
PR/SHA/проверки/ссылку и отдельно оставшиеся настоящие Student-сценарии.
