# E2E-проверки приложения (Maestro)

Потоки лежат в `mobile/.maestro/`, запускаются на iOS-симуляторе и Android-эмуляторе против локального стенда
(`docs/mobile/LOCAL_STACK.md`): настоящие Auth, Postgres, Storage и маршруты портала, только синтетические данные.

| Файл | Что проверяет | Студент | В общем прогоне |
|---|---|---|---|
| `01-sign-in.yaml` | неверный пароль показывает ошибку, верный открывает кабинет (экран «Конфиденциальность», если он показан, проходится) | `assisted` | да |
| `02-home.yaml` | главная: герой дела | `assisted` | да |
| `03-documents-contract.yaml` | «Документы»: скачивание договора, ошибки нет | `assisted`: договор лежит только у него | да |
| `04-inbox-send.yaml` | «Входящие»: сообщение куратору отправляется и появляется в беседе | `assisted`: беседа есть только у него | да |
| `05-universities-favourite.yaml` | «Университеты» открываются на странице страны студента, вуз, «в избранное» и обратно | `assisted`: страна Китай выбрана | да |
| `06-csca-home.yaml` | раздел CSCA открывается | `assisted` | да |
| `07-profile-theme-language.yaml` | профиль: язык RU/KY, тема светлая/тёмная | `assisted` | да |
| `08-sign-out.yaml` | «Выйти» из меню ☰ возвращает экран входа, после перезапуска сессии нет | `assisted` | да |
| `09-apply-invalid-token.yaml` | `evoadmissions://apply?invite=…` с неверным токеном показывает ошибку | входа нет (скрипт всё равно читает студента из файла аккаунтов) | да |
| `10-consent-gate.yaml` | экран «Конфиденциальность» открывается первым; без обеих галочек «Продолжить» не уходит дальше, с обеими ведёт на «Главную»; после перезапуска экран не возвращается | `approved`, который ещё ни разу не входил на этом стенде | **нет, только вручную** (ниже) |
| `11-documents-example.yaml` | «Документы» → «Пример»: лист, крупный просмотр, закрытие; после них меню ☰ показывает «Оплату» и «Профессии» (проверка #1488). Прогнан на iPhone-симуляторе в QA 26.11.2026 (два прогона, оба прошли) | `assisted`: чек-лист есть только у него | да |

Каждый поток начинается с `clearState` (локальные данные и Keychain стёрты). Потоки входят под студентом из `EVO_E2E_ACCOUNT`, по
умолчанию `assisted` (`test.assisted`): на его данных рассчитаны потоки 03, 04, 05 и 11 (договор, беседа, страна Китай, чек-лист;
`docs/mobile/LOCAL_STACK.md`). Поток 09 не входит вовсе; поток 10 входит под `approved` (`test.approved`), см. ниже. Подпотоки: `subflows/`
(вход, раздел через меню ☰, закрытие системного окна «Сохранить пароль?», экран «Конфиденциальность»). Потоки независимы, поэтому порядок
общего прогона не важен: Maestro 2.12 запускает файлы не по номерам (в журнале QA 26.11.2026: 05, 08, 03, 04, 10, 02, 01, 09, 11, 06, 07).

### Поток 10: только вручную

Поток 10 проверяет первый вход студента, который ещё не решал по Политике и ИИ (миграция 356). Такого студента после любого другого
входа нет: потоки 01-08 и 11 входят под `assisted` и сами проходят этот экран (`subflows/pass-consent.yaml`), и дальше он не
показывается. Поэтому поток 10 по замыслу падает на проверке экрана, если студент уже решил. Чтобы полный `npm run e2e:ios` не
заканчивался красным из-за этого, поток вынесен из общего прогона, а сам не ослаблен:

- у потока метка `needs-undecided`, а `mobile/.maestro/config.yaml` исключает её (`excludeTags`): общий прогон берёт остальные десять
  потоков. Одиночный файл метки не фильтруют, поэтому по имени файла поток запускается как обычно. Какие файлы Maestro возьмёт, проверено
  его же планировщиком без устройства (Maestro 2.12.1: с каталогом `.maestro` десять файлов, с `10-consent-gate.yaml` один);
- запуск: на стенде, где студент `approved` ещё ни разу не входил (свежий `npm run mobile:stack:up`):

  ```
  cd mobile
  EVO_E2E_ACCOUNT=approved npm run e2e:ios -- .maestro/10-consent-gate.yaml
  ```

- любой вход под `approved`, на котором экран «Конфиденциальность» пройден (руками или другим потоком), снимает «не решал»: после
  него поток 10 пойдёт красным по замыслу. Вернуть «не решал»: полный сброс стенда (`npm run mobile:stack:down`, затем
  `npm run mobile:stack:up`) либо удалить строки этого студента из `platform_private.student_privacy_consents` и
  `student_ai_consents` на ЛОКАЛЬНОМ стенде.

## Подготовка

1. Стенд: `npm run mobile:stack:up` в корне репозитория (Docker/OrbStack).
2. Maestro: `curl -fsSL "https://get.maestro.mobile.dev" | bash`, затем `export PATH="$PATH:$HOME/.maestro/bin"`.
   Нужна Java 17+ (подойдёт JBR из Android Studio: `JAVA_HOME=/Applications/Android\ Studio.app/Contents/jbr/Contents/Home`).
3. Env приложения: `cp mobile/.env.local-stack mobile/.env` (Metro вшивает значения при сборке, затем `expo start -c`).
   Для Android с `localhost` нужен `adb reverse tcp:46421 tcp:46421 && adb reverse tcp:46430 tcp:46430`
   (и `tcp:<порт Metro>`).
4. Отладочная сборка (http к стенду разрешён только в `__DEV__`): `cd mobile && npx expo run:ios` / `npx expo run:android`
   (или `xcodebuild`/`gradlew assembleDebug`), Metro запущен.
5. Логин и пароль потоки получают из игнорируемого файла `mobile/.local-stack-accounts.json` (его пишет `mobile:stack:up`;
   скопируйте из рабочей копии стенда). Путь можно задать `EVO_E2E_ACCOUNTS`, аккаунт `EVO_E2E_ACCOUNT` (по умолчанию `assisted`).
   Скрипт передаёт их потокам через окружение процесса (`MAESTRO_E2E_LOGIN`, `MAESTRO_E2E_PASSWORD`), в Git их нет.

### Особенности платформ (отладочная сборка)

- **Android.** Сборка читает Metro на `10.0.2.2:8081`: поднимите Metro на своём порту и пробросьте
  `adb reverse tcp:8081 tcp:<порт Metro>` (плюс 46421, 46430). В debug-манифесте есть `ACCESS_LOCAL_NETWORK` (Android 17
  спрашивает его при обращении к Metro); потоки запускают приложение с `permissions: all: allow`. Если на общем AVD остался
  чужой `debug_http_host`, выполните `adb shell pm clear com.evoadmissions.app`. Холодный старт debug-сборки на
  нагруженном Mac занимает до 2 минут, поэтому ожидания входа длинные (120 с).
- **iOS.** Системные окна «Save Password?» и «Open in EVO admissions?» не часть приложения: потоки их закрывают.
  «Сохранить пароль?» приходит на языке системы, поэтому его закрывает `subflows/dismiss-save-password.yaml`: подпись кнопки отказа
  там перечислена на языках iOS (54 локали, строки симулятора 26.5) и Android (en, ru, ky, uk, kk, uz); окна нет - поток идёт дальше.
  Список проверяет `src/__tests__/maestro-flows.test.ts`. «Open in EVO admissions?» поток 09 закрывает только английской
  подписью «Open»: на симуляторе с другим языком системы кнопка не найдётся и поток 09 не пройдёт (пока не исправлено).
- Проверка release-манифеста Android (без `ACCESS_LOCAL_NETWORK`, без cleartext): `npx expo prebuild --platform android`,
  затем `./gradlew :app:processReleaseMainManifest` и просмотр `app/build/intermediates/merged_manifest/release/`.

## Скриншоты для магазинов

`EVO_E2E_OUT=<каталог> npm run e2e:ios -- .maestro/store/screenshots.yaml` (то же для `e2e:android`): Maestro сохраняет PNG
в `<каталог>/<дата>/Скриншоты для магазинов/` (Maestro разрешает `takeScreenshot` только внутри каталога запуска). Готовые файлы
лежат в `docs/mobile/store-screenshots/`.

## Запуск

```
cd mobile
npm run e2e:ios                       # общий прогон (все потоки, кроме 10) на загруженном симуляторе
npm run e2e:android                   # то же на эмуляторе
npm run e2e:ios -- .maestro/05-universities-favourite.yaml   # один поток
EVO_E2E_ACCOUNT=approved npm run e2e:ios -- .maestro/10-consent-gate.yaml   # поток 10: только вручную, см. выше
EVO_E2E_DEVICE=<udid> npm run e2e:ios                        # конкретное устройство
```

`appId` везде `com.evoadmissions.app`. Идентификаторы элементов — `testID` в коде (маска-регулярки вроде `tile-.*`),
поэтому потоки не зависят от языка интерфейса.

## Что не покрыто

Загрузка своего документа (нужен ClamAV, его нет в локальном стенде), регистрация по реальной ссылке (одноразовая),
push (не используется), release-сборка (в ней http к стенду запрещён: проверяется на production после выкладки).

Жесты крупного просмотра «Примера» (щипок, двойное касание, листание движением): потоком Maestro их не проверить. У Maestro нет
щипка, а его `doubleTapOn` на iOS - два отдельных запроса касания, между которыми проходит 0,4-0,65 с (по меткам времени в
`~/.maestro/tests/*/maestro.log`: команда с одним касанием занимает около 0,5 с, с двумя - около 1,1 с). Это дольше окна двойного
касания (300 мс, как у платформы), поэтому страница не приближается и при исправном коде. Проверять двойным щелчком мыши в окне
симулятора или пальцем на телефоне.
