# Локальный стенд для мобильного приложения

Постоянный локальный стенд: настоящие Auth + Postgres + Storage (Supabase CLI, Docker/OrbStack) и настоящие
маршруты Next.js-портала. Только синтетические данные (`@example.test`); продакшн не затрагивается.
Проект Docker называется `evo-mobile-dev`, порты фиксированы.

```
npm run mobile:stack:up       # поднять или переиспользовать; досеять недостающее (идемпотентно)
npm run mobile:stack:status   # адреса, здоровье Auth/REST/портала, логины (без паролей)
npm run mobile:stack:down     # остановить и удалить ТОЛЬКО этот стенд (контейнеры, тома, сеть evo-mobile-dev)
```

Первый `up` скачивает образы и применяет все миграции (несколько минут); повторный занимает секунды.
Состояние (конфиг, лог портала) лежит вне репозитория: `~/.evo-mobile-dev-stack/` (переменная `EVO_MOBILE_STACK_HOME`).
Нужен запущенный Docker (OrbStack); чужие стенды скрипт не трогает.

## Адреса и порты

| Что | iOS-симулятор | Android-эмулятор | Телефон по Wi-Fi |
|---|---|---|---|
| Supabase API (Auth/REST/Storage) | `http://localhost:46421` | `http://10.0.2.2:46421` | `http://<IP Mac>:46421` |
| Портал (Next.js, `next dev`, слушает 0.0.0.0) | `http://localhost:46430` | `http://10.0.2.2:46430` | `http://<IP Mac>:46430` |

Остальное: Studio `:46423`, Mailpit/Inbucket `:46424` (письма регистрации/восстановления), Postgres `:46422`.

## Файлы для приложения (в `mobile/`, в Git не попадают)

- `mobile/.env.local-stack` — iOS-симулятор (`localhost`);
- `mobile/.env.local-stack.android` — Android-эмулятор (`10.0.2.2`);
- `mobile/.env.local-stack.lan` — реальный телефон в той же сети (IP Mac на момент `up`);
- `mobile/.local-stack-accounts.json` — логины, пароли, ссылка регистрации для тестировщиков.

В каждом env-файле три переменные из `mobile/src/config.ts`: `EXPO_PUBLIC_SUPABASE_URL`,
`EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (публичный ключ Supabase CLI), `EXPO_PUBLIC_PORTAL_BASE_URL`.
Если `mobile/.gitignore` приложения не игнорирует эти файлы, добавьте `.env.local-stack*` и `.local-stack-accounts.json`
(шаблон `.env*.local` их не покрывает). Использовать: `cp mobile/.env.local-stack mobile/.env` (iOS) или `cp mobile/.env.local-stack.android mobile/.env`
(Android) и перезапустить Metro с очисткой кеша (`expo start -c`): Metro вшивает значения при сборке.
http разрешён в приложении только в `__DEV__`.

Android без смены хоста: `adb reverse tcp:46421 tcp:46421 && adb reverse tcp:46430 tcp:46430`, тогда подходит
iOS-файл (`localhost`). Это нужно ещё и для скачивания договора/чека: портал отвечает 307 на подписанный URL
Storage вида `http://127.0.0.1:46421/...`, а `127.0.0.1` внутри эмулятора — сам эмулятор. Либо приложение подменяет
хост подписанного URL на свой `EXPO_PUBLIC_SUPABASE_URL`.

## Аккаунты (пароли только в `mobile/.local-stack-accounts.json`)

| Логин | Кто | Что в данных |
|---|---|---|
| `test.approved` | студент, уровень «одобрен» | дело pending, кабинет активирован; документов и чата нет (по правилу уровня); 1 избранный вуз |
| `test.assisted` | студент, уровень «сопровождение» | активное дело, этап `documents`, страна Китай (CN), чек-лист 10 пунктов (1 загружен, 1 отклонён, остальные нужны), договор и чек (PDF в Storage), оплата 400 из 1000 USD, заявка в вуз, виза, чат (5 сообщений, последнее от куратора не прочитано), 2 уведомления, 2 избранных вуза |
| `test.temporary` | студент с временным паролем | вход возвращает `must_set_password: true` (экран «задайте свой пароль») |
| `test.staff@example.test` | куратор (и администратор, как реальные кураторы) | должен получать отказ в мобильном входе (401) |
| `test.admin@example.test`, `test.sales@example.test` | администратор, менеджер продаж | то же, отказ в мобильном входе |

Вход студента: `POST {портал}/api/portal/mobile/session` с `{"login":"test.assisted","password":"…"}` (можно и email
`test.assisted@example.test`) → `access_token`, `refresh_token`. Токен работает против PostgREST:
`POST {supabase}/rest/v1/rpc/student_portal_overview_v2` с заголовками `apikey: <publishable>`,
`Authorization: Bearer <token>`, `Content-Profile: platform`.

Личная ссылка регистрации (не использована) — в `accounts.json` → `registrationInvite` (`/apply?invite=<токен>`).
Поток регистрации: `POST /api/portal/registration` с заголовком `X-EVO-Registration-Flow: email-confirmation-v2`;
письмо подтверждения приходит в Mailpit `:46424`.

## Идемпотентность и сброс

`up` при повторном запуске ничего не дублирует: ищет организацию, пользователей, дела, файлы по стабильным ключам и
досеивает недостающее. Пароли берутся из прошлого запуска и выравниваются в Auth (если тестировщик сменил пароль
через приложение, `up` вернёт записанный). У `test.temporary` флаг временного пароля восстанавливается при каждом `up`.
Ссылка регистрации пересоздаётся, если использована или скоро истекает. Полный сброс: `down`, затем `up`.

## Чего нет и почему

- Загруженная версия документа в чек-листе — строка в БД без байтов в Storage: скачать «свой документ» нельзя
  (настоящий путь загрузки требует антивирусной проверки ClamAV, её в локальном стенде нет). Договор и чек
  скачиваются по-настоящему.
- У `test.approved` чек-листа нет: уровень «одобрен» документов не видит (граница 192).
- Каталог вузов — три синтетических вуза (Test University Alpha/Beta/Gamma), без стоимости и городов-справочника.
- Не засеяны: тесты (assessments), уведомления по просроченному сроку, вторая оплата, консультационные запросы, профиль-анкета.
- Куратор сделан администратором системы: роли персонала (`staff_role_assignments`) создаются админ-командами,
  а без них у «чистого» curator нет прав писать в чат дела.
