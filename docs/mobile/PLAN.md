# План: мобильное приложение студента на Expo (iPhone и Android)

Решение: ADR 0038 (2026-11-09). Справочники лежат в `docs/mobile/reference/`:

- `web-portal-spec.md` — экраны, RPC и дизайн кабинета;
- `ios-app-inventory.md` — поведение и тесты iPhone 1.1;
- `expo-research.md` — версии и правила магазинов;
- `open-problems.md` — ошибки, которые надо закрыть.

Владелец 09.11 сформулировал задачу так: «один код для iPhone и Android, новый
дизайн, сразу новые обновления, исправить ошибки, сделать полностью».

## Что берём готовым и что пишем сами

| Берём готовым | Пишем сами (это и есть продукт) |
|---|---|
| Expo SDK 58, Expo Router, EAS Build, Submit и Update | экраны кабинета по дизайну #1412 |
| `@supabase/supabase-js`, схема LargeSecureStore | клиентский слой RPC с `p_request_id` и замороженными повторами |
| `expo-secure-store`, `expo-document-picker`, `expo-image-picker`, `expo-file-system`, `expo-localization`, `expo-image` | движок CSCA (таймер сервера, пакетные сохранения, строгие декодеры), перенос из Swift |
| `lucide-react-native` + `react-native-svg` (те же иконки, что в вебе) | разбор путей и обзора CSCA по файлам сверки |
| карта: MapLibre React Native (те же открытые тайлы, что в вебе, без ключа Google); если не дружит с SDK 58, то `expo-maps` | генератор токенов из `portal.css`, страж общих импортов |
| строки, контент и чистые правила — из `src/` веба через Metro `watchFolders` | узкие серверные маршруты (раздел S) |
| Jest (`jest-expo`) и `@testing-library/react-native`, Maestro для E2E на iPhone и Android | — |

## Раздел S — сервер (веб-репозиторий, обычный выпуск)

Каждый пункт идёт отдельным PR с независимым ревью и выходит обычным
выпуском.

| № | Что | Закрывает |
|---|---|---|
| S1 | `POST /api/portal/registration`: новая версия потока `X-EVO-Registration-Flow: email-confirmation-v2` — аккаунт только по личной ссылке (поле `invite` обязательно, проверка и погашение ссылки) и с согласиями текущей версии (2026-11-07 + ИИ). Версия `v1` выводится из обращения: отвечает прежним статусом «поток не поддерживается» (426), аккаунт не создаётся. Контракт не меняется задним числом, он версионируется. Сборка SwiftUI iPhone 1.1 (не опубликована, заморожена) после этого регистрироваться не сможет — принято | SEC-1, расхождение согласий |
| S2 | `POST /api/portal/password-recovery` `{email}`: та же логика, что у веб-действия `/auth/forgot-password` (миграция 314, проверка членства сотрудника, нейтральный ответ, фиксированные 1500 мс, ограничение частоты); без проверки `Origin` | #1287 (путь приложения) |
| S3 | `POST /api/portal/mobile/session` `{login, password}`: вход по email или «имя.фамилия» на сервере, отказ сотрудникам как в вебе, ответ — токены сессии Supabase; ограничение частоты | M-1 |
| S4 | `POST /api/portal/mobile/password` (Bearer): установка своего пароля после временного и смена пароля из «Профиля»; после смены пароля остальные сессии отзываются | #1360 (пароль), F-1 |
| S5 | Bearer-ветка у `GET /api/portal/case-files/*/download` | договор и чеки в приложении |

Прямой `/auth/v1/recover` с публичным ключом остаётся открытым: это
известный остаток #1287. Закрыть его можно ограничением на шлюзе или хуком
отправки писем. Это отдельное решение владельца, к этому плану оно не
относится.

## Раздел W — тот же порядок в веб-кабинете

Веб и приложение должны оставаться одним продуктом, поэтому решения #1355–#1363
переносятся и в веб. Каждое идёт отдельным небольшим PR, после того как
соответствующий срез приложения закрепит решение:

- #1358, #1361, #1363, #1357 — малые;
- #1355, #1356, #1360 — средние;
- #1359 — после текста владельца;
- #1362 — вместе с M7.

Устаревший `tests/e2e/student-portal.spec.ts` (F-3) обновляется вместе с
#1355.

## Проверки

- **Каждый срез:**
  - `npx tsc --noEmit`, `npx expo lint`, Jest в `mobile/`;
  - ручной проход изменённого экрана на симуляторе iPhone 17 Pro и на
    эмуляторе Android на локальном синтетическом стенде.
- **Без записи в production.** Production-сессия студента нужна только для
  итоговой проверки M8 и только с разрешения владельца.
- **Серверные S1–S5:** собственные тесты маршрутов и проверка
  `scripts/release/evo-production-browser-smoke.mjs`, если затронут вход.
- **CI:** проверки `mobile/` встраиваются в существующий workflow «Fast
  checks» и включаются только при изменении `mobile/` или общих модулей.
  Требуемые проверки ветки main не меняются.

## Что нужно от владельца

1. Пройти первый запуск Android Studio (лицензии Google) — нужно для эмулятора.
2. Перед первой облачной сборкой: `npx eas-cli login` в терминале
   (аккаунт `izzhackts-team`).
3. Team ID Apple (developer.apple.com → Membership details).
4. Google Play Console (25 $, личный или на компанию).
5. Текст «как платить» для «Оплаты» (#1359).
6. Разрешение на удаление `ios/` после замены в App Store.
