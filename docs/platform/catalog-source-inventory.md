# Инвентаризация источников каталога учебных заведений

Назначение: определить, что в утверждённой внутренней базе знаний может стать
записью каталога учебных заведений и программ, а что не может. Документ отвечает
на вопрос «сколько и чего у нас есть» до проектирования схемы, чтобы схема
опиралась на реальные данные, а не на предположение.

- Дата: 20 августа 2026 года
- Инструмент: `scripts/knowledge_ingestion/catalog_inventory.py`
- Тесты: `tests/knowledge_ingestion/test_catalog_inventory.py`
- Источник: `Внутренняя база знаний ЭВО/Утверждено для внутреннего ИИ/Университеты`
- Прочитано существующим безопасным читателем хранилища из
  `scripts/knowledge_ingestion/build_platform_bundle.py`: проверка маркера,
  запрет символических ссылок, запрет сырого архива и секретов, PII-фильтр

Инструмент ничего не импортирует, не создаёт записей каталога и не обращается к
сети. Классификация выполняется прозрачными правилами по заголовку, а при
отсутствии заведения в заголовке — по тексту документа, и результат честно
помечает, откуда взято определение.

**Область измерения.** Документ описывает только утверждённое внутреннее
хранилище. `Сырой архив ЭВО` намеренно не читается: читатель хранилища
исключает его через `FORBIDDEN_PARTS`, потому что по `AGENTS.md` сырые выгрузки
не публикуются в базу ИИ напрямую. Любой вывод ниже относится к хранилищу, а не
ко всему архиву знаний EVO. Состояние сырого архива ведётся отдельно, в
`Внутренняя база знаний ЭВО/Панель управления/Контроль обработки источников`.

## Смена источника

ТЗ в требовании FR-107 фиксирует, что импорт каталога заблокирован из-за
недоступности Notion. Владелец сообщил 2026-08-20, что Notion больше не
актуален и источником становится утверждённая база знаний EVO. Требование
FR-107 подлежит переписыванию отдельным plan-amendment PR; настоящий документ
готовит для него фактическую основу.

Существующий перечень допустимых источников
`platform.workflow_source_kind` содержит `repository_contract`,
`google_document`, `google_spreadsheet`, `google_drive_file` и
`notion_database`. Значения для базы знаний в нём нет, поэтому импорт из
хранилища требует отдельной миграции.

## Четыре факта, которые меняют проект схемы

**1. База знаний сильно смещена в сторону INTI.** 90 из 104 программ — INTI.
По пяти заведениям из девяти программ нет вовсе, только справочные материалы.
Схема должна допускать заведение без единой программы, а не считать это ошибкой
импорта.

**2. Четыре из пяти «рабочих таблиц» в хранилище — это пересказы, а не данные.**
Проверка табличных строк даёт такой результат:

| Документ в хранилище | Строк данных |
| --- | --- |
| Рабочая таблица программ Китая — набор 2026 | **1512** |
| Рабочая таблица EVO по университетам Малайзии | 0 |
| INTI AUP 2026: таблица популярных университетов и расходов | 0 |
| INTI International College Subang: расписание стоимости 2026 | 0 |
| INTI: AUP fee schedule 2026 | 0 |

Малайзийские документы хранилища описывают, что таблица существует, и передают
краткую сводку, но не её содержимое.

**Сами таблицы существуют — в сыром архиве.** Проверено 2026-08-20 чтением
исходных `.xlsx`: одиннадцать малайзийских таблиц Google Диска, все с данными.
Среди них `AUP ПРОГРАММА ОБМЕНА.xlsx` — 211 непустых строк на трёх листах,
`Programmes.xlsx` Taylor's — 126 строк, `университеты_.xlsx` — 62 строки на
четырёх листах. Всего в сыром архиве 81 файл `.xlsx`.

Поэтому корректный вывод не «данных нет», а **«исходные таблицы скачаны и
сохранены, но перенесены в хранилище лишь частично»**: производные заметки есть
у пяти таблиц из одиннадцати, и даже там сохранена сводка, а не содержимое.

Это дефект конвейера обработки, а не отсутствие данных. Его закрытие ведётся
отдельно, с реестром обработанных и необработанных источников и обязательной
сверкой изменяемых цен по официальным источникам университетов.

**3. Китайская таблица — единственный настоящий табличный источник.** 1512
строк с колонками «университет, город, набор, степень, специальности, язык
обучения, стоимость после стипендии, требования». Данные реальные, но грязные:
названия склеены с числами, например `安徽建筑大学400`. Требуется отдельный
разбор с нормализацией и обязательной ручной проверкой; автоматическое
разделение названия и суммы без проверки создаст неверные записи.

**4. Программы трансфера не укладываются в перечень уровней.** Пятнадцать из 21
документа категории `требует_ручной_классификации` — это American Degree
Transfer Program и Australian Degree Transfer Programme INTI. Это не foundation,
не diploma и не bachelor, а маршрут перевода. Перечень уровней программ должен
либо получить отдельное значение для маршрута перевода, либо такие документы
остаются вне каталога по отдельному решению.

## Заполняемость полей: измерение, а не предположение

Извлекатель `scripts/knowledge_ingestion/catalog_extract.py` прошёл все 104
документа категории `программа` и попытался достать поля дословно. Каждое
заполненное значение несёт строку источника, по которой оно получено.

| Поле | Заполнено | Доля |
| --- | --- | --- |
| Заведение | 104 | 100 % |
| Уровень (предложение) | 104 | 100 % |
| Длительность | 47 | 45 % |
| Месяцы наборов | 78 | 75 % |
| Язык обучения | **0** | **0 %** |

Уровень предлагается для всех 104, но ни один не принимается автоматически:
каждый кандидат несёт `programme_level_confirmation` в списке полей для
человека.

### Почему длительность отсутствует у 57 программ

| Причина | Программ |
| --- | --- |
| В источнике несколько разных длительностей | **34** |
| Длительность в источнике отсутствует | 9 |
| Длительность упомянута без явного числа | 8 |
| Неопределённая форма: диапазон, «минимум», «около» | 6 |

Главная причина — не пробел в данных, а свойство самих программ. Треть из них
указывает длительность **по режиму обучения**: «3 года при очном обучении и
4 года при заочном», «2 года full-time или 4 года part-time». Извлекатель
намеренно отказывается выбирать одно из двух значений.

### Что это значит для схемы

Два вывода, оба основаны на измерении, а не на предположении.

**Колонка языка обучения в первой версии не нужна.** Ноль из 104. Источник о
языке преподавания просто не говорит. Заводить поле, которое гарантированно
пустое, значит создавать место для догадки.

**Одна колонка длительности теряет информацию у трети программ.** Очная и
заочная формы — это разные условия обучения, а не разные описания одного. Режим
обучения следует внести в схему как отдельное измерение, чтобы очная и заочная
формы были отдельными записями, а не конкурировали за одну ячейку.

### Три ошибки, пойманные при проверке извлечения

Первая версия извлекателя выдавала неверные значения. Все три случая закреплены
регрессионными тестами:

| Строка источника | Было извлечено | Верно |
| --- | --- | --- |
| `Длительность: минимум 1 год 7 месяцев` | 12 месяцев | нижняя граница, значение не берётся |
| `Длительность: 3 года очно и 4 года заочно` | 36 месяцев | две длительности, выбор невозможен |
| `первая степень на английском языке, IELTS 6` | язык = `en` | требование к прошлому диплому, не язык обучения |

Третий случай показателен: упоминание языка в требованиях к поступлению не
является языком обучения. Теперь язык берётся только из фразы, прямо говорящей
о языке преподавания, и не берётся из строк про IELTS, TOEFL и сертификаты.

## Документы без принимающего заведения

Три документа не имеют единственного принимающего заведения, и это корректно:

- `AUP: списки университетов, примерные расходы и направления трансфера` —
  перечень принимающих университетов США;
- `Брошюры SPD по BA-программам в fashion` — заведение вне текущего перечня;
- `Китай/Рабочая таблица программ Китая — набор 2026` — множество китайских
  университетов в одном документе.

Ни одному из них заведение не присвоено. Пустое значение сохраняется как пустое.

## Правило, которое действует дальше

Кандидат каталога создаётся только со ссылкой на исходный документ и его
SHA-256. Поле, для которого в источнике нет дословного факта, остаётся пустым.
Импорт создаёт только записи в staging; approved-запись появляется исключительно
после явного утверждения администратором, как требует FR-106.

## Что нужно решить владельцу

1. Заводить ли в каталог пять заведений, у которых нет ни одной программы.
2. Как поступить с 15 документами программ трансфера INTI: отдельный уровень
   или вне каталога.
3. Порядок переноса одиннадцати малайзийских таблиц из сырого архива в
   хранилище: цены изменяемы и требуют сверки с официальным источником и
   даты проверки, поэтому переносить их как обычный факт нельзя.
4. Допустимо ли автоматическое разделение склеенных названий и сумм в китайской
   таблице, либо каждая такая строка проходит ручную проверку.

## Воспроизведение

```bash
python3 scripts/knowledge_ingestion/catalog_inventory.py \
  --vault "<путь>/Внутренняя база знаний ЭВО/Утверждено для внутреннего ИИ" \
  --output <папка результата>
```

Результат детерминирован: тот же вход даёт тот же файл и ту же SHA-256.
