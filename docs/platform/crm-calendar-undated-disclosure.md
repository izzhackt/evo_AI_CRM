# Календарь: сворачиваемые задачи без срока

Пункт 16, узкий срез 16a исходного
[плана CRM](../EVO_CRM_UX_AND_ADMISSIONS_PLAN_2026-09-20.md#10-личный-календарь).
База подготовки: main `e8fc98dc1712f30e2b8bbae1cdc2f0d000ddece9`.
ROOT отвечает за этот срез; A продолжает командный чат. Общий QA используется
последовательно: текущий A1020, затем B1018, затем окно ROOT для календаря.

## Задача и сохранения

Сотрудник должен видеть свой период и раскрывать список задач без срока по
необходимости. Сейчас список всегда развёрнут. Серверный личный отбор уже
реализован; его, права, данные, создание и изменение задач этот срез не меняет.

Impeccable: Operate, адаптация существующего EVO. Сохраняются Golos, цвета,
сетка, подписи задач, действия, URL и контекст. Счётчик в заголовке остаётся
серверным `undatedCount`, а не длиной текущей страницы. Активация заголовка
доступна с клавиатуры и имеет область нажатия не меньше 44 px.

## Поведение

- Обычный вход: список свёрнут, заголовок «Без срока — N» виден.
- Прямое открытие существующей задачи без срока или вход на страницу
  продолжения: список раскрыт. Произвольный query не считается найденной задачей.
- Фактическая смена undated cursor через Next/Back раскрывает список. Обычный
  rerender с тем же cursor не отменяет последующее ручное сворачивание.
- Раскрытие не меняет URL, не делает запрос и не отправляет команду. Карточки,
  порядок, сообщения об ограничении, «Показать следующие» и «К началу списка»
  сохраняются. Пустая страница продолжения с сообщением остаётся доступна.
- Заголовок отражает состояние раскрытия. Скрытые карточки не попадают в Tab;
  сворачивание оставляет фокус на заголовке. Новое автоматическое раскрытие
  не перехватывает фокус.
- Ключ родительского Calendar по target или view/day сохраняется. Полная
  сохранность ручного раскрытия после серверного remount не обещается.

Native details/summary предпочтителен, если не усложняет синхронизацию cursor
и выбранной задачи. Допустима локальная кнопка с aria-expanded/aria-controls и
постоянно смонтированным скрываемым содержимым. Общий компонент для всех
disclosure не требуется. Область кода: Calendar.tsx и только необходимая
локальная логика состояния; без TaskControls, AppShell, CSS, SQL или reader.

2. Реализовать согласованное поведение; проверить lint/types и при необходимости
   состояния cursor/target/manual collapse. Не писать тесты для className.
3. Один пакет 1440/390/320: обычный вход, Enter/Space, отсутствие скрытых
   элементов в Tab, доступная собственная задача, счётчик/URL/ссылки,
   отсутствие горизонтального переполнения. Пагинацию проверять на имеющихся
   данных; отсутствующие варианты явно оставить непроверенными.
4. Подтвердить отсутствие бизнес-записей и закрыть только собственные
   Auth/браузер/server ресурсы. Независимое review фактического результата,
   exact-head review и короткие обязательные CI — перед merge.
