## Задача и сохранения

Сотрудник должен видеть свой период и раскрывать список задач без срока по
необходимости. До изменения список был всегда развёрнут. Серверный личный отбор уже
реализован; его, права, данные, создание и изменение задач этот срез не меняет.

Impeccable: Operate, адаптация существующего EVO. Сохраняются Golos, цвета,
сетка, подписи задач, действия, URL и контекст. Счётчик в заголовке остаётся
серверным `undatedCount`, а не длиной текущей страницы. Активация заголовка
доступна с клавиатуры и имеет область нажатия не меньше 44 px.

## Поведение

- Обычный вход: список свёрнут, заголовок «Без срока — N» виден.
- Прямое открытие существующей задачи без срока или вход на страницу
  продолжения: список раскрыт. Произвольный query не считается найденной задачей.
- Фактическая смена undated cursor через Next/Back раскрывает список. Обычный
  rerender с тем же cursor не отменяет последующее ручное сворачивание.
- Раскрытие не меняет URL, не делает запрос и не отправляет команду. Карточки,
  порядок, сообщения об ограничении, «Показать следующие» и «К началу списка»
  сохраняются. Пустая страница продолжения с сообщением остаётся доступна.
- Заголовок отражает состояние раскрытия. Скрытые карточки не попадают в Tab;
  сворачивание оставляет фокус на заголовке. Новое автоматическое раскрытие
  не перехватывает фокус.
- Ключ родительского Calendar по target или view/day сохраняется. Полная
  сохранность ручного раскрытия после серверного remount не обещается.

Native details/summary предпочтителен, если не усложняет синхронизацию cursor
и выбранной задачи. Допустима локальная кнопка с aria-expanded/aria-controls и
постоянно смонтированным скрываемым содержимым. Общий компонент для всех
disclosure не требуется. Область кода: Calendar.tsx и только необходимая
локальная логика состояния; без TaskControls, AppShell, CSS, SQL или reader.

## Текущий экран и реализация — 22 сентября

До кода существующий Admissions прошёл один настоящий локальный путь на
`a117157a`: 1440/320, 12 доступных задач, одинаковый порядок, без действий
над задачами. На 320 px список занимал 907.25 px по высоте и отодвигал сетку
ниже первого экрана. ROOT просмотрел оба PNG. Финальная сверка данных и
закрытие собственной сессии, браузера и процесса приняты; промежуточный
STOP проверки активной AMR-записи сохранён отдельно. Это исходный вид,
а не проверка ещё не реализованного disclosure.

После закрытия среды интегрирован main `2b25a431` (#1020 и #1018); Calendar
и его зависимости не менялись. Реализация использует обычную кнопку внутри
заголовка, `aria-expanded`/`aria-controls` и постоянно смонтированную область
с `hidden`. Это соответствует [WAI disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/).
Состояние учитывает значения cursor и найденный target; условное обновление
во время render сохраняет ручное сворачивание при неизменном контексте и
избегает кадра с устаревшим состоянием, согласно
[рекомендации React](https://react.dev/learn/you-might-not-need-an-effect#adjusting-some-state-when-a-prop-changes).
Официальные источники проверены 22 сентября. Новый UI на `0c1bf75f` прошёл
один реальный Admissions-проход 1440/390/320, клавиатуру, открытие и закрытие
существующей задачи. Независимое actual/closure review `4f7758c9` принято.
Пагинация не представлена данными; сохранение ручного сворачивания при обычном
refresh проверено только по исходникам. После закрытия QA интегрирован main
`d1568d58` с #1024; 13 файлов календаря/reader/shell/package остались побайтно
равны проверенному source. Итоговому head ещё нужны exact-head review, CI и merge.
Полный пункт16, панель/черновики16b и production этим результатом не закрыты.
