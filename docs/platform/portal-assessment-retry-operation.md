## Проблема и результат

В `AssessmentRunner.tsx` после конфликта студент выбирает загрузку сохранённой
попытки и подтверждает замену локальных ответов. Если read-action возвращает
`unavailable` или выбрасывает исключение, кнопка «Повторить сохранение» вызывает
`write()`. Кроме того, после этой ошибки снова доступны ответы и «Сохранить и
выйти», хотя актуальная попытка ещё не загружена. Серверная проверка ревизии
сохраняется; успешная лишняя запись или потеря данных исходниками не доказаны.

После исправления отказ чтения предлагает «Загрузить сохранённую попытку» и
повторяет только `loadLatest()`. Перед каждой загрузкой сохраняется
`window.confirm`: отмена оставляет ответы, ошибку и ожидающий запрос без изменений.
До успешного чтения редактирование и «Сохранить и выйти» остаются закрытыми.
Ошибка сохранения продолжает повторять прежний pending request и снимок ответов,
включая флаг завершения. Ошибка запуска повторяется прежней кнопкой запуска.

## Контракт — Impeccable Operate / harden

- Хранить происхождение ошибки `start | write | reload` вместе с ошибкой в React
  state. Обе ветки отказа каждой операции — returned failure и throw — задают
  его явно. Не читать ref для выбора JSX и не сохранять замыкание с payload.
- Кнопка зависит от операции: reload остаётся чтением, write — прежним `write()`.
  Без подходящей операции нет запасной write-команды. Существующие busy guards
  и disabled сохраняются.
- `reloadRequired = conflict || operation reload` сохраняет блокировку вопросов,
  `select`, `pause` и «Сохранить и выйти». Дополнительный error ref не нужен:
  error остаётся truthy от конфликта до успешного чтения, autosave закрыт, busyRef
  сериализует запросы. Не захватывать новый state в `write useCallback([])`.
- Три RU/KY сообщения описывают загрузку: ошибка, ожидание чтения и запрет выхода
  до загрузки. Остальные тексты сохраняются. Используется существующий `loadSaved`.
  После успешного чтения устаревший `exitNotice` снимается.
- Сохраняются pending request UUID, expected revision, снимок answers, complete
  flag, start request UUID, autosave delay, exit guard, подтверждение сброса,
  обновление после успешного чтения, focus, история URL, серверная оценка,
  локальные ответы при отказе и вся компоновка «Атласа».
- Границы: `AssessmentRunner.tsx`, три пары RU/KY строк, адресная regression и
  существующая проверка disabled, документация. Actions, RPC, Auth/RLS, SQL,
  другие runners, iPhone и дизайн-система не меняются.

## Проверки и пределы

До исправления regression должна показать неверный выбор write после read failure.
После — настоящий локальный JSX выбора действия и callback проверяются с простыми
счётчиками операций. Это чистая проверка маршрутизации, не подмена RPC и не
браузерное прохождение. Проверить returned failure/throw, write retry, конфликт,
disabled и отмену подтверждения. Pending/snapshot, autosave и success path
сверяются по неизменности исходников; единственное изменение success — exitNotice.

Профильные assessment/i18n tests, scoped lint, TypeScript и `git diff --check`
дополняют независимое source review. Полная suite, новый build и общий QA runtime
автоматически не запускаются. После сбоя диска новая установка зависимостей ждёт
окончания окна A239; её прежний оборванный запуск не считается успешным.

Реальная приёмка остаётся отдельным шагом: обычный Student, естественный конфликт
ревизий, отказ чтения при offline, отмена подтверждения и разрешённый повтор read.
Точные действия и допустимые записи фиксируются до окна QA. Никаких fixtures,
прямой смены ревизии, подменённых ответов или выдачи source tests за actual.
До этого PR остаётся draft; весь пункт 24 и production не закрываются.

## Координация и основание

Native logout #1026 отдельно ждёт разблокировки Mac; его QA закрыта и передана
координатором задаче A239. ROOT явно разрешил этот независимый source-блок в
отдельном worktree после checkpoint/source review #1026, чтобы ожидание Mac не
останавливало веб-исправления. QA порядок остаётся A239 → ROOT16b; данная ветка
не запускает UI/DB/Auth и не использует прежние разрешения или baseline.

Независимый source-разбор агента b32_runtime подтвердил потерю операции и второй
путь записи через pause. Применяются общий [UX-план](../EVO_UX_REFINEMENT_PLAN_2026-09-20.md)
и [ведомость B24](../EVO_ITEMS_1_36_STATUS_2026-09-21.md). Функциональное улучшение
ошибки не меняет визуальное направление; классы, токены и RU/KY сохраняются.
