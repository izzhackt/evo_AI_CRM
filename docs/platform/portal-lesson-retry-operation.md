## Дефект и ожидаемый результат

В `LessonRunner.tsx` последовательность «конфликт → загрузить сохранённое →
сбой сети → повторить» выбирает другую команду. `reloadDraft` возвращает ошибку
`unavailable`, но обработчик повтора выбирает start/save/complete по состоянию
экрана; варианта reload в нём нет. При неотвеченном упражнении он может снова
отправить оставшийся ответ или ничего не сделать, если ответ пуст. При другом
состоянии вызывает завершение. Серверные проверки ревизии и идемпотентности
сохранены; успешная лишняя запись или потеря данных этим source-разбором не
установлены.

После изменения кнопка повторяет ту операцию, которой принадлежит ошибка.
Сбой загрузки сохранённого состояния повторяет только существующий read-action.
Вызовы start/save/complete продолжают использовать прежние request IDs,
ожидаемые ревизии и сохранённые снимки ответов.

## Принятый контракт — Impeccable Operate / harden

- Явная локальная идентичность операции `start | answer | complete | reload`.
  Returned failure и throw записывают её вместе с существующим кодом ошибки.
  При новой операции и успехе прежняя принадлежность ошибки сбрасывается.
  Не сохранять замыкание со старым payload, не создавать общий runner framework.
- Ручной retry выбирает только сохранённую операцию; busyRef предотвращает
  повторную команду во время ожидания. Ни автоматического повтора, ни новой
  команды вместо reload нет. Ref допустим только для обработчиков, не для
  вычисления JSX; отображение ошибки остаётся существующим React state.
- Сохраняются «Атлас», Golos, компоновка, кнопки/подписи RU/KY, локальный alert,
  pending/focus, черновик до подтверждённого чтения, exit guard, содержание
  упражнений и серверная оценка. Actions, RPC, Auth/RLS, SQL и другие runners
  не меняются.
- Изменение ограничено `LessonRunner.tsx`, адресной проверкой его маршрутизации
  повторов и этой документацией. Допустима прямая unit-проверка настоящего
  обработчика с простыми счётчиками выбранных операций; это не RPC/service mock
  и не доказательство Student/UI-прохождения. Новый тестовый стек не добавляется.

## Проверки и actual

Поведенческая regression должна отличать reload от save/complete при разных
состояниях экрана, возвращённом отказе и throw, а также проверять блокировку
дубля. Неизменность pendingSave/startRequestId/completeRequestId проверяется
в diff; профильные чистые learning/i18n проверки, scoped lint, TypeScript и
`git diff --check` дополняют независимое source review. Полный набор продукта,
build и локальная QA-среда автоматически не запускаются.

Реальный путь остаётся обязательным и ожидает отдельного admission. Нужен
настоящий draft/revision conflict существующего Student. Если конфликт требуется
получить обычными действиями в двух вкладках, конечная схема и точные допустимые
записи должны быть согласованы до запуска. Никаких fixtures, прямой смены
ревизий, подмен ответов или имитации успешного Student-пути.

Локальная среда сейчас недоступна: координатор сообщил об отсутствии OrbStack
socket. Это инфраструктурный блокер actual, не дефект кода. Docker не запускаем
и не перезапускаем. Новый source PR остаётся draft с явным QA pending.
