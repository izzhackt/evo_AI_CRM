## Один минимальный целостный блок: поиск/страницы manage index + верхнее Add

1. На index поднять существующий `?new=1` Link в `PartShell.action` («Добавить университет»), оставить ссылку опубликованного каталога, проверку черновиков, все templates и batch entry. Batch — вторичное действие в блоке подготовленных сведений. Нативное поисковое поле «Название университета» и явный submit/reset; оно фильтрует две отдельно подписанные группы: pending drafts и подготовленные материалы. Не добавлять третий список published: существующий каталог/карточка уже дают поиск → edit/forms. Пустая очередь без фильтра, отсутствие совпадений и ошибка чтения — разные тексты. Ошибка drafts не объявляется пустой/успехом.
2. **Чтобы поиск был полным, нужен узкий additive read RPC** (имя/номер выделяет координатор позже), а не фильтр первых50 или загрузка всей очереди. Legacy211 list/detail и commands неизменны. Новый reader использует точно тот же scoped actor+org gate и pending predicate, literal case-insensitive substring по `content.name` до LIMIT, порядок `created_at DESC,id ASC`, keyset `(created_at,id)` и51-ю строку для next-page, выдаёт до50. Все `content`/`reviewKind`/version поля сохраняются. Timestamp cursor передавать точно как SQL-string, не округлять через JS Date. Смешанная граница: older created_at либо equal created_at + larger ID. Нет выдуманного total: подпись «Показано …», Next только по extra-row. Private таблицы/grants/RLS не открывать; deny/unavailable не превращать в [].
3. Строгий additive DTO/parser/URL contract: index принимает только `q` (trim, <=200, без controls) и page cursor (валидные timestamp+UUID, привязан к нормализованному q); изменение q сбрасывает cursor. Index не принимает `listContext`. Editor/review URL принимает ровно один существующий mode-key `draft|edit|identify|template|new|batch` с прежней проверкой его значения и один необязательный `listContext`; сырые `q`/`cursor` рядом с mode запрещены. Все неизвестные/повторные ключи, несколько mode, невалидный cursor/context — notFound. Старые single-mode ссылки без context работают как прежде. Фильтрация всех143 templates разрешена в памяти после штатного parse (полный локальный набор, не RPC-page); label не обещает поиск содержания программ. Cursor/count относятся только к pending-группе.
4. Контекст возврата — отдельный закрытый `listContext`, только для UI navigation. Его decoded value — canonical JSON ровно `{"q": string, "cursor": string|null}` (ключи в этом порядке; максимум4096 UTF-8 bytes). Проверить типы, normalize/validate тем же index parser, совпадение cursor/query и точное равенство входной строки `JSON.stringify` проверенного объекта: это также отвергает дубли JSON-ключей/неизвестные поля. Передавать JSON единожды через `URLSearchParams`; принимать обычное уже декодированное query-значение без дополнительного decodeURIComponent. Никаких href/org/nested context. Обе пустые величины канонизируются в отсутствие `listContext`; list URL всегда конструируется локально из проверенных q/cursor на `/v3/universities/manage`, а не берётся из входной строки.
   - Index → draft/template/new/batch переносит текущий canonical q/cursor в `listContext`; page-level Back и «К списку черновиков» восстанавливают именно этот list URL. Прямой вход без context и внешний published card → edit/forms остаются без context, с нынешним canonical Back. Изменение поиска/reset на index сбрасывает cursor; reset очищает q также.
   - Editor saved-draft Link, edit → identify, identify → edit и saved technical-draft Link сохраняют полученный проверенный `listContext` неизменным; route back у draft-review/template/new/batch делает то же. Это optional navigation prop/Link builder в существующих компонентах, не новый form field. Содержимое формы, requestId/baseVersion и exact retry остаются прежними.
   - Mutation FormData, commands и server actions не меняются. ## Concrete additive wire contract

`platform.staff_university_catalog_draft_page(uuid,text,text,uuid)` receives actor organization, normalized query, optional exact UTC timestamp text and optional UUID (both cursor parts or neither). Returns exactly `{organizationId, query, items, nextCursor}`; nextCursor is null or `{createdAt,id}`, matching the last returned item when the 51st row exists. Dates use canonical UTC `YYYY-MM-DDTHH:mm:ss.ffffffZ`; preserve all six fractional digits. URL cursor is canonical JSON `{q,createdAt,id}`; listContext remains canonical JSON `{q,cursor}`. No JS timestamp rounding, totals, writes, fallback readers, or changes to legacy detail commands. The new adapter rejects preview before RPC and validates organization/query, closed DTO, unique sorted IDs, cursor progress and full draft payloads.
