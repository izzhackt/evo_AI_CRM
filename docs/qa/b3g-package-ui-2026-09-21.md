# Комплект документов: web/CRM — локальная проверка 21 сентября 2026

Проверен узкий пользовательский путь существующих Student и сотрудника в
изолированной локальной QA-среде с миграциями 001–232. Записи, загрузка и решения
выполнялись обычными пользовательскими сессиями через интерфейс. Это техническая
проверка на ранее разрешённых QA-данных, не приёмка реальным клиентом.

## Ревизии и результат

Запись комплекта и решений выполнена на `de4bf800f22175443d30381562069480830ab933`.
Найденные ошибки исправлены в `3041f8ea2ec7cc9cfd5844ffb675c8edde433acd`;
для него независимое review одобрило изменение, обязательные CI-проверки прошли.
Проверка отображения после исправлений выполнена на этой же ревизии без повторной
отправки или создания дополнительных документов.

- Без обязательного материала предварительный просмотр называет отсутствующий
  документ и запрещает отправку. Сохранение файла — отдельное действие; до
  отправки интерфейс показывает «Сохранён, ещё не отправлен».
- Student выбрал паспорт версии 2 и сохранённый материал для требования «Фото»,
  исключил необязательный материал и отправил один комплект до проверки файлов
  сотрудником. Сервер вернул успешный receipt; очередь сотрудника показала
  точный состав. Для слота «Фото» повторно использован прежний технический PDF,
  разрешённый действующей MIME-политикой. Пригодность фотографии не проверялась.
- Сотрудник запросил исправление одного материала, пока оба файла не имели
  решения. Затем принял оба файла и весь комплект. Каждое действие выполнено
  один раз, успешные receipts сопоставлены с сохранёнными записями.
- После одобрения Student открыл первоначальное уведомление об исправлениях.
  Оно сохранило прежние причину, затронутый материал и отсутствие решений файлов
  на тот момент. Более позднее одобрение и текущие решения файлов показаны
  отдельно. Полученные серверные свойства страницы совпали с исходным решением.
- Переход «Неподтверждённые действия» открыл экран восстановления с корректным
  пустым состоянием. URL уведомления с неверным UUID был отклонён. Реальная
  потеря ответа при отправке и восстановление незавершённой команды не вызывались.

## Исправления по результатам

1. Разные React-ключи для формы решения и истории устранили повторную форму
   после обновления данных. В итоговом отображении одна форма, новых ошибок
   React/страницы нет.
2. Убрана повторная общая фраза об отсутствующих материалах, когда уже выведен
   их поимённый список; резервное сообщение сохранено.
3. Добавлены только точный маршрут восстановления и ограниченный UUID-маршрут
   уведомления о комплекте. Проверки Student, владельца и дела сохранены.
   Четыре теста маршрутов проверяют допустимые страницы и запрет неверных UUID,
   лишних сегментов, неизвестных страниц и API-доступа через эти пути.

## Отображение и границы доказательства

Просмотрены снимки уведомления Student и комплекта в CRM на ширинах 1440 и
390 px. Полная ширина страницы совпала с шириной viewport; горизонтального
переполнения нет. Это мобильный браузер, не запуск приложения iPhone.
Сохранены действующие EVO, типографика, разграничение сохранения/отправки и
различимые исторические/текущие решения. Impeccable использован для уточнения
существующего интерфейса, без смены дизайна.

Исходные проверки Node/Swift, типов и переводов описаны в
[контракте интерфейса](../platform/b3g-package-ui.md) с их ревизиями и границами.
После трёх исправлений дополнительно прошли узкие проверки маршрутов и lint.
Нативный UI, VoiceOver, потеря сети/ответа, повторное использование чужой прежней
проверки, весь продукт, App Store и production этим прогоном не подтверждаются.

## Закрытие среды

Обе обычные сессии завершены через «Выйти». Две более ранние сессии, потерявшие
управление при сбое инструмента браузера до загрузки, были завершены обычным
refresh/local logout по их точным идентификаторам; это отдельно отражено в
приватном receipt. Все 224 входящие сессии и их refresh tokens сохранены.
Собственные браузерные контексты, Next-процесс и ClamAV остановлены; собственные
порты 33248 и 33132 закрыты, временные файлы авторизации удалены.

Полная сверка 290 таблиц бизнеса и 33 таблиц Auth/Storage прошла: все прежние
бизнес-строки, схема, функции и права неизменны. Добавлены только записи точной
загрузки, отправки, решений и уведомлений; один объект Storage, обычные события
Auth и времена входа двух разрешённых аккаунтов сопоставлены отдельно.
Итоговый proof receipt SHA256:
`1df242a8e1bb890243c2b3ecd72991deba849d842cd7c0ebf3d7da8fab131965`.

Первый вариант приватного проверяющего скрипта не учитывал стандартное событие
проверки файла и ошибочно выводил scan request из корневого upload request.
Скрипт исправлен по существующим 228 и upload handler: finalization request
выводится отдельно, затем из него получается scan request. Исходные результаты
и снимки сохранены; данные не исправлялись для получения PASS.

Приватные снимки и receipts не содержатся в Git; секреты и полный QA-контекст
не публикуются. Передача локальной среды следующему координатору не означает
серверный релиз.
