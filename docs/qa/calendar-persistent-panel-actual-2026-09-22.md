На source `5c421e505b225b102b7835c0efef825bd1fed9b3` обычный существующий

## Что подтверждено

- В 320px (modal) и 1440px (nonmodal) настоящий select был открыт и сфокусирован
  перед Escape. Первый Escape закрыл picker и оставил панель открытой; значение,
  selectedIndex, фокус, черновик и request ID сохранились.
- Удерживаемый повтор Escape оставил панель открытой. Следующий отдельный Escape
  из уже закрытого select закрыл панель и вернул фокус. Escape на заголовке,
  явный Close и повторное открытие также сохранили черновик.
- Обратный resize 320→1440 сохранил фокус и выделение текста. Реальные target/details,
  Back/Forward, смена вида и периода сохранили черновик. Вычисленные размеры текста
  реальной задачи — 14px для названия и 12px для метаданных.
- Один Tab в 320px остался внутри modal; полный цикл Tab и работа screen reader
  не проверялись. Scroll при blur/focus сохранился только при фактической нулевой
  позиции панели и окна; ненулевая позиция этим запуском не подтверждена.

Сохранены два снимка, просмотренные ROOT; сохранений задач не было. Исходная
геометрия, единственная форма, отсутствие overflow и переходы 1440/390/320,
а также wheel 0→66 подтверждены прежним source `0a01800b`. CSS/layout не менялись
в Escape-исправлениях; это переиспользование прежних данных, не новый запуск 390px.

## Сохранённые остановки

1. Исходный `0a01800b`: Escape закрыл панель, но состояние открытого picker
   не было зафиксировано. Пройденная перед STOP геометрия остаётся отдельным evidence.
2. Повторная диагностика `0a01800b` с подтверждённым open/focus показала закрытие
   панели после Escape из открытого native select.
3. Первый fix `3e11eef9` оставил панель открытой, но сам picker не закрылся.
   Desktop и последующие проверки после этого STOP не выполнялись.

Эти результаты не переписаны как PASS. Второй fix `5c421e50` отменяет Escape только
для действительно открытого сфокусированного select, затем использует его реальные
blur/focus; прежний paired-cancel guard удалён. Значение/индекс не присваиваются.
