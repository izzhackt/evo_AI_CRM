## Изменённое поведение

Шесть текущих canonical stages читаются одним read-only RPC по всему доступному
набору открытых лидов. Период создания лида не фильтрует эту воронку. Отдельная
часть считает только доступные пользователю неархивные pipeline-продажи,
связанные с теми же лидами. Student case не подтверждает продажу. Сведения
продажи, суммы и скрытые ID не выдаются. Нет разрешения — отдельное состояние,
а не ноль. Проверка суммы stage counts против lead_count обнаруживает неполный
или изменившийся набор этапов. Режим просмотра другой роли не раскрывает
настоящую область доступа Admin и честно обозначен.

Экран сохраняет EVO и соседние cohort metrics/динамику. Их период размещён в
их собственной секции; пустой период не скрывает текущую воронку. Путь этапов
допускает независимые растущие и убывающие количества и не показывает конверсию.
Проценты используются только как внутренняя ширина полос, не как метрика.

## Реальная приёмка пока не выполнена

SQL210 не применялась ни к shared, ни к managed базе. Новые данные, роли и
учётные записи не создавались; ответы не подменялись. Старый снимок настоящего
экрана `/tmp/evo-ux-audit-evidence/main-desktop.png` использован только для
сохранения визуального языка, а не как доказательство нового интерфейса.

Конкретный blocker: отсутствует authority применить reviewed210 в среде с
разрешёнными существующими реальными данными и выполнить обычное staff чтение
новой RPC/страницы. Для новой local UI также требуется существующая разрешённая
staff-сессия; перенос credentials из пользовательского Chrome не выполнялся.
Без этих условий нельзя подтвердить успешный новый UI/RPC путь. Отсутствие
подходящих реальных записей для отдельной проверки остаётся пробелом, не
исправляется созданием synthetic/demo datasets.

После получения необходимого доступа проверить: stage counts по реальным
разрешённым строкам, независимость от периода, case без продажи, действующую и
архивную связанную продажу, отдельный report scope, genuine empty/denied/error;
одним проходом desktop и320/390 px, keyboard/focus, light/dark, retry и переходы.
Повторная визуальная проверка — только после обнаруженных исправлений, максимум
один подтверждающий проход. Другой tenant/Student/anonymous и stale authority
проверять доступным реальным путём, не конструировать JWT или поддельные сессии.

PR остаётся непрошедшим реальную приёмку до этого прохода. Production release,
managed SQL/Auth/Storage/business writes и публикации отдельно разрешаются.
Прежние local QA receipts PR935/942 не расширяются на CRM-01.
