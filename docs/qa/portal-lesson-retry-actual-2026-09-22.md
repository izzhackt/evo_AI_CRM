Дата: 2026-09-22 (Asia/Dubai); действия выполнены 2026-09-21 UTC.
Проверенный source: `c59e93cfb59cf67824dcec196c57859730c7448e`, PR #1018.
Статус: **узкий actual, строгая сверка и независимое ревью приняты**.

## Реальный сценарий

Существующий Student в изолированной локальной среде, schema 001–238.
Обычный password login выполнен публичным Auth SDK; экран входа этим не проверен.
Две вкладки открыли существующий черновик: одно из восьми упражнений уже отвечено,
revision 2. Нового пользователя, попытки, упражнения или фикстуры не создавали.

1. Вкладка A сохранила один ответ обычной кнопкой: revision стал 3.
2. Вкладка B отправила ответ с прежней revision и получила `conflict`.
   Черновик остался на экране. Непосредственный SQLSTATE браузером не наблюдался.
3. При настоящем browser-offline «Загрузить сохранённое» завершилось
   `net::ERR_INTERNET_DISCONNECTED`: показана существующая ошибка, черновик сохранён.
4. После восстановления сети ручное «Повторить» вызвало ту же команду чтения
   с тем же телом запроса. Получена revision 3, устаревший ответ больше не показан.
   Автоматическая команда не наблюдалась в выделенном интервале 500 мс.

Watcher зафиксировал четыре lesson POST, включая отказавшую offline-загрузку,
и 12 допустимых notification poll. Неизвестных POST, лишних document GET,
нарушений или ожидающих запросов при завершении нет. Две вкладки стали inert,
затем принадлежащий проверке browser context был закрыт.

## Данные и завершение

Сверены все 290 бизнес-таблиц, 33 таблицы Auth/Storage и структура базы.
Изменились только существующая `learning_lesson_attempts` и одна успешная
квитанция `learning_requests`: один принятый ответ, revision 2 → 3.
У stale-запроса квитанции нет; новая или завершённая попытка не появилась.
Остальные бизнес-данные, каталог, функции, ограничения и права совпали.

Из Auth сохранены только ожидаемые следы собственного входа/выхода и metadata
времени входа. Входящие sessions, refresh tokens и AMR не изменены; собственная
сессия отозвана обычным logout с `scope=local`, ответ 204. Собственные файлы Auth
удалены, cookies/context закрыты, дочерний сервер завершился с кодом 0.

Первая проверка закрытия `runner closed` вернула общий `OSError STOP`.
Исходный результат сохранён; errno и причина неизвестны. Последующее пассивное
наблюдение доказало отсутствие процессов, отказ подключения и свободный порт.
ROOT разрешил ровно одну новую проверку только закрытия: она получила `CLOSED`.
Отдельное наблюдение также подтвердило отсутствие process group. UI-сценарий,
login и бизнес-действия не повторялись. Первая ошибка не переименована в PASS.

## Пределы

Это узкая локальная проверка conflict → offline reload → manual retry.
Остальные операции start/complete проверены только адресными source/unit checks;
их сетевые сбои, KY, native, VoiceOver, новая визуальная приёмка и production
этим прогоном не проверены. Положительное сохранение относится к одному уже
существовавшему черновику. Полный пункт 24 и общий E2E остаются открытыми.
