## Изменение и реальный путь

На прежнем runtime #956 фильтр направления с нулём совпадений показывал
«В выбранном периоде записей нет», хотя в годовом отчёте были доступные продажи.
Действия сброса не было. Исправление отделяет пустой фильтр, пустую страницу
и пустой период; сброс сохраняет год/месяц, начало списка сохраняет фильтры.
Ключ относится только к GET-форме фильтров. Business forms и команды не менялись.

Проверено через настоящий браузер и существующие данные, без новых записей:

1. Year2026/monthall + существующий manager + направление без совпадений:
   честное сообщение о фильтрах, ссылка сброса. Сброс удалил manager/direction/
   review/archive/offset, сохранил year/monthall и вернул четыре доступные строки.
2. Browser Back вернул тот же URL и выбранные значения manager/direction,
   вместе с прежним пустым результатом; форма не осталась в состоянии «Все».
3. Month9 + archive + manager + direction + reviewfalse: сброс из пустого
   состояния сохранил September2026, вернул рабочие записи и очистил остальные
   фильтры в URL и видимых контролах. Ссылка сброса после этого исчезла.
4. Monthall + manager + reviewtrue + offset50: результат честно сообщает
   о пустой странице. Enter на «К началу списка» сохранил год/месяц/manager/
   review, изменил offset на0 и вернул три доступные строки.
5. В годовом списке строки показывают собственный DTO reportMonth:
   September/August/October2026. Дата продажи остаётся отдельной строкой;
   в месячном списке повторная подпись reportMonth отсутствует.
6. Manager, отсутствующий в options, остаётся явно выбранным значением,
   не превращается визуально во «Все». На настоящем viewport390×844
   innerWidth/clientWidth/scrollWidth равны390; обе ссылки сброса имеют высоту44px.
   Мобильный сброс с клавиатуры сохранил monthall и очистил manager.
7. Year1900/month1 без дополнительных фильтров: обычное пустое состояние
   периода и предложение изменить период; сброса нет. Неверный year:
   отдельная ошибка проверки; ссылка сброса не маскирует невалидный период.

Desktop и mobile осмотрены в одном раунде. Скриншот инструмента при CDP mobile
был масштабирован некорректно; прямой CDP screenshot подтвердил настоящий
390×844, scale1 и читаемость. Browser-локаторы role/label несколько раз не
разрешились после history; свежий DOM и обычные CSS-локаторы тех же видимых
полей позволили завершить проверки. Это ограничение инструмента не засчитано
как дефект приложения. Временная эмуляция ширины снята.
