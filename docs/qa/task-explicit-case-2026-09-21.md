## Изменение

Общий календарь и поиск дела больше не выбирают первого студента автоматически.
Поиск сохраняет последний явный выбор, если он остался в результатах, иначе
очищает выбор. Последний выбор читается из ref, а не старой async closure.
Смена disabled/active intent и unmount инвалидируют ожидающие результаты.

В общем диалоге режим дела определяется намерением пользователя. Без дела и
проверенного исполнителя кнопка и client submit guard блокируют создание;
оно не превращается в staff command. Сотрудник без staffAllowed остаётся в
case mode при collapse. Закрытый необязательный picker disabled и не блокирует
обычную задачу скрытым required-полем. Server commands, права, request IDs,
черновики, сроки и схема не изменены.

## Реальный путь, без submit

Существующая ordinary Local QA Sales; собственный localhost33222;
существующая локальная БД001–214. Использованы UI и реальные read/search actions.
Новых сущностей/ролей/Auth changes, сообщений, mark-read, provider calls,
создания/сохранения задач или managed/production действий не было.

Baseline до кода: на localhost33221 календарь сам выбрал первое из4дел, поиск
другого существующего дела автоматически заменил выбор. Общий диалог в staff
mode имел закрытый, но required/invalid/validatable case select. Подробности:
`/private/tmp/evo-task-case-choice-baseline.md`.

После изменения:

- Календарь открывается с «Выберите дело», пустым student_case_id, disabled
  исполнителем и кнопкой. Поиск `Local QA sale current` возвращает одну запись,
  но не выбирает её. После явного выбора настоящий read исполнителей возвращает
  Local QA Sales и включает кнопку; её не нажимали.
- Расширение поиска до `Local QA sale` сохраняет текущий выбор. Поиск без
  совпадений очищает дело, показывает пустой результат и блокирует кнопку.
- Общий диалог: закрытый optional picker disabled=true, willValidate=false;
  staff submit не блокируется этим полем (прочие native required остаются).
  Открытый пустой case mode блокирует submit и просит выбрать дело. Результат
  поиска сам не выбирается; явный выбор включает проверку исполнителя.
- Close/reopen optional panel сохраняет явно выбранное дело и его черновик.
  При очистке через пустой результат восстанавливается собственный общий
  черновик, не текст другого дела. Два временных QA-текста затем очищены через
  Ctrl/Meta+A, Backspace; в закреплённом диалоге подтверждено пустое название.
  Первоначальный automation fill("") не очистил контролируемое поле; этот
  результат не засчитан как очистка.
- Настоящий вход: воронка → существующая карточка `Local QA sale current` →
  «+ Задача». Диалог показывает закреплённое имя, не имеет case picker,
  сохраняет разрешённого исполнителя. Отмена без submit. Ранняя попытка открыть
  `/v3/calendar?case=...` без task получила ожидаемый404: календарный deeplink
  требует пару case/task; она не засчитана как pinned proof.
- Desktop и actual390px календаря/общего диалога просмотрены. На390
  clientWidth=scrollWidth=390. Длинная форма прокручивается внутри диалога,
  поля/подсказки читаемы. Временная эмуляция отключена.
