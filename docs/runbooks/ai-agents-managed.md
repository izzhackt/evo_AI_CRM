# ИИ-агенты на Claude Managed Agents: включение и эксплуатация

Раздел CRM «ИИ-агенты» (хаб и страницы агентов) управляет агентами, которые
работают в Claude Managed Agents. Контракт реализации —
`docs/design/ai-agents/contract.md`, решение — ADR 0035. Этот документ —
порядок включения и ежедневные действия. Gemini-«ИИ-агент» (`/v3/ai-agent`) с
этим разделом не связан и не затронут.

Границы:

- Агенты работают **только** с данными EVO CRM. amoCRM вне объёма. Интернета у
  агентов нет: встроенные `web_search` и `web_fetch` выключены (решение владельца
  24.10.2026), `bash` и файловые инструменты остаются (песочнице нужен curl для
  ссылок на файлы документов). После выпуска этой правки у уже синхронизированных
  агентов появится «нужна синхронизация»: нажать «Синхронизировать с Claude» у
  каждого, тогда новая версия агента без веб-инструментов вступит в силу для новых
  сессий.
- Секреты — только в окружении приложения, vault Claude и архиве SOPS
  (`EVO_Знания/Секреты и доступы ЭВО`). В Git, чат и этот файл их не вносить.
- Лимиты расходов владелец задаёт в **Claude Console**. CRM показывает расход по
  запускам, но потолок в Console не заменяет.
- Данные, которые агент прочитал в CRM, остаются в протоколе сессии у Anthropic
  (США), пока сессия не удалена (см. «Удаление сессий»). Managed Agents не входит
  в ZDR. Юридическое оформление (политика конфиденциальности, согласие студента
  на ИИ-ответы) — решение владельца, оно открыто (ADR 0035, риск R6).

## 1. Порядок включения (выполняют владелец и эксплуатация)

Ничего из этого сборка и тесты не делают: живого ключа и живого Claude в
разработке не было.

1. Миграции 317, 318, 319 и 320 применены workflow `EVO schema ledger` (check → apply → check)
   **до** выпуска приложения. Без 317 раздел показывает «готовится», а MCP
   отвечает `503 not_configured`. 318 (мелкие правки по ревью #1290: сбой
   синхронизации не запирает агента, ключ повтора по умолчанию у
   `send_message`, одна среда Claude при одновременных синхронизациях)
   приложение переживает и без неё: прежнее поведение, без аренды среды.
   319 (ключ повтора по умолчанию у `create_task`, `add_note` и `post_digest`;
   аудит чувствительных чтений внутри самого чтения) от приложения не зависит:
   её можно применить до выпуска приложения или после него.
   320 (согласие студента на ИИ-помощников, раздел 10) тоже можно применить до
   приложения, но **закрывает** чтение: пока студент с кабинетом не разрешил,
   агенты не читают его документы и переписку. Выкладывать вместе с карточкой
   согласия в кабинете и на iPhone, иначе разрешить будет негде.
2. В Claude Console: рабочее пространство, **месячный лимит расходов**
   (и уведомления, если нужны), ключ API. Ключ положить в
   `/opt/evo-crm/.env.production` как `EVO_ANTHROPIC_API_KEY` по порядку
   управления секретами EVO и выпустить приложение. Ключ не должен совпадать ни с
   одним другим значением файла (в том числе со старым `ANTHROPIC_API_KEY`):
   проверка env-контракта откажет.
3. Рекомендуется: строка `header_up X-Evo-Mcp-Ip {remote_host}` в живом
   Caddyfile `evo-edge-caddy` (порядок — `docs/runbooks/infrastructure-map.md`,
   раздел 3). Без неё фильтр адресов использует последний элемент
   `X-Forwarded-For`.
4. Проверить MCP до подключения к Claude (раздел 3 ниже).
5. В CRM, по порядку: «ИИ-агенты» → **Директор / Аналитик** → «Настройки» →
   (а) «Синхронизировать с Claude» **при выключенном агенте**: в Claude
   создаются среда, хранилище токена и агент, расписание ещё не ставится;
   (б) включить агента («Включён»): «Поручить» принимает поручения только у
   включённого и синхронизированного агента, поэтому до включения ответ будет
   `agent_disabled`; включение само запускает повторную синхронизацию, и в
   Claude ставится расписание (если повторная синхронизация не прошла, агент
   продолжает работать по настройке из шага «а», а ошибка видна на странице);
   (в) в «Поручить»: «Покажи свои настройки», в хронике видны вызов
   `get_my_settings` и ответ; (г) «Запустить по расписанию сейчас».
6. «Продажи» и кураторы: оставить **Авто выключенным**. Все сообщения клиентам
   и студентам тогда идут черновиками, которые одобряют сотрудники. Включать
   «Авто» осознанно и по одному агенту.
7. WhatsApp: сессия `crm_primary` сейчас отключена. После переподключения сперва
   одобрить один черновик на собственный номер владельца, только потом
   разрешать агентам прямую отправку.
8. События (новая заявка сайта, входящее WhatsApp) и расписание заработают у
   агента, который включён, синхронизирован и у которого включён триггер.
9. Регламент Малайзии (до первого запуска «Куратора Малайзия»; запись в базу,
   нужно отдельное разрешение владельца). Загрузить в базу знаний полный текст
   регламента ОЗО, который владелец утвердил 23.10.2026, одной записью
   «Регламент ОЗО — Малайзия» с аудиторией «внутренняя» (в тексте есть контакты,
   реквизиты и коды агентов; файл остаётся у владельца, в Git его нет). Затем
   вывести из поиска прежние записи о Малайзии: заменить документ новым или
   архивировать страницу, ничего не удаляя. Пока этого не сделано, инструкция
   опирается на свой пересказ регламента и считает все прочие записи о Малайзии
   справкой, которая в споре уступает регламенту (раздел «Основа инструкции» в
   `src/content/ai-agents/curator-my.md`). Название записи должно совпадать с
   названием в инструкции. Проверка: в «Поручить» куратору Малайзии вопрос по
   документам для одного университета; в хронике видно, что `search_knowledge`
   вернул запись «Регламент ОЗО — Малайзия».

## 2. Переменные окружения

Все имена необязательные: пусто — раздел выключен (`deploy/env.production.example`,
проверка `scripts/evo-app-env-contract.mjs`).

| Имя | Что это | По умолчанию |
| --- | --- | --- |
| `EVO_ANTHROPIC_API_KEY` | ключ Claude API (секрет) | пусто = всё выключено |
| `EVO_ANTHROPIC_API_BASE_URL` | только для своего шлюза; https, без пути | `https://api.anthropic.com` |
| `EVO_AI_AGENTS_MCP_URL` | публичный адрес MCP, который вызывает Claude | `https://crm.evoadmissions.com/api/mcp/v1` |
| `EVO_AI_AGENTS_MCP_IP_ALLOWLIST` | сети, которым разрешены MCP и скачивание файлов по одноразовым ссылкам агента, или `off` | `160.79.104.0/21` |
| `EVO_AI_AGENTS_RUN_BUDGET_USD` | потолок расхода одного запуска, 0..100 (0 — без потолка) | `5` |

Потолок запуска агента, заданный в CRM (на странице агента), сильнее значения из
env. Claude сам останавливает сессию на потолке (`budget_reached`) и запись в
CRM получает статус «Остановлен по лимиту».

## 3. Проверка MCP до подключения к Claude

Агент вызывает инструменты CRM по `POST /api/mcp/v1` с токеном агента
(`Authorization: Bearer`). Токен нигде не хранится открытым текстом: в БД лежит
SHA-256, в vault Claude токен записан без права чтения. Поэтому для проверки
**до** синхронизации выпускают временный токен вручную на тестовом агенте и
после проверки обновляют его настоящим (кнопка синхронизации с «Обновить токен»).

```bash
# на машине оператора, значения только в переменных оболочки
TOKEN=$(openssl rand -base64 32 | tr '+/' '-_' | tr -d '=')    # 43 символа
SHA=$(printf %s "$TOKEN" | shasum -a 256 | cut -d' ' -f1)
# SQL под service_role на целевой базе (идентификаторы подставить свои):
#   select platform.ai_agent_runtime_token_set_v1(
#     '<organization_id>', 'director', '<membership_id администратора>', '<SHA>', 'stage');
node scripts/ai-agents-mcp-smoke.mjs https://crm.evoadmissions.com/api/mcp/v1 "$TOKEN"
```

Скрипт проходит `initialize` → `tools/list` (24 инструмента) →
`get_my_settings` и печатает только «ok/ошибка» с кодами HTTP. Что значат отказы:

- `401 invalid_token` — токен неизвестен или просрочен (старый токен после
  обновления действует 10 минут);
- `403 ip_not_allowed` — адрес не из списка. Для проверки с рабочей машины
  добавить её адрес в `EVO_AI_AGENTS_MCP_IP_ALLOWLIST`, а если сети Anthropic
  `160.79.104.0/21` не покрывают Managed Agents — временно `off` (основная
  защита остаётся: токен 256 бит) и сообщить разработчикам;
- `503 not_configured` — нет ключа сервера Supabase или не применена 317;
- `400` с ошибкой JSON-RPC «Unsupported MCP-Protocol-Version» — клиент прислал
  заголовок `MCP-Protocol-Version` с версией не из списка (`2025-11-25`,
  `2025-06-18`, `2025-03-26`, `2024-11-05`). Без заголовка и на `initialize`
  запрос принимается. Проверку `Origin` и версию `2026-07-28` не вводили
  (спецификация: modelcontextprotocol.io/specification/2025-11-25/basic/transports).

Одноразовая ссылка на файл документа (`GET /api/mcp/v1/files/<токен>`) привязана
к запрашивающему тем же списком адресов: с чужого адреса отвечает пустой `404`
(в журнале приложения причина `ip_denied` или `ip_unknown`), и использование
ссылки не тратится (по-прежнему 10 минут и 3 использования). Исходящий адрес
песочницы агента может отличаться от адреса вызовов MCP. Если агент жалуется,
что не может скачать документ, а в журнале `ip_denied`, добавить сеть песочницы
в список или временно `off` (тогда защита — сама ссылка) и сообщить
разработчикам.

## 4. Обновление токена MCP

«ИИ-агенты» → агент → «Настройки» → «Синхронизировать с Claude» с отметкой
«Обновить токен» (только системный администратор). CRM выпускает новый токен,
записывает его в vault Claude, а в БД оставляет SHA-256; прежний токен ещё
10 минут принимается, чтобы идущие сессии не оборвались. Сбой Claude на этом
шаге откатывает токен: старый остаётся рабочим, статус синхронизации «Ошибка».
Токен также обновляется сам при смене `EVO_AI_AGENTS_MCP_URL` (адрес креденшла в
Claude неизменяем: создаётся новый, старый архивируется). После смены адреса
проверить в Console список разрешённых хостов среды `evo-crm-agents`.

### Если синхронизация не прошла

Агент, у которого в Claude уже есть рабочая настройка (создан агент и креденшл
MCP), остаётся доступным для «Поручить» и событий при любом статусе последней
синхронизации (`Ошибка синхронизации` или `не завершена`); на странице агента
видны текст ошибки и кнопка «Повторить синхронизацию». Агент, который ещё ни разу
не дошёл до создания в Claude, запускать нельзя (`agent_not_synced`).
Очистка поля «ID агента в Claude» только отвязывает агента: следующая синхронизация
находит его по `metadata.evo_agent_key` и подключает снова (предупреждение
«подключён, заново не создан»). Чтобы получить нового агента, сначала
архивируйте прежнего в Claude Console, затем очистите поле и синхронизируйте. Две
синхронизации разных агентов одновременно не создают две среды: среду находит
или создаёт одна, вторая ждёт до минуты и берёт записанную первой; не дождалась —
«Среду Claude сейчас создаёт другая синхронизация», повторить через минуту.

## 5. Как выключить

Чем быстрее, тем выше в списке:

1. **«Включён» у агента** — мгновенно. Идущая сессия остановится на ближайшем
   вызове инструмента (MCP отвечает `agent_disabled`). Новые запуски по событиям
   и «Поручить» не стартуют. Чтобы остановилось и расписание в Claude, после
   выключения нажать «Синхронизировать с Claude» (cron-расписание ставится на
   паузу) либо поставить его на паузу в Console.
2. **«Авто» выключить** — агент перестаёт отправлять сам, дальше только
   черновики для одобрения.
3. **Пустой `EVO_ANTHROPIC_API_KEY` и выпуск приложения** — CRM перестаёт
   создавать сессии, принимать события и синхронизировать. Уже созданные
   расписания (deployments) живут в Claude и продолжают срабатывать: их надо
   остановить п. 1 или в Console.
4. **Console**: приостановить расписание, снизить месячный лимит, архивировать
   агента или ключ.

## 6. Ошибки в хронике запуска

| Ошибка сессии | Что делать |
| --- | --- |
| `mcp_authentication_failed_error` («Токен MCP не принят») | синхронизировать с обновлением токена (раздел 4); проверить, что адрес креденшла совпадает с адресом агента |
| `mcp_connection_failed_error` («MCP недоступен») | проверить адрес и доступность (раздел 3), фильтр адресов (`403 ip_not_allowed` в журнале приложения), список хостов среды `evo-crm-agents` в Console |
| запуск `failed` с кодом `start_lost` | приложение не получило id сессии; сессия в Claude могла быть создана (у неё в `metadata` есть `evo_run_id`) — проверить в Console и повторить поручение |
| запуск `failed` с кодом `create_unconfirmed` | Claude не подтвердил создание сессии (обрыв, тайм-аут, 5xx): сессия могла запуститься без записи в CRM. Найти в Console по `metadata.evo_run_id`, остановить лишнюю, затем повторить поручение |
| запуск `failed` с кодом `session_unlinked` | сессия создана, но запуск в CRM не записался (сбой базы); приложение остановило сессию (`user.interrupt`). Повторить поручение (в интерфейсе — новым запросом: прежний уже записан как `failed`); не остановилась — остановить в Console, id сессии в журнале приложения (`op:"run_link"`) |
| запуск по расписанию `failed` с кодом `deployment_paused` | расписание агента стоит на паузе в Claude (вручную или из-за ошибки). Фоновая сверка паузу **не снимает**: устранить причину и нажать «Синхронизировать с Claude» (снимает паузу) |
| запуск `failed` с кодом `terminated` | сессия Claude завершилась ошибкой; смотреть хронику и журнал приложения |
| `Остановлен по лимиту` | сработал потолок запуска; увеличить в настройках агента или начать новое поручение |
| агент не скачивает документ студента (в журнале `ai_agents_mcp_file` причина `ip_denied`) | сеть песочницы не входит в `EVO_AI_AGENTS_MCP_IP_ALLOWLIST`: добавить её или временно `off` (раздел 3) |

Журнал приложения (`docker logs evo-crm-app-1`) — одна JSON-строка на операцию:
`{"event":"ai_agents_runtime","op":"run_start|sync|dispatch|reconcile|…","status":"ok|error",…}`
и `ai_agents_whatsapp_send`. В них только счётчики, коды и ключи агентов: ни
текстов поручений и ответов, ни ключей, ни токенов, ни данных клиентов. У
операций с запуском есть `run_id`, `session_id`, `duration_ms`, а у ошибок
Claude — `request_id` (заголовок `request-id` ответа): его просят в поддержке
Anthropic. Фоновая сверка пишет строку `{"event":"ai_agents_maintenance",…}`
(раздел 8).

## 7. Удаление сессий

Протоколы сессий (поручения, ответы агента, прочитанные строки CRM, документы
студентов, которые агент открывал) хранятся в Anthropic, пока сессия не удалена.
Удалять: Claude Console → Managed Agents → Sessions. Удаление сессии убирает её
события и песочницу. Записи запусков в CRM (статус, расход, сводка, действия
агента, черновики) остаются в БД.

Решение владельца 24.10.2026: протоколы сессий у Anthropic хранятся
**бессрочно**, автоматического удаления сессий нет (CRM их не удаляет, фоновая
сверка тоже); удаляют только вручную в Console.

## 8. Фоновая сверка (таймер systemd на хосте)

Раньше статусы и расход запусков обновлялись, только когда кто-то открывал
страницу раздела (ленивая сверка), а запуски расписания читались одной страницей
из 20. Фоновая сверка делает это сама раз в ~5 минут: это
`/app/ai-agents-maintenance.mjs` в образе приложения (собирается из
`scripts/ai-agents-maintenance.mjs`, как задача телефонии). За один проход:

1. без `EVO_ANTHROPIC_API_KEY` ничего не делает (строка `status:"disabled"`);
2. один проход за раз: замок `/tmp/evo-ai-agents-maintenance.lock` в контейнере
   (старше 6 минут считается брошенным);
3. для расписания каждого агента читает его запуски в Claude (`deployment_runs`,
   по 100 на страницу, до 5 страниц, за последние 8 суток): запуск с сессией
   становится строкой «Запусков», запуск без сессии (Claude его не создал) —
   строкой `failed`, но только свежий (не старше часа): строка запуска получает
   начало «сейчас», и давний сбой стал бы «последним запуском» агента; повторы
   ничего не дублируют;
4. расписание, которому положено работать (агент включён, cron задан), но которое
   стоит на паузе в Claude, записывает в «Запуски» одной строкой `failed` с кодом
   `deployment_paused`. **Паузу не снимает** — её снимает только «Синхронизировать
   с Claude»;
5. закрывает открытые запуски по состоянию сессии (до 100 за проход): итог и расход
   попадают в CRM без открытия страницы.

Проход ограничен по времени (150 с; жёсткий предел процесса 200 с, у unit 240 с).
В журнал уходит одна JSON-строка с счётчиками (`agents`, `deployments`,
`deployment_runs_seen`, `deployments_paused`, `open_closed`, …) и статусом
`ok`/`error`/`disabled`/`skipped`; код выхода 1 — сбой базы или Claude (в строке
есть `request_id`). Видно так: `journalctl -u evo-ai-agents-maintenance -n 20`.

Установка на VPS — отдельный серверный шаг по разрешению владельца (не часть
выпуска). Файлы unit и timer:

```ini
# /etc/systemd/system/evo-ai-agents-maintenance.service
[Unit]
```

## 10. Согласие студента на ИИ-помощников (миграция 320, решение владельца 25.10.2026)

Правило Apple 5.1.2(i): личные данные уходят стороннему ИИ только с явного разрешения в приложении.
Решение студента (`granted` | `declined`, версия текста политики, источник `portal_web` | `ios`) хранится
одной строкой на студента в `platform_private.student_ai_consents`; каждое изменение — событие журнала
платформы `ai.consent.grant` / `ai.consent.decline` (в CRM: «Журнал действий»). Кабинет и iPhone зовут
`platform.portal_ai_consent_get_v1()` и `platform.portal_ai_consent_set_v1(...)`, сотрудник видит чип «ИИ: ...»
в шапке Student 360.

- **Запрет в базе**, не в промпте: `platform_private.ai_agent_student_ai_allowed(организация, дело)`. Закрыто,
  если студент отказал; закрыто, если у него есть кабинет (действующее участие студента) и он не решил или решил
  на прежней версии текста; открыто, если разрешил на действующей версии или кабинета нет (основание — договор
  и политика). Закрыто = инструменты `get_document_file`, `get_case_chat`, `get_conversation` (чат WhatsApp,
  связанный со студентом по делу, клиенту или лиду) отвечают агенту `ai_consent_missing` (в журнале действий —
  «нет согласия студента», статус `denied`), `list_conversations` не показывает текст последнего сообщения такого
  чата, ссылка на файл, выданная раньше, перестаёт скачиваться. Имя, этап, сроки, задачи, документы со
  статусами и заметки сотрудников агентам остаются доступны: запрет касается только переписки и файлов.
- **Новая версия текста политики** — новая миграция, которая заменяет `student_ai_consent_policy_version()`, и
  константа `AI_CONSENT_POLICY_VERSION` в `src/lib/ai-agents/consent.ts` (их равенство проверяет
  `tests/ai-agents-db-contract.test.mjs`). У всех студентов карточка согласия появится снова, а запрет будет считать
  прежнее решение «не решено» (отказ остаётся отказом).
- **Если агент «ничего не читает» у студента:** в Student 360 чип «ИИ: не спрашивали» у студента с кабинетом —
  он ещё не ответил на карточку; «ИИ: не разрешено» — отказал. Обойти запрет нельзя и не нужно: работа с делом
  не меняется, её делает сотрудник.
- **Не закрыто этой миграцией:** Gemini-помощник в чате (`evo-lead-agent`, читает чаты WhatsApp продаж) и
  отправка сообщений агентом (`send_message` не читает переписку и запретом не закрыт).
- **Удаление аккаунта (280):** строка согласия — данные аккаунта, автоматическое удаление стирает её вместе с
  событиями журнала о ней; ручное — удаляет внешний ключ на `auth.users`.
