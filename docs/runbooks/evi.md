# Эви — ИИ-профориентатор кабинета студента: включение и эксплуатация

Эви живёт во вкладке «Профессии» → «Подбор с Эви» кабинета студента (`app.evoadmissions.com/portal/professions?view=evi`).
Ученик отвечает на несколько вопросов, Эви сверяет его со всеми профессиями каталога и предлагает три. Модель —
**Claude Sonnet 5.5** (`claude-sonnet-5-5`), решение владельца 17.11.2026.

Код: серверное действие `src/lib/portal/evi-actions.ts`, вызов Claude `src/lib/server/evi/messages.ts`, системный промт
`src/lib/server/evi/prompt.ts`. Решения владельца — `docs/design/v3/product.md`, записи 16.11 и 17.11 «Подбор с Эви».

Границы:

- Ключ Claude у Эви **свой**: `EVO_EVI_ANTHROPIC_API_KEY`, отдельный от ключа ИИ-агентов CRM (`EVO_ANTHROPIC_API_KEY`).
  Так у Эви свой лимит трат, и ученики не расходуют бюджет агентов сотрудников (решение владельца 16.11.2026).
- Секреты — только в `/opt/evo-crm/.env.production` и в архиве SOPS (`EVO_Знания/Секреты и доступы ЭВО`). В Git, чат,
  задачи и этот файл ключ не вносить.
- Потолок расходов задаётся в **Claude Console**. Приложение ограничивает только частоту: не больше 40 ответов на ученика
  за 10 минут и 150 за сутки, 1200 на весь кабинет за час. Это защита от зацикленной кнопки, а не учёт денег.
- В Claude уходят только переписка, которую ученик видит на экране, и результат его собственного теста интересов словами,
  без баллов. Профиль, дело, документы и контакты не уходят. EVO разговор нигде не сохраняет.
- Согласие на ИИ ученик даёт галочкой при регистрации. Ученику, который отозвал его в «Профиле», вкладка Эви не
  показывается.

## 1. Что нужно от владельца

Без этих шагов Эви в кабинете честно пишет «Эви сейчас недоступен» и даёт кнопку «Открыть каталог», а наверху
«Профессий» остаётся прежняя карточка теста интересов. Ничего не ломается.

1. **Слить PR с Эви в `main`.** Код без ключа безопасен: он просто «недоступен».
2. **Claude Console** (`console.anthropic.com`, аккаунт EVO):
   1. Создать отдельное рабочее пространство, например «EVO Эви». Так расход Эви виден и ограничивается отдельно от
      агентов CRM.
   2. В настройках этого пространства задать **месячный лимит расходов** (раздел лимитов пространства; названия пунктов
      в Console могут отличаться). Сумму решает владелец; для первого месяца хватит небольшой, например $50.
      Оценка цены — примерно $0,25–0,40 за разговор: каталог в промте кешируется, основная часть — размышления модели
      перед итогом. Это расчёт, а не замер: после первых разговоров сверить с Usage и поправить лимит.
   3. Включить уведомления о расходе на почту владельца, если нужны.
   4. Создать API-ключ именно в этом пространстве (раздел API Keys), назвать, например, `evo-evi-production`. Ключ
      показывается один раз: сразу положить его в архив SOPS. В чат и в Git не вставлять.
3. **Сервер.** Положить ключ в `/opt/evo-crm/.env.production` (раздел 2).
4. **Выпуск приложения** через CI (раздел 3). Сервер читает `.env.production` только при выпуске: без выпуска ключ не
   подхватится.
5. **Проверка** в кабинете (раздел 4).

Шаги 3–4 можно сделать одним выпуском вместе с выпуском слитого PR: сначала ключ в файл, потом один выпуск.

## 2. Ключ на сервере

На сервере, под root:

```bash
cd /opt/evo-crm
cp -p .env.production ".env.production.$(date -u +%Y%m%dT%H%M%SZ)"   # резервная копия, 0600 root:root
nano .env.production                                                # или привычный редактор
```

Добавить одну строку (если строка `EVO_EVI_ANTHROPIC_API_KEY=` уже есть — вписать значение в неё):

```text
EVO_EVI_ANTHROPIC_API_KEY=<ключ из Claude Console>
```

- Формат — `NAME=value`: без кавычек, без `export`, без пробелов.
- Ключ — 20–300 печатных символов и **не совпадает** ни с одним другим значением файла, в том числе с
  `EVO_ANTHROPIC_API_KEY` и старым `ANTHROPIC_API_KEY`. Иначе выпуск откажет ещё до замены контейнера с кодом
  `optional_feature_configuration_invalid`, и рабочий сайт останется прежним.
- Права файла не менять: `root:root`, `0600`.
- После правки обновить архив SOPS тем же порядком, что для остальных секретов.

## 3. Выпуск

Только через CI, по контракту `deploy/fast-app-release.md`. Вручную на сервере не выкатывать. Порядок тот же, что для
любого выпуска:

```bash
gh variable set EVO_PRODUCTION_RELEASE_ARMED --body true -R izzhackt/evo_AI_CRM
gh workflow run evo-platform-ci.yml -f proof_revision=<точный SHA main> --ref main -R izzhackt/evo_AI_CRM
# при 403 на допуске — gh run rerun <тот же прогон CI>, новый CI не запускать
# «EVO fast app release» стартует сам после CI (workflow_run); дождаться success
gh variable set EVO_PRODUCTION_RELEASE_ARMED --body false -R izzhackt/evo_AI_CRM   # ВСЕГДА, и при неудаче
```

Выпуск снимает копию `.env.production` и проверяет её контрактом `scripts/release/evo-app-env-contract.mjs`, в том
числе формат ключа Эви. Миграций базы у Эви нет.

## 4. Проверка после выпуска

1. Войти в кабинет студентом с одобренным кабинетом, который не отзывал согласие на ИИ (тестовый ученик EVO).
2. «Профессии»: наверху карточка **«Не знаешь, кем стать? · Поговорить с Эви»** с роботом. Если вместо неё карточка
   «Тест интересов» — ключ не подхватился (раздел 5).
3. «Поговорить с Эви» → «Начнём!». Через несколько секунд Эви задаёт первый вопрос с вариантами, сверху появляется
   «Вопрос 1 из 10». Пока Эви отвечает, в шапке написано «печатает».
4. Ответить на вопросы до итога: три карточки профессий с фото, у каждой — почему она подходит.
5. Claude Console → Usage: в пространстве «EVO Эви» видны запросы к `claude-sonnet-5-5`. Через день сверить расход с
   оценкой из раздела 1.

## 5. Что видит ученик и что делать

| Что видит ученик | Причина | Что делать |
|---|---|---|
| «Эви сейчас недоступен» сразу, наверху карточка теста | в выпущенном приложении нет ключа | проверить строку в `.env.production` и сделать выпуск (разделы 2–3) |
| «Эви сейчас недоступен» после сообщения | ключ отозван, исчерпан месячный лимит, нет оплаты или модель недоступна аккаунту (ответ Claude 401–404) | Claude Console: ключ активен, лимит не исчерпан, оплата в порядке |
| «Не получилось ответить. Попробуйте ещё раз.» и «Повторить» | сбой сети, перегрузка Claude (5xx) или слишком долгий ответ (ожидание до 4 минут) | обычно проходит повтором; часто — смотреть статус Anthropic |
| «Слишком много сообщений подряд…» | сработал ограничитель частоты приложения (40 ответов на ученика за 10 минут и 150 за сутки, 1200 на кабинет за час) или Claude ответил 429 | подождать. Если часто упираются в ограничитель приложения — менять числа в `src/lib/server/evi/limiter.ts` через PR; если 429 от Claude — смотреть лимиты тарифа аккаунта в Console |
| «Разговор сбился. Начните новый чат.» | модель отказалась отвечать на эту переписку или история разговора повреждена | ученик нажимает «Новый чат» |

Ни ключ, ни тексты учеников в журнал приложения не пишутся.

## 6. Как выключить

1. **Быстро:** в Claude Console архивировать или удалить ключ `evo-evi-production`. Со следующего сообщения Эви у всех
   учеников пишет «Эви сейчас недоступен». Карточка «Поговорить с Эви» наверху при этом остаётся до выпуска из п. 2.
2. **Полностью:** очистить значение `EVO_EVI_ANTHROPIC_API_KEY=` в `.env.production` и сделать выпуск. Чат
   «недоступен» с первого экрана, наверху «Профессий» возвращается карточка теста интересов.

## 7. Что здесь не проверено

- Живой Claude ни разу не вызывался: в разработке ключа не было. Формат запроса сверен с документацией Claude API
  (17.11.2026) и покрыт тестами `tests/portal-evi-ai.test.mjs`. Первый настоящий разговор — после шага 4 раздела 1.
- Цена разговора — расчёт, не замер.
- «Новый чат» во время ответа не отменяет уже отправленный запрос: первое сообщение нового чата ждёт его окончания.
