# Защищённая выгрузка WhatsApp для базы знаний ЭВО

Этот процесс создаёт сырой архив-источник. Он не публикует переписку в
Obsidian и не превращает сообщения в утверждённые знания автоматически.

## Граница безопасности

- Скрипт выполняет запросы WAHA внутри приватного контейнера lead-agent.
- Ключ WAHA не передаётся на локальный компьютер и не записывается в файлы.
- Выгрузка работает только на чтение: список чатов и история сообщений.
- Каталог назначения получает права `0700`, файлы — `0600`.
- По умолчанию каталог находится вне Git-репозитория и вне Obsidian vault.
  По прямому разрешению владельца допускается закрытый раздел
  `90_Закрытый архив` с правами каталогов `0700`, файлов `0600` и запретом
  клиентскому ИИ. Это не шифрование: плагины и синхронизация Obsidian могут
  видеть файлы.
- Имена файлов чатов — SHA-256 от внутреннего ID; телефон не попадает в имя.
- Реестр содержит чувствительные данные и защищается так же, как сообщения.

## Полная выгрузка

```bash
python3 scripts/export-waha-knowledge.py \
  --destination "/абсолютный/путь/к/защищённому/архиву" \
  --ssh-host hermes-vps \
  --container evo-crm-lead-agent-1 \
  --session crm_primary
```

Результат:

- `Чаты/<sha256>.jsonl` — одна атомарная копия каждого чата;
- `контрольная точка.json` — timestamp последнего сообщения, количество и hash;
- `реестр.json` — соответствие hash исходным метаданным чата;
- `отчёт.json` — обезличенные общие счётчики архива и последнего запуска;
- `Журналы/запуск-*.json` — неизменяемая история обезличенных отчётов;
- `Журналы/ошибки последнего запуска.json` — ошибки, если чат не выгрузился.

## Повторный запуск

Повторите ту же команду. Неизменённые чаты пропускаются. Если последнее
сообщение изменилось, скрипт заново получает доступную историю этого чата,
удаляет дубликаты по ID и атомарно заменяет его файл.

Успешная проверка идемпотентности: второй запуск показывает ноль выгруженных
чатов, все чаты отмечены как неизменённые, SHA-256 файлов не меняются.

## Ограничение первого этапа

Запрос использует `downloadMedia=false`: JSON хранит признаки и метаданные
медиа, но не байты фотографий, аудио и документов. Загрузку вложений следует
запускать отдельным этапом после проверки полноты текстового архива, чтобы
контролировать объём, ошибки и хранение персональных документов.

## Передача в Obsidian

Сырой архив никогда не копируется в каноническую базу. Обработка создаёт только
русскоязычные карточки-кандидаты в `10_На проверке`. Факт переходит в основную
базу и в клиентский AI-контур только при выполнении действующих правил:
официальный актуальный источник плюс подтверждение владельца или руководителя
ЭВО.

Если владелец явно разрешил хранить оригиналы в Obsidian, они помещаются только
в `90_Закрытый архив`, никогда не в `30_Утверждено для ИИ`. Для этого служат
`build-whatsapp-obsidian.py`, `download-waha-media.py`,
`extract-whatsapp-media-text.py` и `transcribe-whatsapp-media.py`.
Автоматически распознанный текст всегда остаётся черновиком до проверки.
