# Инвентаризация источников базы знаний

`inventory.py` выполняет read-only проход по четырём корням. Файлы читаются
потоком только для SHA-256, текст архивов не извлекается. Исходники не меняются.
Приватный JSONL содержит каждое происхождение, размер, хеш, границу доступа
и предварительную папку. Это предложение распределения, не завершённая сортировка.

Запускать с `--source <локальная-база>` и `--output <приватный-путь-вне-Git>`.
Обе опции обязательны. Вывод и журнал получают режим 0600, папка — 0700.
В stdout попадают только суммы. Ключи остаются вне импорта/выгрузки с явным
статусом `retained_key_outside_export`; зашифрованные данные инвентаризируются.

После прерывания повторить ту же команду. Журнал сбрасывается на диск после
каждого файла; хеш повторно используется только при совпадении dev/inode/size/
mtime/ctime. При изменении файла во время чтения проход сообщает ошибку.
Исчезнувшие источники не остаются в итоговом инвентаре за счёт старого журнала.
Символические ссылки не обходятся и дают явную неполноту. Недоступные корни,
каталоги и файлы также делают результат неполным; ошибка не скрывается лимитом.

`--max-files N` останавливает проход после реальной контрольной партии и
возвращает exit 2. Полный корректный инвентарь — exit 0; незавершённый/неполный —
exit 2; ошибка запуска или повреждённого состояния — exit 1. Прерванный JSONL
сохраняется как журнал; основной инвентарь заменяется атомарно только после обхода.
Перед импортом байты проверяются снова: стат-подпись — оптимизация повторного
инвентаря, не доказательство неизменности удалённого объекта.

Инструмент не импортирует данные, не публикует AI bundles, не извлекает секреты,
не выбирает победителя конфликта и не подтверждает принадлежность клиента.

## План размещения и защищённый пакет

`prepare_import.py --inventory <JSONL> --output <приватный-JSON>` сохраняет каждую
исходную запись. Разрешённые Markdown-страницы классифицируются по существующей
группировке, заголовкам и статусу; сырой архив, Trash/Spam и закрытые производные
материалы по содержимому не анализируются. Исходная контрольная сумма проверяется
перед чтением. Новых утверждений фактов или публикации AI bundles нет.

`prepare_protected.py --plan <план> --output-dir <приватная-папка>` использует
существующий ключ `EVO Secrets Age Key` из macOS Keychain. Исходники сейфа
запечатываются SOPS как точные байты с зашифрованными метаданными; существующие
доступы представлены отдельными структурированными записями. Каждый результат
расшифровывается в памяти и сравнивается с оригиналом. Повторный запуск проверяет
и переиспользует готовый ciphertext. Секреты и ключ не печатаются, plaintext-файлы
не создаются. Подписывающие ключи резервных копий остаются вне пакета.

В CRM: «База знаний → Перенос локальной базы». Сначала выбрать план и исходную
папку, перенести контрольную партию, проверить реальное чтение/редактирование,
выгрузить и сравнить байты. Затем продолжить весь план. Защищённый пакет выбирается
отдельно, ключ через браузер не передаётся. «Сверить все источники» скачивает
приватный отчёт со статусом каждого оригинала, hash/size, повторным использованием
blob и исключёнными ключами. Публично публикуются только агрегаты.

## Runtime и координация

Forward migrations 201–204 в `supabase/migrations/` зарезервированы за Astra
после передачи выпуска владельцем. Порядок: library, sealed records,
canonical exports, export jobs. Первый файл создаёт отдельный
private Storage bucket с частями по 8 MiB и закрывает прямой доступ Auth/anon.
Применять ровно один раз через согласованный migration ledger.

SOPS 3.13.2 скачивается в Docker по закреплённому SHA-256 для amd64/arm64.
Источник и процедура проверки: [официальный релиз](https://github.com/getsops/sops/releases/tag/v3.13.2).
Внешний `/etc/evo-crm/knowledge/age.key` должен принадлежать uid 1001 и иметь режим
0600 либо 0400; каталог — 0700. Его монтируют read-only. В `.env.production`
задаётся только публичный `EVO_KNOWLEDGE_AGE_RECIPIENTS`. Значения ключа не входят
в образ, SQL, Git, экспорт или журнал. Provisioning выполняет согласованный
владелец выпуска; отсутствие/ошибка ключа дают явную недоступность сейфа.

`knowledge-maintenance.mjs` включён в тот же immutable image. Systemd unit/timer
в `deploy/knowledge/` запускает его внутри app-контейнера каждые 15 минут. Он
удаляет истёкшие временные архивы и подхватывает queued/stale задания. Ручная
команда: `docker exec evo-crm-app-1 node /app/knowledge-maintenance.mjs`.
Установка timer — часть согласованного выпуска, а не фоновое действие скриптов.

ZIP доступен только создавшему его действующему Admin в течение 24 часов.
Повторное скачивание использует готовые части. При сбое сборки фиксированный
snapshot сохраняется; повторная сборка сверяет и переиспользует записанные части.
Непроверенный/недоступный исходник останавливает сборку с ошибкой: готовый полный
архив в этом случае не объявляется. Ключи и Student-private результаты обучения
в канонический экспорт не входят.
