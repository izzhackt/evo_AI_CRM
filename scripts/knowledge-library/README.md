# Инвентаризация источников базы знаний

`inventory.py` выполняет read-only проход по четырём корням. Файлы читаются
потоком только для SHA-256, текст архивов не извлекается. Исходники не меняются.
Приватный JSONL содержит каждое происхождение, размер, хеш, границу доступа
и предварительную папку. Это предложение распределения, не завершённая сортировка.

Запускать с `--source <локальная-база>` и `--output <приватный-путь-вне-Git>`.
Обе опции обязательны. Вывод и журнал получают режим 0600, папка — 0700.
В stdout попадают только суммы. Ключи остаются вне импорта/выгрузки с явным
статусом `retained_key_outside_export`; зашифрованные данные инвентаризируются.

После прерывания повторить ту же команду. Журнал сбрасывается на диск после
каждого файла; хеш повторно используется только при совпадении dev/inode/size/
mtime/ctime. При изменении файла во время чтения проход сообщает ошибку.
Исчезнувшие источники не остаются в итоговом инвентаре за счёт старого журнала.
Символические ссылки не обходятся и дают явную неполноту. Недоступные корни,
каталоги и файлы также делают результат неполным; ошибка не скрывается лимитом.

`--max-files N` останавливает проход после реальной контрольной партии и
возвращает exit 2. Полный корректный инвентарь — exit 0; незавершённый/неполный —
exit 2; ошибка запуска или повреждённого состояния — exit 1. Прерванный JSONL
сохраняется как журнал; основной инвентарь заменяется атомарно только после обхода.
Перед импортом байты проверяются снова: стат-подпись — оптимизация повторного
инвентаря, не доказательство неизменности удалённого объекта.

Инструмент не импортирует данные, не публикует AI bundles, не извлекает секреты,
не выбирает победителя конфликта и не подтверждает принадлежность клиента.
