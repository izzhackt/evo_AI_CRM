# Гейт качества V3

Тот самый прогон, который весь день ловил регрессии на экранах V3. Он дешёвый
и ловит настоящее, поэтому гоняется на каждую правку интерфейса, а не перед
релизом.

Раньше жил в `tmp/` и в репозиторий не попадал. Это была ошибка: правила,
которые нельзя запустить, перестают действовать в первый же день после
передачи.

## Что проверяет

На каждом экране V3, в трёх прогонах — десктоп 1280, телефон 393 и
**принудительная тёмная тема** (у этого мира тёмной темы нет, и прогон
доказывает, что светлые значения не уезжают):

- `axe-core` по WCAG 2.0/2.1/2.2 уровня A и AA — ноль нарушений;
- ровно один `h1` на странице;
- отсутствие горизонтальной прокрутки страницы;
- ни одной кликабельной мишени меньше 24×24 (SC 2.5.8);
- цвет земли — доказательство, что стили вообще применились.

## Как запустить

Нужна поднятая production-сборка и база с данными.

```
npm run build
node .next/standalone/server.js          # порт и окружение — см. ниже
node scripts/v3-gate/gate.mjs
```

Переменные, которые читает прогон:

- `EVO_AUDIT_APPPORT` — порт поднятого приложения;
- `EVO_DEV_GATE_ADMIN_IDENTIFIER` и `EVO_DEV_GATE_ADMIN_SECRET` — пара для
  входа через локальный шлюз;
- `DATABASE_URL` — база, из которой экраны читают.

**Важно про сборку.** Не пропускайте её вывод через `head` или `grep | head`:
закрытие потока убивает сборку сигналом на середине, и сервер поднимается на
битых артефактах. Пишите в файл: `npm run build > /tmp/b.log 2>&1`.

## Данные

`seed.sql` наполняет пустую базу набором, на котором прогон осмыслен: 18
человек, 19 лидов, 4 переданных дела, 24 визовые вехи, 20 задач, 6 входящих
сообщений, 82 события шины, 1 финансовый стоп. Даты заведения лидов намеренно
разнесены — иначе ряд «Динамика» на главной не на чем считать.

## Что делать, когда прогон краснеет

Чинить экран, а не прогон. Единственное исключение — если правило перестало
соответствовать продукту; тогда сначала меняется правило в `CLAUDE.md`, и
только потом код.
